- [x] 6. AVL-деревья. Основные операции. Теорема о высоте AVL-дерева (с доказательством). <mark style="background: #FF5582A6;">6/10</mark>
- insert/delete BST -> идём вверх -> update height -> balance
- +2 + left BF>=0 -> LL -> right rotate
- -2 + right BF<=0 -> RR -> left rotate
- +2 + left BF<0 -> LR -> left child, right root
- -2 + right BF>0 -> RL -> right child, left root
- N(h)=1+N(h-1)+N(h-2) ~ Fibonacci
- n >= c\*phi^h => h=O(log n)
      
- [x] 7. Красно-черные деревья. Основные операции. Теорема о высоте красно-черного дерева (с доказательством). <mark style="background: #FF5582A6;">8/10</mark>
    * BST + RED/BLACK
    * root BLACK
    * NIL BLACK
    * RED has BLACK children
    * одинаковый black height
    * insert:
		- insert RED
		- parent BLACK -> end
		- parent RED:
		  - uncle RED -> P,U BLACK; G RED; вверх
		  - uncle BLACK:
		    - zigzag -> rotate P
		    - line -> rotate G + recolor
	- delete:
		- RED -> delete
		- BLACK + RED child -> child BLACK
		- BLACK -> double black
		- sibling RED -> rotate parent
		- sibling BLACK + children BLACK -> sibling RED, BB вверх
		- near RED, far BLACK -> rotate sibling
		- far RED -> rotate parent + recolor -> end
	- height:
		- subtree with bh has >= 2^bh-1 nodes
		- bh <= log2(n+1)
		- no two RED подряд
		- h <= 2bh
		- h <= 2log2(n+1)
      
- [x] 8. Декартовы деревья. Основные операции. Операции split и merge. Оценка алгоритмической сложности выполнения операций. <mark style="background: #FFF3A3A6;">5/10</mark>
      * (key, priority)
      * key > key_1, key < key_2; p > p1,p2
      * `t->key < key` => `split(t->right, key, t->right, b)`, `a = t`
      * `t->key >= key` => `split(t->left, key, a, t->left)`, `b = t`
      
- [x] 9. Неявные декартовы деревья. Основные операции. <mark style="background: #FF5582A6;">7/10</mark>
      * key = index in array 
      * split(T, 3) for T = \[A,B,C,D,E\] => T1=\[A,B,C\] | T2=\[D,E\]
      * k <= leftSize => `split(t->left, k, a, t->left)`
      * k > leftSize => split(t->right, k - leftSize - 1, t->right, b)
      * merge(A, B) for A=\[A,B,C\],B=\[D,E\] => \[A,B,C,D,E\]
      * a->priority > b->priority => a->right = merge(a->right, b);
      * a->priority < b->priority => b->left = merge(a, b->left);

- [ ] 11. PATRICIA trie. Основные операции. Оценка алгоритмической сложности выполнения операций. <mark style="background: #FF5582A6;">7/10</mark>
	* бинарный trie, но храним **только значимые позиции битов**
	- вершина: `(key, bit, left, right)`
	- `bit` = номер бита ключа, который надо проверить
	- по `0` идём `left`, по `1` → `right`
	- при поиске:
	    - пока `next.bit > current.bit` → идём дальше
	    - `next.bit <= current.bit` → обратная ссылка / self-loop → **stop**
	    - получили candidate → обязательно `candidate.key == key`
	- обратные ссылки нужны, чтобы не хранить обычные листья
	- `header` — специальная корневая вершина, обычно `bit = 0`
	- вставка:
	    - найти candidate
	    - найти **первый различающийся бит** `d`
	    - вставить новую вершину в место, где `parent.bit < d`, а `child.bit >= d`
	    - одна ссылка новой вершины → старое поддерево
	    - вторая → **сама новая вершина**
	- удаление:
	    - нельзя всегда просто удалить вершину, т.к. она может проверять бит для других ключей
	    - если есть удобная self-link → переподключаем ссылки и удаляем
	    - иначе ключ другой вершины переносим в удаляемую, а физически удаляем ту вершину
	- поиск: `O(h + L)`, где `h` — число проверенных битов, `L` — длина полного сравнения
	- `h <= L` → поиск / вставка / удаление `O(L)`
- [ ] 12. 2-3-4 деревья. Основные операции. Связь с красно-черными деревьями. <mark style="background: #FFF3A3A6;">5/10</mark> 
	- вершина может хранить `1`, `2` или `3` ключа
	- соответственно имеет `2`, `3` или `4` ребёнка
	- все листья находятся на одной глубине
	- поиск — выбираем подходящий промежуток между ключами
	- вставка:
        - идём к листу
        - если встретили 4-вершину, делим её
        - средний ключ поднимается в родителя
	- удаление:
        - удаляем из листа
        - если вершина становится пустой → берём ключ у соседа или сливаем вершины
    - высота `O(log n)`
	
	Связь с КЧ-деревом:
	- 2-вершина ↔ `BLACK`
	- 3-вершина ↔ `BLACK + RED child`
	- 4-вершина ↔ `BLACK + 2 RED children`
	- split 4-вершины ↔ перекраска в КЧ-дереве
	- повороты в КЧ ↔ перераспределение ключей в 2-3-4 дереве
- [ ] 13. B-деревья. Основные операции. Оценка алгоритмической сложности выполнения операций. <mark style="background: #FFF3A3A6;">5/10</mark>
	- обобщение 2-3-4 дерева
	- вершина хранит много ключей и много детей
	- ключи внутри вершины отсортированы
	- все листья на одной глубине
	- для B-дерева минимальной степени `t`:
        - ключей: от `t-1` до `2t-1`
        - детей: от `t` до `2t`
	- поиск — ищем нужный диапазон внутри вершины и идём в ребёнка
	- вставка:
        - если вершина заполнена → split
        - средний ключ поднимается в родителя
	- удаление:
        - если мало ключей → borrow у соседа или merge
	- высота `O(log_t n)`
	- поиск / вставка / удаление: `O(log_t n)` переходов по вершинам
	- используются в БД и файловых системах, потому что большая степень уменьшает число обращений к диску
