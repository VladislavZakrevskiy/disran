## I. Сортировки за линейное время

1. [ ] Теорема об оценке времени работы сортировок, использующих сравнение элементов (с доказательством). <mark style="background: #FFF3A3A6;">5/10</mark>
    - сортировку сравнениями представляем как **дерево решений**
    - вершина = сравнение `a_i < a_j`
    - 2 исхода → бинарное дерево
    - для `n` различных элементов существует `n!` возможных порядков
    - каждому порядку нужен свой лист → `L >= n!`
    - у бинарного дерева высоты `h`: `L <= 2^h`
    - `n! <= 2^h`
    - `h >= log₂(n!)`
    - по Стирлингу `log(n!) = Θ(n log n)`
    - ⇒ **любая сортировка сравнениями в худшем случае `Ω(n log n)`**
    - counting/radix/bucket обходят теорему, т.к. используют **значения ключей**, а не только сравнения

---

2. [ ] Сортировка подсчётом. Доказательство линейности алгоритма. <mark style="background: #BBFABBA6;">3/10</mark>
    - ключи — целые числа из небольшого диапазона `[0..k]`
    - `count[x]` = сколько раз встретился `x`
    - проход по массиву → считаем частоты `O(n)`
    - проход по `count` → восстанавливаем ответ `O(k)`
    - итог: **`O(n+k)`**
    - если `k = O(n)` → **`O(n)`**
    - отрицательные числа → сдвиг на минимум: `index = x - min`
    - устойчивая версия:
        - делаем prefix sums по `count`
        - `count[x]` = позиция конца блока ключа `x`
        - исходный массив обходим **справа налево**
        - `result[count[x]-1] = x`, затем `count[x]--`
    - справа налево → одинаковые ключи сохраняют исходный порядок
    - память: `O(n+k)`

---

3. [ ] Поразрядная сортировка. Доказательство линейности алгоритма. <mark style="background: #BBFABBA6;">3/10</mark>
    - число разбиваем на `d` разрядов
    - каждый разряд имеет `k` возможных значений
    - **LSD:** сортируем от младшего разряда к старшему
    - каждый проход должен быть **устойчивым** (обычно counting sort)
    - после 1-го прохода правильно отсортирован 1 младший разряд
    - если уже отсортированы `i` младших разрядов:
        - разные новые цифры → порядок задаёт новый разряд
        - одинаковые → устойчивость сохраняет порядок по младшим
    - ⇒ после прохода отсортированы `i+1` разрядов
    - после `d` проходов отсортировано всё число
    - один проход: `O(n+k)`
    - всего: **`O(d(n+k))`**
    - если `d = const`, `k = O(n)` / `const` → **`O(n)`**
    - **MSD:** начинаем со старшего разряда → делим на блоки → рекурсивно сортируем каждый блок по следующему разряду
    - LSD проще: `d` раз применили устойчивый counting sort

---

4. [ ] Карманная сортировка. <mark style="background: #BBFABBA6;">3/10</mark>
    - для лекционного варианта: `n` чисел равномерно распределены в `[0,1)`
    - создаём `n` карманов
    - индекс для `x`: **`⌊n·x⌋`**
    - раскладываем элементы по карманам
    - каждый карман сортируем отдельно, например insertion sort
    - затем склеиваем карманы слева направо
    - любой элемент кармана `i` меньше любого элемента более позднего кармана → склейка корректна
    - при равномерном распределении ожидается `O(1)` элементов в кармане
    - распределение `O(n)` + сортировка карманов в среднем `O(n)` + склейка `O(n)`
    - ⇒ **ожидаемая `O(n)`**
    - точнее: `O(n + Σ n_i²)` при insertion sort внутри карманов
    - плохой случай: все элементы в одном кармане → **`O(n²)`**
    - поэтому линейность здесь **ожидаемая при равномерном распределении**, а не гарантия для любого входа
