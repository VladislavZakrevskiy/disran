# 23. Суффиксные массивы: построение через суффиксные деревья и поиск подстроки

## 1. Что такое суффиксный массив

Суффиксный массив строки `S` — это массив позиций начала суффиксов строки в лексикографическом порядке.

Обычно к строке добавляют специальный терминальный символ `$`, который меньше всех обычных символов и встречается ровно один раз. Он нужен, чтобы все суффиксы стали различными и ни один суффикс не был префиксом другого.

Пример:

```text
S = banana$
```

Все суффиксы:

| позиция | суффикс |
|---:|---|
| 0 | `banana$` |
| 1 | `anana$` |
| 2 | `nana$` |
| 3 | `ana$` |
| 4 | `na$` |
| 5 | `a$` |
| 6 | `$` |

Сортируем:

| порядок | позиция | суффикс |
|---:|---:|---|
| 0 | 6 | `$` |
| 1 | 5 | `a$` |
| 2 | 3 | `ana$` |
| 3 | 1 | `anana$` |
| 4 | 0 | `banana$` |
| 5 | 4 | `na$` |
| 6 | 2 | `nana$` |

Значит:

```text
SA = [6, 5, 3, 1, 0, 4, 2]
```

---

## 2. Зачем нужен суффиксный массив

Суффиксный массив — более компактная альтернатива суффиксному дереву. Он не хранит само дерево, рёбра, вершины и переходы, а хранит только порядок всех суффиксов.

Основная информация в нём такая:

```text
SA[i] = начало i-го суффикса в отсортированном порядке
```

Память:

```text
O(n)
```

На практике суффиксный массив часто проще и компактнее суффиксного дерева, но при этом позволяет решать похожие задачи:

- искать подстроку в тексте;
- находить количество вхождений подстроки;
- искать повторяющиеся подстроки;
- считать количество различных подстрок;
- искать наибольшую общую подстроку двух строк.

Сам по себе `SA` даёт порядок суффиксов. Если вместе с ним хранить ещё и `LCP`-массив, то появляется информация о том, насколько сильно соседние суффиксы совпадают в начале. Именно связка `SA + LCP` обычно используется в задачах про статистику подстрок.

## 3. Построение суффиксного массива через суффиксное дерево

Если уже есть суффиксное дерево строки `S$`, то получить суффиксный массив очень просто.

Нужно обойти дерево DFS в лексикографическом порядке рёбер, то есть из каждой вершины сначала идти по ребру с наименьшим первым символом, потом по следующему и так далее.

Каждый раз, когда встречаем лист, записываем номер суффикса.

Почему работает?

В суффиксном дереве каждый путь от корня до листа задаёт один суффикс строки. Лист хранит позицию, с которой этот суффикс начинается в исходной строке.

Лексикографический порядок строк определяется первым символом, в котором строки отличаются. Если из каждой вершины обходить исходящие рёбра в порядке символов, то DFS сначала полностью обойдёт все суффиксы, начинающиеся с меньшего префикса, и только потом перейдёт к большему префиксу.

Значит, листья будут встречаться ровно в лексикографическом порядке соответствующих суффиксов. Порядок номеров листьев и есть суффиксный массив.

---

## 4. Пример через дерево

Для:

```text
S = aba$
```

Дерево:

```text
root
 ├─ $        leaf 3
 ├─ a
 │   ├─ $    leaf 2
 │   └─ ba$  leaf 0
 └─ ba$      leaf 1
```

Если порядок символов:

```text
$ < a < b
```

DFS даёт листья:

```text
3, 2, 0, 1
```

Суффиксы:

```text
3: $
2: a$
0: aba$
1: ba$
```

Они действительно отсортированы.

```text
SA = [3, 2, 0, 1]
```

### 4.1. Как получить этот массив руками

Берём дерево и в каждой вершине идём по рёбрам в порядке `$ < a < b`.

| шаг | где находимся | что делаем | что записываем |
|---:|---|---|---|
| 1 | `root` | идём по ребру `$` | лист `3` |
| 2 | `root` | идём по ребру `a` | пока ничего |
| 3 | вершина `a` | сначала идём по ребру `$` | лист `2` |
| 4 | вершина `a` | потом идём по ребру `ba$` | лист `0` |
| 5 | `root` | последним идём по ребру `ba$` | лист `1` |

Получили листья в порядке:

```text
3, 2, 0, 1
```

Значит:

```text
SA = [3, 2, 0, 1]
```

Смысл ручного обхода: мы не сортируем суффиксы отдельно, а просто читаем листья дерева слева направо, если дети каждой вершины уже упорядочены по первому символу ребра.

## 5. Поиск подстроки через суффиксный массив

Идея:

В суффиксном массиве все суффиксы отсортированы.

Все суффиксы, которые начинаются с образца `P`, образуют непрерывный отрезок.

Значит, можно найти этот отрезок бинарным поиском.

Почему отрезок непрерывный?

Если суффикс начинается с `P`, то он лексикографически лежит среди строк с тем же начальным префиксом. Между двумя строками, начинающимися с `P`, не может оказаться строка, которая начинается с другого префикса: такая строка либо меньше всего блока с префиксом `P`, либо больше всего блока.

Поэтому задача поиска `P` сводится не к просмотру всех суффиксов, а к поиску границ блока:

```text
SA[left], SA[left + 1], ..., SA[right - 1]
```

Все эти суффиксы начинаются с `P`, а вне этого отрезка таких суффиксов нет.

## 6. Пример поиска `ana` в `banana$`

```text
SA = [6, 5, 3, 1, 0, 4, 2]
```

Суффиксы в порядке:

```text
0: $          pos 6
1: a$         pos 5
2: ana$       pos 3
3: anana$     pos 1
4: banana$    pos 0
5: na$        pos 4
6: nana$      pos 2
```

Ищем:

```text
P = ana
```

Суффиксы, начинающиеся с `ana`:

```text
ana$      pos 3
anana$    pos 1
```

Они стоят подряд в `SA` на позициях `2..3`.

Ответ:

```text
positions = [3, 1]
```

Если нужны позиции в порядке возрастания по тексту, сортируем ответ:

```text
[1, 3]
```

## 7. Бинарный поиск границ

Нужно найти:

```text
left  = первый суффикс >= P
right = первый суффикс > всех суффиксов с префиксом P
```

Тут важно не путать сравнение полной строки и сравнение с образцом.

Для поиска подстроки нас интересует только первые `|P|` символов суффикса. Поэтому функция сравнения возвращает:

```text
-1, если S[pos..] лексикографически меньше P
 0, если P является префиксом S[pos..]
 1, если S[pos..] лексикографически больше P
```

Значение `0` здесь не означает, что суффикс полностью равен `P`. Оно означает, что найдено вхождение `P` в позиции `pos`.

Тогда:

1. `lower_bound` по сравнению суффикса с `P`.
2. Второй бинарный поиск ищет первый суффикс, для которого сравнение строго больше `0`.

После этого:

```text
[left, right) = все суффиксы, начинающиеся с P
right - left  = количество вхождений P
```

Позиции вхождений — это значения `SA[i]` для всех `i` от `left` до `right - 1`.

### 7.1. Ручной бинарный поиск границ

Возьмём тот же пример:

```text
S  = banana$
P  = ana
SA = [6, 5, 3, 1, 0, 4, 2]
```

Суффиксы в `SA`:

```text
0: $          pos 6
1: a$         pos 5
2: ana$       pos 3
3: anana$     pos 1
4: banana$    pos 0
5: na$        pos 4
6: nana$      pos 2
```

Ищем левую границу `left`: первый суффикс, который не меньше `P`.

| шаг | отрезок `[l, r)` | `mid` | суффикс | `cmp` с `ana` | действие |
|---:|---|---:|---|---:|---|
| 1 | `[0, 7)` | 3 | `anana$` | 0 | `r = mid`, потому что суффикс подходит |
| 2 | `[0, 3)` | 1 | `a$` | -1 | `l = mid + 1`, потому что `a$ < ana` |
| 3 | `[2, 3)` | 2 | `ana$` | 0 | `r = mid`, потому что суффикс подходит |

Получили:

```text
left = 2
```

Теперь ищем правую границу `right`: первый суффикс, который строго больше всех суффиксов с префиксом `ana`.

| шаг | отрезок `[l, r)` | `mid` | суффикс | `cmp` с `ana` | действие |
|---:|---|---:|---|---:|---|
| 1 | `[0, 7)` | 3 | `anana$` | 0 | `l = mid + 1`, потому что это ещё вхождение |
| 2 | `[4, 7)` | 5 | `na$` | 1 | `r = mid`, потому что `na$ > ana` |
| 3 | `[4, 5)` | 4 | `banana$` | 1 | `r = mid`, потому что `banana$ > ana` |

Получили:

```text
right = 4
```

Значит, все вхождения лежат в полуинтервале:

```text
[left, right) = [2, 4)
```

Берём `SA[2]` и `SA[3]`:

```text
SA[2] = 3
SA[3] = 1
```

Ответ:

```text
positions = [3, 1]
```

Количество вхождений:

```text
right - left = 4 - 2 = 2
```

## 8. Код поиска через суффиксный массив

```cpp
int cmp_suffix_pattern(const string& s, int pos, const string& p) {
    int n = (int)s.size();
    int m = (int)p.size();

    for (int i = 0; i < m; i++) {
        if (pos + i >= n) return -1; // суффикс короче pattern
        if (s[pos + i] < p[i]) return -1;
        if (s[pos + i] > p[i]) return 1;
    }

    return 0; // pattern является префиксом суффикса
}

vector<int> search_suffix_array(const string& s, const vector<int>& sa, const string& p) {
    int n = (int)sa.size();

    int l = 0, r = n;
    while (l < r) {
        int mid = (l + r) / 2;
        int cmp = cmp_suffix_pattern(s, sa[mid], p);
        if (cmp >= 0) r = mid;
        else l = mid + 1;
    }
    int left = l;

    l = 0; r = n;
    while (l < r) {
        int mid = (l + r) / 2;
        int cmp = cmp_suffix_pattern(s, sa[mid], p);
        if (cmp > 0) r = mid;
        else l = mid + 1;
    }
    int right = l;

    vector<int> ans;
    for (int i = left; i < right; i++) {
        ans.push_back(sa[i]);
    }
    return ans;
}
```

## 9. Сложность поиска

Один сравнительный шаг бинарного поиска может сравнить до `m` символов.

Бинарных шагов:

```text
O(log n)
```

Значит, простой поиск:

```text
O(m log n + occ)
```

где `occ` — количество найденных вхождений, потому что их ещё нужно выписать в ответ.

Почему появляется множитель `m`?

На каждом шаге бинарного поиска мы сравниваем `P` с каким-то суффиксом. В худшем случае первые `m - 1` символов совпадут, и только на последнем символе станет понятно, куда двигаться дальше. Таких сравнений `O(log n)`, поэтому получается `O(m log n)`.

С дополнительным `LCP`-массивом и более аккуратным бинарным поиском можно не пересравнивать уже известные общие префиксы. Тогда границы блока можно искать быстрее:

```text
O(m + log n + occ)
```

Но это уже не простой бинарный поиск, а поиск с использованием информации о LCP между границами и серединой. Для базового зачётного вопроса обычно достаточно знать простой вариант:

```text
O(m log n)
```

для поиска границ без LCP-ускорения.

## 10. LCP-массив

`LCP[i]` — длина наибольшего общего префикса соседних суффиксов в суффиксном массиве:

```text
LCP[i] = lcp(SA[i], SA[i-1])
```

Обычно считают, что `LCP[0] = 0`, потому что перед первым суффиксом нет предыдущего.

Для `banana$`:

```text
SA = [6, 5, 3, 1, 0, 4, 2]
```

Соседние суффиксы:

```text
$       и a$       → 0
a$      и ana$     → 1
ana$    и anana$   → 3
anana$  и banana$  → 0
banana$ и na$      → 0
na$     и nana$    → 2
```

Значит:

```text
LCP = [0, 0, 1, 3, 0, 0, 2]
```

### 10.1. Что показывает LCP

`LCP[i]` показывает, сколько начальных символов совпадает у суффиксов `SA[i - 1]` и `SA[i]`.

Например:

```text
SA[2] = 3 → ana$
SA[3] = 1 → anana$
LCP[3] = 3
```

Общий префикс этих суффиксов — `ana`, его длина равна `3`.

### 10.2. LCP для любых двух суффиксов

LCP-массив хранит значения только для соседних суффиксов, но через него можно находить общий префикс любых двух суффиксов.

Если суффиксы стоят в `SA` на позициях `i` и `j`, где `i < j`, то:

```text
lcp(SA[i], SA[j]) = min(LCP[i + 1], LCP[i + 2], ..., LCP[j])
```

Почему берётся минимум?

Суффиксы между позициями `i` и `j` идут в лексикографическом порядке. Пока все они имеют общий префикс длины `k`, соседние пары тоже имеют общий префикс хотя бы `k`. Как только у какой-то соседней пары LCP меньше, общий префикс всего отрезка тоже не может быть больше.

На практике для быстрых запросов минимума по отрезку строят RMQ-структуру поверх `LCP`.

### 10.3. Как построить LCP

Если суффиксный массив уже построен, `LCP` можно построить за `O(n)` алгоритмом Касаи.

Идея:

1. Строим обратный массив `rank`, где `rank[pos]` — позиция суффикса `S[pos..]` в суффиксном массиве.
2. Идём по позициям `pos` в исходной строке.
3. Для суффикса `S[pos..]` находим предыдущий суффикс в `SA`.
4. Считаем их общий префикс, но используем уже найденную длину `k`.

Главный трюк:

```text
если lcp(S[pos..], previous_suffix) = k,
то для следующей позиции общий префикс не может уменьшиться больше чем на 1
```

Поэтому после обработки позиции можно сделать:

```text
k = max(k - 1, 0)
```

Каждый символ за всё время работы добавляется в сравнение и выкидывается из него ограниченное число раз, поэтому суммарная сложность получается `O(n)`, а не `O(n^2)`.

### 10.4. Как LCP ускоряет поиск

В простом бинарном поиске мы на каждом шаге заново сравниваем `P` с очередным суффиксом с первого символа. Это может повторять одну и ту же работу.

С LCP можно хранить, сколько символов образца уже совпадает с левой и правой границей поиска. Когда берём середину, часть символов можно не сравнивать заново: известно, что они совпадают из-за LCP-информации между суффиксами на отрезке.

Идея такая:

```text
если уже известно, что первые k символов совпадают,
то сравнение можно начать с позиции k
```

За счёт этого суммарное число прямых сравнений символов образца можно ограничить `O(m)`, а не `O(m log n)`. Поэтому улучшенный поиск через `SA + LCP` даёт:

```text
O(m + log n + occ)
```

### 10.5. LCP для статистики подстрок

Каждый суффикс содержит много подстрок, которые начинаются в одной позиции. Если суффикс имеет длину `len`, то он даёт `len` префиксов:

```text
a
an
ana
anan
anana
```

Но часть этих префиксов уже могла встретиться в предыдущих суффиксах. Именно `LCP[i]` показывает, сколько начальных подстрок текущего суффикса уже было учтено раньше.

Поэтому количество новых различных подстрок, которые добавляет суффикс `SA[i]`, равно:

```text
длина_суффикса_без_$ - LCP[i]
```

Терминальный символ `$` нужен для построения структуры, но он не считается частью подстрок исходной строки.

Если исходная строка без терминального символа имеет длину `n`, то всего непустых подстрок с учётом повторений:

```text
n(n + 1) / 2
```

Количество различных подстрок:

```text
n(n + 1) / 2 - sum(LCP)
```

Для `banana`:

```text
n = 6
всего подстрок с повторами = 6 * 7 / 2 = 21
sum(LCP) = 0 + 1 + 3 + 0 + 0 + 2 = 6
различных подстрок = 21 - 6 = 15
```

### 10.6. Ручной подсчёт различных подстрок

Считаем для `banana`. Терминальный суффикс `$` в подстроки исходной строки не добавляет ничего.

| `i` | `SA[i]` | суффикс | длина без `$` | `LCP[i]` | новых различных подстрок |
|---:|---:|---|---:|---:|---:|
| 0 | 6 | `$` | 0 | 0 | 0 |
| 1 | 5 | `a$` | 1 | 0 | 1 |
| 2 | 3 | `ana$` | 3 | 1 | 2 |
| 3 | 1 | `anana$` | 5 | 3 | 2 |
| 4 | 0 | `banana$` | 6 | 0 | 6 |
| 5 | 4 | `na$` | 2 | 0 | 2 |
| 6 | 2 | `nana$` | 4 | 2 | 2 |

Последний столбец считается так:

```text
новые = длина_суффикса_без_$ - LCP[i]
```

Например, суффикс `anana$` имеет длину `5` без `$`, но `LCP[3] = 3`, потому что с предыдущим суффиксом `ana$` уже совпадает префикс `ana`.

Значит, первые три префикса уже были:

```text
a
an
ana
```

А новые префиксы только:

```text
anan
anana
```

Их `2`, поэтому в таблице стоит:

```text
5 - 3 = 2
```

Суммируем последний столбец:

```text
0 + 1 + 2 + 2 + 6 + 2 + 2 = 15
```

Значит, у строки `banana` ровно `15` различных непустых подстрок.

Ещё типовые применения:

- самая длинная повторяющаяся подстрока — это максимум в `LCP`;
- количество вхождений подстроки `P` — длина найденного интервала в `SA`;
- общие подстроки двух строк можно искать через суффиксный массив строки `A#B$` и LCP соседних суффиксов, принадлежащих разным строкам.

Для `banana` максимум `LCP` равен `3`, значит самая длинная повторяющаяся подстрока — `ana`.

---

## 11. Сложности построения через дерево

Если суффиксное дерево построено за `O(n)`, то DFS по дереву тоже `O(n)`.

Значит:

```text
построение SA через suffix tree: O(n)
```

Это верно при условии, что исходящие рёбра каждой вершины уже можно обходить в лексикографическом порядке. Если порядок рёбер приходится дополнительно сортировать, появляется стоимость сортировки детей вершин.

Само суффиксное дерево тоже сложнее реализовать: линейное построение требует нетривиального алгоритма, например Укконена. Кроме того, у дерева обычно больше константы по памяти, потому что нужно хранить вершины, рёбра, границы подстрок на рёбрах, суффиксные ссылки и другую служебную информацию.

Поэтому на практике часто строят суффиксный массив напрямую через сортировку циклических строк — это пункт 24.

## 12. Что сказать на зачёте

Короткий ответ:

> Суффиксный массив — это массив начал суффиксов строки в лексикографическом порядке. Обычно к строке добавляют терминальный символ `$`, чтобы все суффиксы были различны. Если уже построено суффиксное дерево, то суффиксный массив получается DFS-обходом листьев в лексикографическом порядке исходящих рёбер: пути к листьям соответствуют суффиксам, а такой DFS выдаёт их в отсортированном порядке. Для поиска подстроки `P` используется бинарный поиск по `SA`, потому что все суффиксы, начинающиеся с `P`, образуют один непрерывный отрезок. Простой поиск работает за `O(|P| log n + occ)`. Массив `LCP` хранит длины общих префиксов соседних суффиксов; он позволяет ускорять поиск и решать задачи статистики подстрок, например считать количество различных подстрок по формуле `n(n + 1) / 2 - sum(LCP)` и искать самую длинную повторяющуюся подстроку как максимум `LCP`. Память суффиксного массива — `O(n)`.
