# 19. Алгоритм Ахо–Корасик, доказательство линейности, задача с джокером

## 1. Задача

Дано много образцов:

```text
P1, P2, ..., Pk
```

и текст `T`.

Нужно найти все вхождения всех образцов в тексте.

Если запускать КМП для каждого образца отдельно, получится:

```text
O(k · |T|)
```

Ахо–Корасик делает лучше:

```text
O(суммарная длина образцов + |T| + число ответов)
```

---

## 2. Главная идея

Алгоритм строит автомат по множеству образцов.

Он состоит из трёх частей:

1. **Trie** по образцам.
2. **Суффиксные ссылки** `link`.
3. **Выходные ссылки / списки терминальных вершин**, чтобы быстро понимать, какие образцы закончились в текущей позиции текста.

---

## 3. Trie по образцам

Пусть образцы:

```text
he
she
his
hers
```

Строим бор:

```text
root
 ├─ h
 │   ├─ e      terminal: he
 │   │   └─ r
 │   │       └─ s  terminal: hers
 │   └─ i
 │       └─ s      terminal: his
 └─ s
     └─ h
         └─ e      terminal: she
```

Если при чтении текста мы идём по рёбрам trie, то можем находить образцы как пути от корня.

Но проблема:

```text
если перехода нет, нельзя просто вернуться в root всегда;
может быть полезный суффикс текущего прочитанного слова.
```

Для этого нужны суффиксные ссылки.

---

## 4. Суффиксная ссылка

Для вершины `v`, соответствующей строке `str(v)`, суффиксная ссылка ведёт в вершину, соответствующую наибольшему собственному суффиксу `str(v)`, который тоже есть в trie.

Пример:

```text
str(v) = she
```

Собственные суффиксы:

```text
he, e
```

В trie есть `he`, значит:

```text
link(she) = he
```

Смысл:

> Если мы читали `she`, но дальше продолжить не можем, самый длинный полезный остаток — `he`.

---

## 5. Построение ссылок BFS

Ссылки строятся обходом в ширину.

Для детей корня:

```text
link[child] = root
```

Для остальных:

Пусть есть переход:

```text
v --c--> child
```

Тогда:

```text
link[child] = go(link[v], c)
```

То есть берём суффиксную ссылку родителя и пытаемся из неё перейти по тому же символу.

---

## 6. Переход автомата `go(v, c)`

Когда мы в вершине `v` и читаем символ `c`:

1. Если есть trie-ребро по `c`, идём по нему.
2. Иначе идём по суффиксным ссылкам, пока не найдём переход по `c`.
3. Если дошли до корня и перехода нет, остаёмся в корне.

Можно заранее посчитать все переходы `go[v][c]`, если алфавит небольшой.

---

## 7. Поиск по тексту по шагам

Текст:

```text
T = ushers
```

Образцы:

```text
he, she, his, hers
```

Идём по символам.

### Читаем `u`

Из root нет перехода по `u`.

```text
state = root
```

### Читаем `s`

Есть переход:

```text
root --s--> s
```

```text
state = s
```

### Читаем `h`

```text
s --h--> sh
```

```text
state = sh
```

### Читаем `e`

```text
sh --e--> she
```

Вершина `she` терминальная.

Значит, найден образец:

```text
she заканчивается в позиции 3
начинается в позиции 1
```

Но у `she` есть суффиксная ссылка на `he`.

`he` тоже терминальный.

Значит, одновременно найден:

```text
he заканчивается в позиции 3
начинается в позиции 2
```

### Читаем `r`

Из `she` нет перехода по `r`.

Идём по ссылке:

```text
link(she) = he
```

Из `he` есть переход по `r`:

```text
he --r--> her
```

### Читаем `s`

```text
her --s--> hers
```

Нашли `hers`.

## 8. Кодовая схема

```cpp
struct Node {
    int next[26];
    int link;
    vector<int> out;

    Node() {
        fill(next, next + 26, -1);
        link = 0;
    }
};

vector<Node> trie(1);
vector<string> patterns;

void add_string(const string& s, int id) {
    int v = 0;
    for (char ch : s) {
        int c = ch - 'a';
        if (trie[v].next[c] == -1) {
            trie[v].next[c] = (int)trie.size();
            trie.emplace_back();
        }
        v = trie[v].next[c];
    }
    trie[v].out.push_back(id);
}

void build_aho() {
    queue<int> q;

    for (int c = 0; c < 26; c++) {
        int u = trie[0].next[c];
        if (u != -1) {
            trie[u].link = 0;
            q.push(u);
        } else {
            trie[0].next[c] = 0;
        }
    }

    while (!q.empty()) {
        int v = q.front();
        q.pop();

        // Наследуем выходы по суффиксной ссылке.
        for (int id : trie[trie[v].link].out) {
            trie[v].out.push_back(id);
        }

        for (int c = 0; c < 26; c++) {
            int u = trie[v].next[c];
            if (u != -1) {
                trie[u].link = trie[trie[v].link].next[c];
                q.push(u);
            } else {
                trie[v].next[c] = trie[trie[v].link].next[c];
            }
        }
    }
}

vector<pair<int,int>> search_aho(const string& text) {
    vector<pair<int,int>> ans; // (позиция начала, id образца)
    int v = 0;

    for (int i = 0; i < (int)text.size(); i++) {
        int c = text[i] - 'a';
        v = trie[v].next[c];

        for (int id : trie[v].out) {
            int len = (int)patterns[id].size();
            ans.push_back({i - len + 1, id});
        }
    }

    return ans;
}
```

## 9. Доказательство линейности

Если переходы `go` заранее заполнены, то каждый символ текста обрабатывается одним переходом автомата:

```text
v = go[v][c]
```

Это `O(1)` на символ.

Построение trie занимает суммарную длину образцов:

```text
O(sum |Pi|)
```

BFS по вершинам и переходам:

```text
O(number_of_vertices · |Σ|)
```

Если алфавит фиксированный, это линейно от размера trie.

Поиск:

```text
O(|T| + число найденных вхождений)
```

Почему плюс ответы?

Потому что в одной позиции может закончиться много образцов.

Например:

```text
patterns = a, aa, aaa, aaaa
text = aaaa
```

В одной позиции может быть несколько совпадений.

## 10. Задача с джокером

Пусть есть образец с wildcard-символом `?`, который может означать любой символ.

Пример:

```text
P = ab?cd?e
T = xxabxcdyezzabzcdqe
```

Нужно найти все места, где `P` подходит.

---

## 11. Идея решения через Ахо–Корасик

Разбиваем образец по джокерам на обычные куски.

```text
P = ab ? cd ? e
```

Куски:

| кусок | строка | offset в P |
|---|---|---:|
| 0 | `ab` | 0 |
| 1 | `cd` | 3 |
| 2 | `e`  | 6 |

Теперь ищем все куски в тексте одновременно через Ахо–Корасик.

Если кусок `part` длины `len` найден в тексте с началом `pos`, то возможное начало всего образца:

```text
start = pos - offset
```

Для этого `start` увеличиваем счётчик:

```text
cnt[start]++
```

В конце позиция `start` подходит, если:

```text
cnt[start] == количество кусков
```

и образец целиком помещается в текст:

```text
0 <= start
start + |P| <= |T|
```

---

## 12. Пример с джокером по шагам

```text
P = ab?cd?e
T = xxabxcdye
```

Куски:

```text
ab offset 0
cd offset 3
e  offset 6
```

Ищем куски:

```text
T = x x a b x c d y e
idx 0 1 2 3 4 5 6 7 8
```

Нашли `ab` в позиции `2`:

```text
start = 2 - 0 = 2
cnt[2]++
```

Нашли `cd` в позиции `5`:

```text
start = 5 - 3 = 2
cnt[2]++
```

Нашли `e` в позиции `8`:

```text
start = 8 - 6 = 2
cnt[2]++
```

Всего кусков `3`, и:

```text
cnt[2] = 3
```

Значит, образец подходит с позиции `2`:

```text
T[2..8] = abxcdye
P       = ab?cd?e
```

## 13. Кодовая схема для джокеров

```cpp
struct Piece {
    string s;
    int offset;
};

vector<int> wildcard_search(const string& text, const string& pattern) {
    vector<Piece> pieces;

    for (int i = 0; i < (int)pattern.size(); ) {
        if (pattern[i] == '?') {
            i++;
            continue;
        }
        int start = i;
        string cur;
        while (i < (int)pattern.size() && pattern[i] != '?') {
            cur.push_back(pattern[i]);
            i++;
        }
        pieces.push_back({cur, start});
    }

    vector<int> cnt(text.size(), 0);

    // 1. Добавляем все pieces в Ахо–Корасик.
    // 2. При нахождении piece id с началом pos делаем:
    //    candidate = pos - pieces[id].offset;
    //    if valid candidate: cnt[candidate]++;
    // 3. Ответ: cnt[start] == pieces.size().

    vector<int> ans;

    if (pieces.empty()) {
        // Образец состоит только из '?'.
        for (int s = 0; s + (int)pattern.size() <= (int)text.size(); s++) {
            ans.push_back(s);
        }
        return ans;
    }

    // Здесь должен быть запуск Ахо–Корасика по pieces.
    // Конспект показывает идею; реализация автомата такая же, как выше.

    return ans;
}
```

## 14. Сложность задачи с джокером

Пусть суммарная длина всех обычных кусков равна `L`.

Построение Ахо–Корасика:

```text
O(L)
```

Поиск по тексту:

```text
O(|T| + число найденных кусков)
```

Финальная проверка счётчиков:

```text
O(|T|)
```

Итого:

```text
O(L + |T| + число найденных кусков)
```

## 15. Что сказать на зачёте

Короткий ответ:

> Ахо–Корасик строит trie по всем образцам, затем добавляет суффиксные ссылки, которые ведут в вершину наибольшего собственного суффикса текущей строки, присутствующего в trie. При чтении текста автомат переходит по символу, а если прямого ребра нет, использует суффиксные переходы. Все образцы, заканчивающиеся в текущей позиции, берутся из терминальных вершин на пути по выходным ссылкам. При заранее построенных переходах каждый символ текста обрабатывается за `O(1)`, поэтому поиск `O(|T| + answers)`. Для образца с джокерами разбиваем его на куски без джокеров, ищем все куски через Ахо–Корасик, а затем по offsets считаем возможные старты полного образца.
