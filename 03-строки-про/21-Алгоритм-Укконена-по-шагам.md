# 21. Алгоритм Укконена: суффиксные связи, skip/count, доказательство линейности

## 1. Что делает алгоритм Укконена

Алгоритм Укконена строит суффиксное дерево строки за линейное время.

Он делает это **онлайн**:

```text
прочитали S[0]      → дерево для S[0]
прочитали S[0..1]   → дерево для S[0..1]
прочитали S[0..2]   → дерево для S[0..2]
...
```

На каждой фазе добавляется один новый символ.

В конце обычно добавляют уникальный терминатор `$`, чтобы получить явное суффиксное дерево.

Важная мысль:

```text
Укконен строит не "какое-то другое" дерево,
а обычное суффиксное дерево, только без квадратичной вставки всех суффиксов.
```

После каждой фазы дерево может быть **неявным**: некоторые суффиксы заканчиваются внутри рёбер.

После добавления `$` все суффиксы становятся явными листьями.

---

## 2. Почему наивно получается плохо

На фазе `i` нужно добавить новый символ ко всем суффиксам текущего префикса.

Если делать буквально:

```text
фаза 0: добавить 1 суффикс
фаза 1: добавить 2 суффикса
фаза 2: добавить 3 суффикса
...
```

Получается:

```text
1 + 2 + ... + n = O(n^2)
```

Укконен ускоряет это за счёт:

1. глобального конца листьев;
2. active point;
3. суффиксных ссылок;
4. skip/count trick;
5. правила остановки Rule 3.

---

## 3. Фаза и расширение

В классическом описании есть два уровня:

1. **Фаза** — добавили очередной символ `S[i]`.
2. **Расширение** — в этой фазе обработали один суффикс.

Например, для префикса:

```text
S[0..i]
```

надо было бы обработать суффиксы:

```text
S[0..i]
S[1..i]
S[2..i]
...
S[i..i]
```

Но алгоритм не вставляет их заново.

Он хранит, сколько суффиксов ещё "висят" и ждут явной обработки:

```text
remainder
```

Если в фазе добавился символ `c = S[i]`, то:

```text
remainder++
```

Пока `remainder > 0`, алгоритм пытается добавить `c` к очередному суффиксу.

Если создаётся новый лист или делается split, один суффикс обработан:

```text
remainder--
```

Если срабатывает Rule 3, фаза останавливается, а `remainder` переносится дальше.

---

## 4. Как хранятся рёбра

На ребре не хранят строку явно.

Ребро хранит границы подстроки исходной строки:

```text
[start, end]
```

Например, если:

```text
S = banana$
```

то ребро:

```text
ana
```

можно хранить как:

```text
[1, 3]
```

потому что:

```text
S[1..3] = ana
```

Длина ребра:

```text
edgeLength = end - start + 1
```

Для листовых рёбер `end` обычно не число, а ссылка на общий конец.

---

## 5. Глобальный конец листьев

В суффиксном дереве многие рёбра ведут в листья.

Если каждый раз при добавлении символа продлевать каждое листовое ребро, будет дорого.

Укконен хранит конец листовых рёбер как ссылку на общую переменную:

```text
globalEnd = текущая позиция последнего добавленного символа
```

Листовое ребро хранит:

```text
[start, &globalEnd]
```

Когда добавили новый символ, просто увеличили `globalEnd`, и все листья как будто продлились сами.

Это называется **Rule 1**.

---

## 6. Active point

Чтобы не начинать каждый раз от корня, Укконен хранит активную точку:

```text
activeNode
activeEdge
activeLength
```

Смысл:

- `activeNode` — вершина, откуда сейчас смотрим;
- `activeEdge` — первый символ ребра, по которому идём;
- `activeLength` — сколько символов уже прошли по этому ребру.

Активная точка может находиться:

1. прямо в вершине;
2. внутри ребра.

---

### Как читать active point

Если:

```text
activeNode = root
activeEdge = символ a
activeLength = 2
```

это значит:

```text
из root идём по ребру, которое начинается с a,
и уже прошли по нему 2 символа
```

Например, есть ребро:

```text
root -- abx... --> ...
```

Тогда active point находится здесь:

```text
ab|x...
```

Если `activeLength = 0`, active point находится прямо в `activeNode`.

---

### Что именно хранит activeEdge

В реализации `activeEdge` часто хранят не как символ, а как индекс в строке:

```text
activeEdge = позиция в S
```

Текущий первый символ активного ребра:

```text
S[activeEdge]
```

Это удобно, потому что при сдвиге к следующему суффиксу можно просто поменять индекс.

---

## 7. Remainder

`remainder` — сколько суффиксов текущего префикса ещё надо явно обработать на этой фазе.

На каждой новой фазе:

```text
remainder++
```

Каждый раз, когда мы создаём новый лист или делаем split, один суффикс становится обработанным:

```text
remainder--
```

Если сработало Rule 3, фаза заканчивается раньше, а `remainder` переносится на следующую фазу.

Пример:

```text
S = aba
```

После добавления второго `a` суффикс `a` уже есть внутри ребра `aba`.

Новый лист создавать не надо.

Срабатывает Rule 3:

```text
remainder = 1
```

Это означает:

```text
один суффикс уже есть в дереве неявно,
но пока не стал отдельным листом
```

Когда позже добавится терминатор `$`, этот отложенный суффикс станет явным.

---

## 8. Три правила расширения

Пусть на фазе добавляется символ `c = S[i]`.

### Rule 1: продлить все листья

Это делается автоматически через `globalEnd`.

Ничего явно обходить не надо.

### Rule 2: нужно создать новый лист или split

Если из active point нельзя продолжить символом `c`, значит текущего суффикса ещё нет.

Два варианта:

#### 2a. Active point в вершине

Если из вершины нет ребра по `c`, создаём новый лист.

```text
activeNode --c...--> new leaf
```

#### 2b. Active point внутри ребра

Если внутри ребра следующий символ не равен `c`, нужно разрезать ребро:

```text
старое ребро:  A -- xyz... --> B
active point после x
новый символ c
```

После split:

```text
A -- x --> split
split -- yz... --> B
split -- c...  --> new leaf
```

### Rule 3: символ уже есть

Если из active point можно продолжить символом `c`, значит текущий суффикс уже присутствует в дереве.

Тогда:

```text
activeLength++
фаза заканчивается
```

Почему можно закончить фазу?

Если самый длинный ещё необработанный суффикс уже есть, то все его суффиксы тоже есть как подстроки дерева.

Например, если в дереве уже есть строка:

```text
abac
```

то её суффиксы тоже встречаются как подстроки:

```text
bac
ac
c
```

Поэтому после Rule 3 оставшиеся расширения не создадут новых рёбер.

---

## 9. Суффиксные ссылки

Суффиксная ссылка из внутренней вершины со строкой `xα` ведёт в вершину со строкой `α`.

Например:

```text
abc → bc
anana → nana
```

Зачем они нужны?

Когда мы обработали один суффикс, следующий суффикс отличается тем, что у него отброшен первый символ.

Вместо того чтобы идти от корня, можно перейти по суффиксной ссылке.

Если суффиксной ссылки ещё нет, обычно ведём её в `root`.

Для корня суффиксная ссылка тоже считается ведущей в `root`.

---

## 10. Пример суффиксной ссылки

Пусть после split появилась внутренняя вершина для строки:

```text
ana
```

Тогда её суффиксная ссылка должна вести в вершину для:

```text
na
```

Если вершина `na` ещё не создана, ссылка будет поставлена позже, когда она появится.

В алгоритме используется переменная вроде:

```text
lastNewNode
```

Она помнит последнюю созданную внутреннюю вершину на текущей фазе.

Когда создаётся следующая внутренняя вершина, можно проставить ссылку:

```text
lastNewNode.suffixLink = currentSplit
```

Почему ссылка ставится именно так?

В одной фазе split-ы обычно создают вершины для строк:

```text
xα
α
```

Значит, первая созданная вершина должна ссылаться на следующую.

## 11. Каноническая активная точка и skip/count

Рёбра могут быть длинными.

Если active point должен пройти по ребру длины `len`, не надо сравнивать символы по одному.

Если:

```text
activeLength >= edgeLength
```

то можно перепрыгнуть всё ребро целиком:

```text
activeNode = child
activeLength -= edgeLength
activeEdgeIndex += edgeLength
```

Это и есть **skip/count**.

Смысл:

> Мы считаем длины рёбер и прыгаем через целые рёбра, а не идём по каждому символу.

После такого прыжка active point снова должен быть в нормальном виде:

```text
activeLength < длина активного ребра
```

Такую active point называют **канонической**.

Идея:

```text
если activeLength хватает пройти целое ребро,
то active point на самом деле лежит глубже
```

Значит, надо спуститься по дереву.

---

## 12. Основной цикл алгоритма

Каркас Укконена можно запомнить так:

```text
root = новая вершина
activeNode = root
activeEdge = 0
activeLength = 0
remainder = 0
globalEnd = -1

for pos = 0..n-1:
    globalEnd = pos
    remainder++
    lastNewNode = null

    while remainder > 0:
        если activeLength == 0:
            activeEdge = pos

        если из activeNode нет ребра по S[activeEdge]:
            создать лист [pos, globalEnd]
            если lastNewNode != null:
                lastNewNode.suffixLink = activeNode
                lastNewNode = null

        иначе:
            next = ребро из activeNode по S[activeEdge]

            если activeLength >= length(next):
                перепрыгнуть next через skip/count
                continue

            если S[next.start + activeLength] == S[pos]:
                activeLength++
                если lastNewNode != null:
                    lastNewNode.suffixLink = activeNode
                break

            иначе:
                split = разрезать next после activeLength символов
                создать новый лист из split по S[pos]

                если lastNewNode != null:
                    lastNewNode.suffixLink = split
                lastNewNode = split

        remainder--

        если activeNode == root и activeLength > 0:
            activeLength--
            activeEdge = pos - remainder + 1
        иначе если activeNode != root:
            activeNode = activeNode.suffixLink
```

Это не полный код, но это главный скелет.

Если понимать этот цикл, остальные детали уже технические.

## 13. Как обновляется active point после расширения

После Rule 2 один суффикс обработан.

Нужно перейти к следующему суффиксу.

Есть два случая.

### Случай 1: activeNode — root

Если мы в корне и `activeLength > 0`, то следующий суффикс получается удалением первого символа.

Поэтому:

```text
activeLength--
activeEdge = pos - remainder + 1
```

Например, если обрабатывали:

```text
aba$
```

после split для суффикса `a$` нужно перейти к суффиксу:

```text
$
```

То есть активная длина уменьшается.

### Случай 2: activeNode не root

Если мы не в корне, переходим по суффиксной ссылке:

```text
activeNode = activeNode.suffixLink
```

Смысл:

```text
xα  →  α
```

После перехода active point описывает следующий суффикс.

## 14. Где создаются новые внутренние вершины

Новая внутренняя вершина появляется только при split.

Ситуация:

```text
есть ребро с символами: x y z ...
active point после x
новый символ: c
y != c
```

Тогда старое ребро режется:

```text
до:

A -- xyz... --> B

после:

A     -- x    --> split
split -- yz... --> B
split -- c...  --> new leaf
```

Вершина `split` стала внутренней.

Именно для таких вершин нужны suffix links.

Листам suffix links не нужны.

## 15. Маленький пример построения: `aba$`

Построим суффиксное дерево для:

```text
S = aba$
```

### Фаза 0: добавляем `a`

```text
remainder = 1
```

Из root нет ребра `a`.

Создаём лист:

```text
root
 └─ a...  leaf 0
```

`remainder = 0`.

### Фаза 1: добавляем `b`

Лист `a...` автоматически стал `ab` из-за `globalEnd`.

Из root нет ребра `b`.

Создаём лист:

```text
root
 ├─ ab... leaf 0
 └─ b...  leaf 1
```

### Фаза 2: добавляем `a`

Листья автоматически продлились:

```text
ab... → aba
b...  → ba
```

Нужно добавить суффикс `a`.

Из root есть ребро на `a`.
Следующий символ совпадает.

Срабатывает Rule 3:

```text
activeLength = 1
remainder остаётся 1
фаза заканчивается
```

Суффикс `a` пока находится внутри ребра `aba` — дерево неявное.

### Фаза 3: добавляем `$`

Листья автоматически продлились до `$`.

Теперь нужно обработать старый `remainder = 1` плюс новый символ:

```text
remainder = 2
```

Active point находится внутри ребра `aba$` после символа `a`.

Следующий символ на ребре — `b`, а новый символ — `$`.

```text
b != $
```

Нужно split:

```text
root
 ├─ a
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 └─ ba$      leaf 1
```

`remainder` уменьшается до `1`.

Так как activeNode = root и activeLength > 0:

```text
activeLength--
activeEdge сдвигается к следующему суффиксу
```

Теперь нужно добавить суффикс `$`.

Из root нет ребра `$`, создаём лист:

```text
root
 ├─ a
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 ├─ ba$      leaf 1
 └─ $        leaf 3
```

`remainder = 0`.

Готово.

## 16. Полный пример построения: `ababa$`

Исходная строка:

```text
ababa
```

Для явного суффиксного дерева добавим терминатор:

```text
S = ababa$
```

Индексы:

```text
0 1 2 3 4 5
a b a b a $
```

Лист `leaf i` означает суффикс, который начинается в позиции `i`.

### Фаза 0: добавляем `a`

```text
remainder = 1
globalEnd = 0
```

Из `root` нет ребра по `a`, создаём лист:

```text
root
 └─ a  leaf 0
```

`remainder = 0`.

### Фаза 1: добавляем `b`

`globalEnd = 1`, поэтому старый лист автоматически стал длиннее:

```text
a  →  ab
```

Теперь надо добавить суффикс `b`.

Из `root` нет ребра по `b`, создаём лист:

```text
root
 ├─ ab  leaf 0
 └─ b   leaf 1
```

`remainder = 0`.

### Фаза 2: добавляем `a`

Листья автоматически продлились:

```text
ab  →  aba
b   →  ba
```

Теперь надо добавить суффикс `a`.

Из `root` уже есть ребро по `a`, и следующий символ совпадает. Срабатывает Rule 3:

```text
activeNode = root
activeEdge = a
activeLength = 1
remainder = 1
```

Дерево пока неявное:

```text
root
 ├─ aba  leaf 0
 └─ ba   leaf 1
```

Суффикс `a` уже есть, но заканчивается внутри ребра `aba`.

### Фаза 3: добавляем `b`

Сначала `remainder` увеличивается:

```text
старый remainder = 1
новый символ b
remainder = 2
```

Листья автоматически продлились:

```text
aba  →  abab
ba   →  bab
```

Active point стоит внутри ребра `abab` после строки `a`.
Следующий символ на ребре — `b`, новый символ тоже `b`.

Снова Rule 3:

```text
activeLength = 2
remainder = 2
```

Дерево остаётся неявным:

```text
root
 ├─ abab  leaf 0
 └─ bab   leaf 1
```

Теперь внутри рёбер спрятаны суффиксы:

```text
ab
b
```

### Фаза 4: добавляем `a`

```text
старый remainder = 2
новый символ a
remainder = 3
```

Листья автоматически продлились:

```text
abab  →  ababa
bab   →  baba
```

Active point стоит внутри ребра `ababa` после строки `ab`.
Следующий символ на ребре — `a`, новый символ тоже `a`.

Срабатывает Rule 3:

```text
activeLength = 3
remainder = 3
```

Дерево:

```text
root
 ├─ ababa  leaf 0
 └─ baba   leaf 1
```

Оно всё ещё неявное. Внутри рёбер спрятаны суффиксы:

```text
aba
ba
a
```

### Фаза 5: добавляем `$`

Терминатор ломает все совпадения, поэтому отложенные суффиксы становятся явными.

```text
старый remainder = 3
новый символ $
remainder = 4
```

Листья автоматически продлились:

```text
ababa  →  ababa$
baba   →  baba$
```

Теперь надо обработать четыре суффикса:

```text
aba$
ba$
a$
$
```

#### Расширение 1: суффикс `aba$`

Active point находится внутри ребра `ababa$` после строки `aba`.

Следующий символ на ребре — `b`, а новый символ — `$`:

```text
b != $
```

Делаем split после `aba`:

```text
root
 ├─ aba
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 └─ baba$    leaf 1
```

Создалась внутренняя вершина `aba`.

```text
remainder = 3
```

Так как `activeNode = root`, переходим к следующему суффиксу:

```text
activeLength--
activeLength = 2
```

Теперь активная строка — `ba`.

#### Расширение 2: суффикс `ba$`

В `root` есть ребро `baba$`.

Active point находится внутри него после строки `ba`.
Следующий символ на ребре — `b`, новый символ — `$`:

```text
b != $
```

Делаем split после `ba`:

```text
root
 ├─ aba
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 └─ ba
     ├─ ba$  leaf 1
     └─ $    leaf 3
```

Создалась внутренняя вершина `ba`.

Теперь можно поставить суффиксную ссылку от предыдущей внутренней вершины:

```text
aba -> ba
```

```text
remainder = 2
activeLength = 1
```

Теперь активная строка — `a`.

#### Расширение 3: суффикс `a$`

В `root` есть ребро `aba`.

Active point находится внутри него после строки `a`.
Следующий символ на ребре — `b`, новый символ — `$`:

```text
b != $
```

Делаем split после `a`:

```text
root
 ├─ a
 │   ├─ ba
 │   │   ├─ ba$  leaf 0
 │   │   └─ $    leaf 2
 │   └─ $        leaf 4
 └─ ba
     ├─ ba$      leaf 1
     └─ $        leaf 3
```

Создалась внутренняя вершина `a`.

Ставим следующую суффиксную ссылку:

```text
ba -> a
```

```text
remainder = 1
activeLength = 0
```

Теперь осталось добавить только суффикс `$`.

#### Расширение 4: суффикс `$`

Active point снова в `root`.

Из `root` нет ребра по `$`, создаём лист:

```text
root
 ├─ a
 │   ├─ ba
 │   │   ├─ ba$  leaf 0
 │   │   └─ $    leaf 2
 │   └─ $        leaf 4
 ├─ ba
 │   ├─ ba$      leaf 1
 │   └─ $        leaf 3
 └─ $            leaf 5
```

Последняя внутренняя вершина `a` получает ссылку в `root`:

```text
a -> root
```

`remainder = 0`, построение закончено.

### Что получилось

Все суффиксы строки `ababa$` стали явными листьями:

```text
leaf 0: ababa$
leaf 1: baba$
leaf 2: aba$
leaf 3: ba$
leaf 4: a$
leaf 5: $
```

Суффиксные ссылки между созданными внутренними вершинами:

```text
aba -> ba
ba  -> a
a   -> root
```

Почему именно так?

Потому что suffix link удаляет первый символ строки вершины:

```text
aba без первого символа = ba
ba  без первого символа = a
a   без первого символа = пустая строка = root
```

В этом конкретном примере после split-ов работает специальное правило для `root`:

```text
activeLength--
```

Но созданная цепочка показывает, какие suffix links получают внутренние вершины. В общем случае, когда `activeNode` не равен `root`, алгоритм переходит к следующему суффиксу именно по такой ссылке.

---

## 17. Почему Rule 3 завершает фазу

Если на текущей фазе мы пытаемся добавить символ `c` к некоторому суффиксу и видим, что переход по `c` уже есть, значит этот суффикс уже присутствует.

Все более короткие суффиксы тоже уже присутствуют, потому что они являются суффиксами уже существующей строки.

Поэтому оставшиеся расширения ничего нового не создадут.

Можно остановить фазу.

## 18. Доказательство линейности

Линейность Укконена держится на нескольких амортизациях.

### 18.1 Листья не продлеваются явно

Все листья имеют общий `globalEnd`.

Добавление символа не требует пройти по всем листьям.

Это убирает очевидный `O(n^2)`.

### 18.2 Внутренних вершин линейно много

Каждый split создаёт одну внутреннюю вершину.

В суффиксном дереве для строки длины `n` внутренних вершин `O(n)`.

Значит, split-ов всего `O(n)`.

### 18.3 Листьев линейно много

Каждый суффикс даёт один лист.

Листьев не больше `n`.

### 18.4 Суффиксные ссылки не дают ходить от корня каждый раз

После обработки одного суффикса следующий суффикс находится переходом по suffix link.

Суммарное число переходов по suffix links — `O(n)` амортизированно.

### 18.5 Skip/count прыгает по рёбрам

При переходе вниз мы не идём по символам длинного ребра.

Мы сравниваем длину ребра с `activeLength` и прыгаем целиком.

Каждый такой прыжок переводит active point ниже по дереву, и суммарно таких переходов линейно много.

### 18.6 Почему `remainder` не делает алгоритм квадратичным

Кажется, что `while remainder > 0` может дать `O(n^2)`.

Но каждая итерация цикла делает одно из двух:

1. создаёт лист или split и уменьшает `remainder`;
2. срабатывает Rule 3 и сразу заканчивает фазу.

Созданий листьев и split-ов всего `O(n)`.

Rule 3 может случиться не больше одного раза на фазу.

Значит, суммарно внутренний цикл не становится квадратичным.

### 18.7 Итог

Все дорогие события ограничены линейно:

```text
создание листьев: O(n)
создание внутренних вершин: O(n)
переходы по suffix links: O(n)
skip/count переходы: O(n)
```

Значит:

```text
O(n)
```

## 19. Сложность

При фиксированном алфавите или хеш-таблицах переходов:

```text
Время: O(n)
Память: O(n)
```

Если переходы в вершинах хранятся в `map`, то может быть:

```text
O(n log |Σ|)
```

## 20. Частые ошибки

### Ошибка 1: думать, что Rule 1 реально проходит по всем листьям

Нет.

Листья продлеваются не циклом, а через общий `globalEnd`.

### Ошибка 2: забывать, что active point может быть внутри ребра

В compact trie не все символы представлены вершинами.

Поэтому active point — это не просто вершина, а тройка:

```text
(activeNode, activeEdge, activeLength)
```

### Ошибка 3: после split не проставлять suffix link

Если в одной фазе создано несколько внутренних вершин, они должны связаться suffix links.

Для этого нужна переменная:

```text
lastNewNode
```

### Ошибка 4: сравнивать длинные рёбра посимвольно

Для линейности нужен skip/count:

```text
если activeLength >= edgeLength,
прыгаем через всё ребро
```

### Ошибка 5: строить без терминатора и ждать явное дерево

Без `$` дерево может остаться неявным.

Некоторые суффиксы будут заканчиваться внутри рёбер.

## 21. Что сказать на зачёте

Короткий ответ:

> Алгоритм Укконена строит суффиксное дерево онлайн по фазам, добавляя символы слева направо. Он поддерживает active point `(activeNode, activeEdge, activeLength)` и `remainder` — число ещё не обработанных суффиксов. Листья продлеваются автоматически через общий `globalEnd`. Если нужно добавить новый переход, создаётся лист или делается split ребра. Если нужный символ уже есть, срабатывает Rule 3 и фаза заканчивается. Суффиксные ссылки позволяют после обработки суффикса быстро перейти к следующему, а skip/count позволяет перепрыгивать длинные рёбра по длинам. Линейность следует из того, что листьев и внутренних вершин `O(n)`, переходов по suffix links и skip/count суммарно `O(n)`, а листья не продлеваются явно.
