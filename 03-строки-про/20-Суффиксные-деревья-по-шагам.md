# 20. Суффиксные деревья: неявные, наивное построение, обобщённые

## 1. Что такое суффикс

Суффикс строки — это окончание строки.

Для строки:

```text
S = banana$
```

суффиксы:

```text
banana$
anana$
nana$
ana$
na$
a$
$
```

Символ `$` — специальный терминальный символ, который меньше/отличен от всех остальных и встречается только один раз.

Он нужен, чтобы никакой суффикс не был префиксом другого.

---

## 2. Что такое суффиксное дерево

**Суффиксное дерево** строки `S` — это compact trie всех суффиксов строки `S`.

То есть:

1. Берём все суффиксы строки.
2. Строим trie.
3. Сжимаем цепочки вершин степени 1 в одно ребро.

Рёбра подписаны не отдельными символами, а подстроками исходной строки.

---

## 3. Почему это compact trie

Если построить обычный trie всех суффиксов `banana$`, будет много длинных цепочек.

Например, суффикс:

```text
banana$
```

дал бы путь:

```text
b → a → n → a → n → a → $
```

В compact trie это можно хранить одним ребром:

```text
banana$
```

Но физически в памяти обычно не хранят саму строку на ребре. Хранят пару индексов:

```text
[start, end]
```

которая указывает на подстроку исходного `S`.

---

## 4. Пример маленького суффиксного дерева

Возьмём:

```text
S = aba$
```

Суффиксы:

```text
0: aba$
1: ba$
2: a$
3: $
```

Суффиксное дерево:

```text
root
 ├─ a
 │   ├─ ba$   leaf 0
 │   └─ $     leaf 2
 ├─ ba$       leaf 1
 └─ $         leaf 3
```

Проверим:

- путь `a + ba$ = aba$` — суффикс с позиции 0;
- путь `ba$` — суффикс с позиции 1;
- путь `a + $ = a$` — суффикс с позиции 2;
- путь `$` — суффикс с позиции 3.

---

## 5. Зачем суффиксное дерево нужно

Оно позволяет быстро отвечать на запрос:

```text
является ли P подстрокой S?
```

Потому что любая подстрока строки `S` является префиксом какого-то суффикса `S`.

Значит, чтобы найти `P`, надо просто пройти по дереву символы `P`.

Если смогли пройти — `P` есть в `S`.

---

## 6. Поиск подстроки по шагам

Дерево для:

```text
S = aba$
```

```text
root
 ├─ a
 │   ├─ ba$   leaf 0
 │   └─ $     leaf 2
 ├─ ba$       leaf 1
 └─ $         leaf 3
```

Ищем:

```text
P = ba
```

Из root есть ребро `ba$`.

Сравниваем `P` с началом ребра:

```text
b == b
a == a
```

Образец закончился внутри ребра.

Значит, `ba` есть в строке.

Где?

Все листья под этой точкой дают позиции вхождений. Здесь это leaf `1`.

---

## 7. Наивное построение суффиксного дерева

Самый простой способ:

1. Начинаем с пустого дерева.
2. Для каждого суффикса `S[i..n-1]` вставляем его в compact trie.
3. При вставке идём по рёбрам, сравнивая подписи.
4. Если на ребре случилось частичное совпадение, разрезаем ребро.
5. Добавляем новый лист.

Сложность наивного построения:

```text
O(n^2)
```

потому что суммарная длина всех суффиксов — квадратичная:

```text
n + (n-1) + ... + 1 = O(n^2)
```

---

## 8. Вставка суффикса в compact trie по шагам

Построим дерево для:

```text
S = aba$
```

### Вставляем суффикс `aba$`

Дерево пустое.

Создаём ребро:

```text
root
 └─ aba$   leaf 0
```

### Вставляем суффикс `ba$`

Из root нет ребра на `b`.

Добавляем:

```text
root
 ├─ aba$   leaf 0
 └─ ba$    leaf 1
```

### Вставляем суффикс `a$`

Из root есть ребро `aba$`, потому что оно начинается с `a`.

Сравниваем:

```text
a == a
$ != b
```

Совпала только первая буква `a`.

Нужно разрезать ребро `aba$`:

```text
aba$ = a + ba$
```

Получаем:

```text
root
 ├─ a
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 └─ ba$      leaf 1
```

### Вставляем суффикс `$`

Из root нет ребра на `$`.

Добавляем:

```text
root
 ├─ a
 │   ├─ ba$  leaf 0
 │   └─ $    leaf 2
 ├─ ba$      leaf 1
 └─ $        leaf 3
```

Готово.

---

## 9. Неявное суффиксное дерево

**Неявное суффиксное дерево** — это суффиксное дерево для строки без обязательного терминального символа `$`.

Проблема без `$`:

```text
S = aba
```

Суффиксы:

```text
aba
ba
a
```

Суффикс `a` является префиксом суффикса `aba`.

В обычном суффиксном дереве лист для `a` может не появиться явно: он заканчивается внутри ребра.

Для `aba` неявное дерево можно представить как:

```text
root
 ├─ aba
 └─ ba
```

Суффикс `a` спрятан внутри ребра `aba`.

Когда добавляем терминатор `$`, все суффиксы становятся различными листьями:

```text
aba$, ba$, a$, $
```

---

## 10. Где появляются неявные деревья в Укконене

Алгоритм Укконена строит дерево онлайн, символ за символом.

После каждой фазы для префикса `S[0..i]` он фактически имеет **неявное суффиксное дерево** этого префикса.

Только когда добавлен уникальный терминатор `$`, дерево становится явным: все суффиксы заканчиваются в листьях.

---

## 11. Обобщённое суффиксное дерево

**Обобщённое суффиксное дерево** строится не для одной строки, а для нескольких.

Например, есть две строки:

```text
A = aba
B = bab
```

К каждой строке добавляем свой терминатор:

```text
A#
B$
```

Терминаторы должны быть:

1. разными;
2. не встречаться в исходных строках;
3. отличаться от обычных символов алфавита.

Для примера:

```text
A# = aba#
B$ = bab$
```

Потом строки склеиваются:

```text
T = aba#bab$
```

и для `T` строится обычное суффиксное дерево.

---

### Как строится обобщённое дерево

Порядок такой:

1. Берём строки `S1, S2, ..., Sk`.
2. Добавляем к ним разные терминаторы:

```text
S1#1
S2#2
...
Sk#k
```

3. Склеиваем всё в одну строку:

```text
T = S1#1S2#2...Sk#k
```

4. Строим суффиксное дерево для `T`.
5. Каждый лист помечаем цветом той строки, из которой начался его суффикс.

Например, для:

```text
T = aba#bab$
```

суффиксы, начинающиеся внутри `A`, получают цвет `A`:

```text
aba#bab$   начинается в A
ba#bab$    начинается в A
a#bab$     начинается в A
```

суффиксы, начинающиеся внутри `B`, получают цвет `B`:

```text
bab$       начинается в B
ab$        начинается в B
b$         начинается в B
```

Суффиксы, которые начинаются с терминаторов, обычно не важны для задач про исходные строки:

```text
#bab$
$
```

Важно: обычные подстроки не должны проходить через терминатор.

Например, строка:

```text
a#b
```

есть в склеенной строке `aba#bab$`, но её нет ни в `A`, ни в `B`.

Поэтому при решении задач учитывают только пути без терминаторов или мысленно обрезают суффиксы на первом терминаторе.

---

### Пример дерева для `aba` и `bab`

Если для каждого суффикса оставить только часть до первого терминатора включительно, листья можно представить так:

```text
A: aba#
A: ba#
A: a#
B: bab$
B: ab$
B: b$
```

Обобщённое дерево:

```text
root
 ├─ a
 │   ├─ b
 │   │   ├─ a#   leaf A:0
 │   │   └─ $    leaf B:1
 │   └─ #        leaf A:2
 ├─ b
 │   ├─ a
 │   │   ├─ #    leaf A:1
 │   │   └─ b$   leaf B:0
 │   └─ $        leaf B:2
 ├─ #            leaf terminal
 └─ $            leaf terminal
```

Что здесь видно:

- путь `a → b` даёт подстроку `ab`;
- под ним есть лист `A:0` и лист `B:1`, значит `ab` встречается в обеих строках;
- путь `b → a` даёт подстроку `ba`;
- под ним есть лист `A:1` и лист `B:0`, значит `ba` тоже встречается в обеих строках.

Лист `A:0` означает: суффикс начался в строке `A` с позиции `0`.

Лист `B:1` означает: суффикс начался в строке `B` с позиции `1`.

---

### Цвета внутренних вершин

Цвет листа известен сразу:

```text
leaf A:i имеет цвет A
leaf B:j имеет цвет B
```

Цвет внутренней вершины — это объединение цветов её детей.

Например:

```text
вершина для ab имеет цвета {A, B}
вершина для a имеет цвета {A, B}
лист A:2 имеет цвет {A}
```

Если у вершины есть цвета `{A, B}`, значит строка на пути от корня до этой вершины встречается и в `A`, и в `B`.

Если у вершины есть только `{A}`, значит такая подстрока встречается только в `A`.

Для многих строк аналогично:

```text
цвета вершины = множество номеров строк, где встречается эта подстрока
```

## 12. Зачем нужно обобщённое дерево

Оно позволяет решать задачи про несколько строк:

1. Наибольшая общая подстрока двух строк.
2. Наибольшая общая подстрока многих строк.
3. Поиск образца в базе текстов.
4. Подсчёт повторов, общих фрагментов, статистики совпадений.

### Пример задачи: наибольшая общая подстрока

Пусть:

```text
A = aba
B = bab
```

Нужно найти самую длинную подстроку, которая встречается в обеих строках.

Строим обобщённое дерево для:

```text
aba#bab$
```

Дальше для каждой вершины считаем множество цветов в её поддереве.

Интересуют вершины с цветами:

```text
{A, B}
```

То есть вершины, под которыми есть листья обеих строк.

В нашем дереве:

```text
путь ab имеет цвета {A, B}
путь ba имеет цвета {A, B}
```

Обе строки имеют длину `2`.

Более глубоких вершин с двумя цветами нет.

Значит, наибольшие общие подстроки:

```text
ab
ba
```

Если нужен один ответ, можно вывести любую из них.

Общее правило:

```text
LCS = самая глубокая вершина, в поддереве которой есть листья всех нужных цветов
```

Глубина вершины — это длина строки на пути от корня.

Для двух строк `banana` и `ananas` по тому же правилу получится:

```text
anana
```

---

## 13. Сложности

Если дерево уже построено:

```text
Поиск образца P: O(|P| + число ответов)
```

Наивное построение:

```text
O(n^2)
```

Укконен:

```text
O(n)
```

при фиксированном алфавите или словарях переходов с амортизированным `O(1)`.

Память суффиксного дерева:

```text
O(n)
```

потому что в compact trie число вершин и рёбер линейно.

---

## 14. Что сказать на зачёте

Короткий ответ:

> Суффиксное дерево строки `S$` — это compact trie всех суффиксов строки. Рёбра подписаны подстроками исходной строки, обычно хранятся индексами `[l, r]`. Благодаря терминатору `$` каждый суффикс заканчивается в отдельном листе. Поиск подстроки `P` выполняется проходом по рёбрам за `O(|P|)`, а листья под найденной точкой дают позиции вхождений. Наивное построение вставляет все суффиксы в compact trie и работает за `O(n^2)`. Неявное суффиксное дерево возникает без терминатора, когда некоторые суффиксы заканчиваются внутри рёбер. Обобщённое суффиксное дерево строится для строк `S1#1S2#2...Sk#k`, где терминаторы разные. Листья помечаются цветами строк, а цвет внутренней вершины — объединение цветов листьев в её поддереве. Например, LCS — это самая глубокая вершина, в поддереве которой есть листья всех нужных цветов.
