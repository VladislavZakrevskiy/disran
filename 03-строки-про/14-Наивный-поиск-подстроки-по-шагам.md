# 14. Поиск подстроки в строке. Наивный алгоритм поиска

## 1. Задача

Дан текст `T` длины `n` и образец `P` длины `m`.
Нужно найти все позиции `s`, такие что:

```text
T[s .. s + m - 1] = P[0 .. m - 1]
```

Будем считать индексацию с нуля.

Пример:

```text
T = abacaba
P = aba
```

Ответ: позиции `0` и `4`, потому что:

```text
T[0..2] = aba
T[4..6] = aba
```

---

## 2. Главная идея наивного алгоритма

Мы просто прикладываем образец ко всем возможным позициям текста и проверяем символы слева направо.

Возможные старты:

```text
s = 0, 1, 2, ..., n - m
```

Для каждого `s` проверяем:

```text
P[0] == T[s]
P[1] == T[s + 1]
...
P[m - 1] == T[s + m - 1]
```

Если все равны — нашли вхождение.

---

## 3. Алгоритм по шагам

Пусть:

```text
T = abacaba
P = aba
n = 7
m = 3
```

Значит, можно начинать только в позициях:

```text
0, 1, 2, 3, 4
```

Потому что если начать с `5`, то для длины `3` не хватит символов текста.

### Старт `s = 0`

```text
T: a b a c a b a
   ↑ ↑ ↑
P: a b a
```

Сравнения:

```text
P[0] = a, T[0] = a  OK
P[1] = b, T[1] = b  OK
P[2] = a, T[2] = a  OK
```

Все совпало. Значит, ответ содержит `0`.

### Старт `s = 1`

```text
T: a b a c a b a
     ↑ ↑ ↑
P:   a b a
```

Первое же сравнение:

```text
P[0] = a, T[1] = b  mismatch
```

Не подходит.

### Старт `s = 2`

```text
T: a b a c a b a
       ↑ ↑ ↑
P:     a b a
```

```text
P[0] = a, T[2] = a  OK
P[1] = b, T[3] = c  mismatch
```

Не подходит.

### Старт `s = 3`

```text
T: a b a c a b a
         ↑ ↑ ↑
P:       a b a
```

```text
P[0] = a, T[3] = c  mismatch
```

Не подходит.

### Старт `s = 4`

```text
T: a b a c a b a
           ↑ ↑ ↑
P:         a b a
```

```text
P[0] = a, T[4] = a  OK
P[1] = b, T[5] = b  OK
P[2] = a, T[6] = a  OK
```

Нашли вхождение в позиции `4`.

Итог:

```text
answer = [0, 4]
```

## 4. Код

```cpp
#include <bits/stdc++.h>
using namespace std;

vector<int> naive_search(const string& text, const string& pattern) {
    int n = (int)text.size();
    int m = (int)pattern.size();
    vector<int> ans;

    if (m == 0) {
        // По соглашению пустой образец входит в каждую позицию.
        for (int i = 0; i <= n; i++) ans.push_back(i);
        return ans;
    }

    for (int s = 0; s + m <= n; s++) {
        bool ok = true;
        for (int j = 0; j < m; j++) {
            if (text[s + j] != pattern[j]) {
                ok = false;
                break;
            }
        }
        if (ok) ans.push_back(s);
    }

    return ans;
}
```

---

## 5. Сложность

Внешний цикл делает `n - m + 1` попыток.

Внутренний цикл в худшем случае сравнивает `m` символов.

Значит:

```text
T(n, m) = O((n - m + 1) · m)
```

Обычно говорят проще:

```text
O(nm)
```

Память:

```text
O(1), если не считать массив ответа
```

---

## 6. Почему может быть плохо

Плохой пример:

```text
T = aaaaaaaaaab
P = aaaab
```

На многих позициях алгоритм сначала долго сравнивает `a`, `a`, `a`, `a`, и только потом понимает, что в конце не совпало.

То есть одни и те же символы текста могут сравниваться много раз.

Именно это исправляют Z-функция и КМП: они используют информацию о уже сделанных сравнениях.

---

## 7. Что сказать на зачёте

Короткий ответ:

> Наивный алгоритм перебирает все возможные позиции начала образца в тексте. Для каждой позиции он сравнивает образец с соответствующим фрагментом текста посимвольно. Если все `m` символов совпали, позиция является вхождением. В худшем случае есть `n - m + 1` позиций и на каждой до `m` сравнений, поэтому время `O(nm)`, память `O(1)`.
