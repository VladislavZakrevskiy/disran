# 17. Алгоритм Бойера–Мура: плохой символ и хороший суффикс

## 1. Задача

Как обычно, есть:

```text
T — текст длины n
P — образец длины m
```

Нужно найти все вхождения `P` в `T`.

Бойер–Мур — алгоритм, который часто работает очень быстро на практике, потому что умеет сдвигать образец сразу на несколько символов.

> [!info] Лекционные источники
> По [[99-Навигация/01-Карта лекций к темам|карте лекций]] эта тема разбирается в лекциях [13](https://www.youtube.com/watch?v=iezKlm1M2S0), [14](https://www.youtube.com/watch?v=mjiu7Rpk1fY), [15](https://www.youtube.com/watch?v=zV3pN8A0Ebc). Базовая лекционная заметка: [[03-Строки/02-Бойер-Мур|Глава 8.1. Алгоритм Бойера-Мура]].

---

## 2. Главная идея

Наивный алгоритм сравнивает образец слева направо.

Бойер–Мур делает наоборот:

> Прикладываем образец к тексту и сравниваем справа налево.

Почему это полезно?

Потому что если справа встретился «плохой» символ, мы часто можем понять, что несколько следующих позиций точно не подходят.

---

## 3. Общая схема

Пусть образец приложен к тексту с началом в позиции `s`.

```text
T: ... T[s] T[s+1] ... T[s+m-1] ...
P:     P[0] P[1] ... P[m-1]
```

Сравниваем:

```text
P[m-1] с T[s+m-1]
P[m-2] с T[s+m-2]
...
```

Если всё совпало — нашли вхождение.

Если на позиции `j` случилось несовпадение:

```text
P[j] != T[s+j]
```

то считаем два возможных сдвига:

1. сдвиг по правилу **плохого символа**;
2. сдвиг по правилу **хорошего суффикса**.

Берём максимум:

```text
shift = max(bad_character_shift, good_suffix_shift)
```

---

## 4. Правило плохого символа

Пусть несовпадение:

```text
P[j] != T[s+j]
```

Символ текста:

```text
c = T[s+j]
```

Он называется **плохим символом**.

Идея:

> Нужно сдвинуть образец так, чтобы ближайшее такое же `c` в образце оказалось под этим символом текста.

Если символа `c` в образце нет, можно сдвинуть образец так, чтобы он полностью прошёл мимо `c`.

---

## 5. Пример плохого символа

```text
T:  x y z A B C D
P:        A B C X
```

Сравниваем справа:

```text
P[3] = X
T[6] = D
```

Несовпадение. Плохой символ `D`.

В образце `ABCX` символа `D` нет.

Значит, ни одно выравнивание, где `D` стоит под каким-то символом образца, не поможет.
Можно сдвинуть образец за `D`.

---

## 6. Таблица last occurrence

Для каждого символа `c` храним:

```text
last[c] = последняя позиция c в P
```

Если символа нет:

```text
last[c] = -1
```

При несовпадении на позиции `j`:

```text
bad_shift = max(1, j - last[c])
```

Почему `max(1, ...)`?

Потому что сдвиг должен быть хотя бы `1`.

---

## 7. Правило хорошего суффикса

Пусть при сравнении справа налево у нас уже совпал суффикс:

```text
P[j+1 .. m-1]
```

А на позиции `j` случилось несовпадение.

Этот совпавший кусок называется **хорошим суффиксом**.

Идея:

> Раз уж хороший суффикс уже совпал с текстом, попробуем сдвинуть образец так, чтобы другая копия этого суффикса в образце встала на то же место.

Если другой копии нет — пытаемся совместить с текстом максимальный префикс образца, который является суффиксом хорошего суффикса.

---

## 8. Хороший суффикс на пальцах

Пусть:

```text
P = ABAB
```

И при текущем выравнивании справа совпал суффикс:

```text
AB
```

```text
P: A B A B
       ↑ ↑   хороший суффикс AB
```

В образце есть ещё один `AB` в начале:

```text
P: A B A B
   ↑ ↑       другая копия AB
```

Значит, можно сдвинуть образец так, чтобы левый `AB` встал туда, где только что совпал правый `AB`.

---

## 9. Если другой копии нет

Пусть:

```text
P = ABCAB
```

Хороший суффикс:

```text
CAB
```

Другой копии `CAB` в образце нет.

Тогда смотрим: какой суффикс `CAB` является префиксом всего образца `ABCAB`?

Суффиксы `CAB`:

```text
CAB, AB, B
```

Префиксы `ABCAB`:

```text
A, AB, ABC, ABCA, ABCAB
```

Общий максимальный:

```text
AB
```

Значит, можно сдвинуть образец так, чтобы его префикс `AB` совпал с суффиксом уже совпавшего текста.

---

## 10. Более сильное правило плохого символа

В простой версии мы храним только:

```text
last[c] = последняя позиция c в P
```

Этого достаточно для корректности, но это не всегда даёт максимальный сдвиг. Проблема: последняя позиция `c` может стоять **правее** места несовпадения `j`.

Пример:

```text
P = a b c a x
        ↑     ↑
        j     last[a]
```

Если на позиции `j = 2` плохой символ текста равен `a`, то обычная таблица скажет:

```text
j - last[a] = 2 - 3 < 0
```

и мы сдвинемся только на `1`.

Но левее `j` тоже есть `a` в позиции `0`. Можно совместить именно его:

```text
bad_shift = j - prev[a][j]
```

где:

```text
prev[c][j] = ближайшая позиция символа c в P строго левее j
```

Если такой позиции нет:

```text
prev[c][j] = -1
bad_shift = j + 1
```

Такую таблицу в лекциях часто обозначают как `R`: она отвечает не просто за последнее вхождение символа в образце, а за последнее вхождение **до текущей позиции сравнения**.

На зачёте обычно достаточно понимать разницу:

| Вариант | Что хранит | Что даёт |
|---|---|---|
| `last[c]` | последнее вхождение `c` во всём `P` | проще код |
| `R[c][j]` или `prev[c][j]` | последнее вхождение `c` левее `j` | более сильный сдвиг |

## 11. Функция `N` для хорошего суффикса

Хороший суффикс формально удобно считать через функцию `N`.

```text
N[i] = длина наибольшего суффикса P[0..i],
       который одновременно является суффиксом всего P
```

То есть `N[i]` отвечает на вопрос:

> какой кусок, заканчивающийся в позиции `i`, совпадает с концом всего образца?

Пример:

```text
P = a b a b a
```

Для `i = 2`:

```text
P[0..2] = a b a
```

Эта строка сама является суффиксом всего `P = ababa`, значит:

```text
N[2] = 3
```

Как посчитать `N` за `O(m)`:

1. перевернуть образец;
2. посчитать Z-функцию от перевёрнутого образца;
3. отразить индексы обратно.

Идея простая: суффиксы исходной строки становятся префиксами перевёрнутой, а Z-функция как раз быстро считает совпадения с префиксом.

## 12. Таблицы `L` и `small_l`

Для хорошего суффикса нужны две ситуации.

### 12.1 Таблица `L`

Пусть после несовпадения справа уже совпал суффикс:

```text
P[i..m-1]
```

Таблица `L[i]` хранит правое подходящее вхождение этого суффикса внутри образца левее его текущего места.

Подходящее означает важную вещь:

```text
символ перед найденной копией должен отличаться
от символа перед текущим суффиксом
```

Почему это нужно?

Если перед обеими копиями стоит один и тот же символ, то после сдвига мы сразу получим то же самое несовпадение и ничего не выиграем.

Смысл:

```text
если L[i] существует,
сдвигаем P так, чтобы внутренняя копия P[i..m-1]
встала под уже совпавший текст
```

Сдвиг:

```text
good_shift = m - 1 - L[i]
```

### 12.1.1 Пример, где работает `L`

Пусть:

```text
P = D A B C A B
```

И при сравнении справа налево случилась такая ситуация:

```text
индексы: 0 1 2 3 4 5
P:       D A B C A B
               ^ \_/
               j  хороший суффикс AB
```

То есть:

```text
j = 3
i = j + 1 = 4
P[i..m-1] = P[4..5] = AB
```

Справа `AB` уже совпало с текстом, а на позиции `j` был провал:

```text
T:       ? ? ? X A B
P:       D A B C A B
               ^ A B совпали
               C != X
```

Теперь ищем другую копию хорошего суффикса `AB` левее. Она есть:

```text
P:       D A B C A B
           \_/   \_/
         копия   текущий хороший суффикс
```

Левая копия `AB` заканчивается в позиции `2`, значит:

```text
L[4] = 2
```

Сдвиг:

```text
good_shift = m - 1 - L[4]
           = 6 - 1 - 2
           = 3
```

После сдвига на `3` левая копия `AB` встанет ровно туда, где только что совпал правый `AB`:

```text
до:
T:       ? ? ? X A B
P:       D A B C A B

после сдвига на 3:
T:       ? ? ? X A B
P:             D A B C A B
                 \_/
              этот AB стоит под уже совпавшим AB текста
```

Вот это и делает `L`: **пытается переиспользовать весь хороший суффикс целиком**.

### 12.1.2 Почему нужен другой символ слева

Возьмём:

```text
P = B A B A B
```

Пусть хороший суффикс снова `AB`:

```text
индексы: 0 1 2 3 4
P:       B A B A B
             ^ \_/
             j  хороший суффикс AB
```

Текущий `AB` стоит в позициях `3..4`, а другая копия `AB` есть в позициях `1..2`.

Но перед обеими копиями стоит один и тот же символ `B`:

```text
P:       B A B A B
         ^ \_/ ^ \_/
         B     B
```

Если на позиции `j` уже было несовпадение:

```text
P[j] = B
T[s+j] = X
B != X
```

то после сдвига к левой копии мы снова поставим `B` под тот же `X`.

То есть сразу получим тот же провал:

```text
B != X
```

Поэтому такая копия для `L` считается плохой. `L` ищет копию хорошего суффикса, у которой символ слева **отличается** от символа перед текущим хорошим суффиксом.

### 12.2 Таблица `small_l`

Если подходящего внутреннего вхождения нет, используем второй вариант:

```text
small_l[i] = длина наибольшего суффикса P[i..m-1],
             который является префиксом всего P
```

Смысл:

```text
совместить с уже совпавшим текстом не весь хороший суффикс,
а его самый длинный хвост, который совпадает с началом P
```

Сдвиг:

```text
good_shift = m - small_l[i]
```

### 12.2.1 Пример, где работает `small_l`

Пусть:

```text
P = A B C A B
```

И справа уже совпал хороший суффикс:

```text
индексы: 0 1 2 3 4
P:       A B C A B
           ^ \___/
           j  хороший суффикс CAB
```

То есть:

```text
j = 1
i = j + 1 = 2
P[i..m-1] = P[2..4] = CAB
```

Ищем другую копию `CAB` левее:

```text
P = A B C A B
```

Другой копии `CAB` нет. Значит `L[2]` не помогает.

Теперь `small_l` задаёт другой вопрос:

> Если весь хороший суффикс `CAB` переиспользовать нельзя, какой его хвост можно совместить с началом образца?

Смотрим суффиксы `CAB`:

```text
CAB
AB
B
```

Смотрим префиксы всего образца `ABCAB`:

```text
A
AB
ABC
ABCA
ABCAB
```

Максимальное совпадение:

```text
AB
```

Значит:

```text
small_l[2] = 2
```

Сдвиг:

```text
good_shift = m - small_l[2]
           = 5 - 2
           = 3
```

После сдвига начало образца `AB` встанет под хвост уже совпавшего текста:

```text
до:
T:       ? X C A B
P:       A B C A B
           ^ C A B совпали
           B != X

после сдвига на 3:
T:       ? X C A B
P:             A B C A B
               \_/
               AB под уже совпавшим AB текста
```

Вот это и делает `small_l`: **если весь хороший суффикс нельзя переиспользовать, берём его самый длинный хвост, который является началом образца**.

Если даже такого хвоста нет, то:

```text
small_l[i] = 0
good_shift = m
```

То есть образец можно сдвинуть почти целиком за уже проверенный кусок.

Итоговое правило при несовпадении в позиции `j`:

```text
i = j + 1

if хороший суффикс пустой:
    good_shift = 1
else if L[i] существует:
    good_shift = m - 1 - L[i]
else:
    good_shift = m - small_l[i]
```

## 13. Что делать после полного совпадения

Если все символы совпали, мы нашли вхождение. Но просто сдвигаться на `1` часто слишком медленно.

После полного совпадения можно использовать ту же идею префикса-суффикса:

```text
shift_after_match = m - small_l[1]
```

Почему `small_l[1]`, а не `small_l[0]`?

`small_l[0]` фактически может быть равен `m`, то есть всему образцу. Нам нужен собственный бордер: самый длинный собственный суффикс образца, который является его префиксом.

Пример:

```text
P = a b a b
```

Собственный суффикс-префикс:

```text
ab
```

Значит, после найденного вхождения можно сдвинуться на:

```text
m - 2 = 2
```

и не пропустить перекрывающееся вхождение.

## 14. Дополнительные оптимизации: Галиль и Апостолико-Джанкарло

Классические эвристики отвечают на вопрос:

```text
куда сдвигать образец?
```

Но остаётся второй вопрос:

```text
надо ли заново сравнивать куски текста, которые уже точно совпадали?
```

### Правило Галиля

Правило Галиля запоминает защищённый интервал текста, про который уже известно, что он совпадает с частью образца.

Если следующее выравнивание снова попадает на этот интервал, алгоритм не сравнивает его повторно.

Коротко:

```text
если кусок текста уже гарантированно совпал,
при следующем сдвиге его можно перепрыгнуть
```

Эта оптимизация нужна для аккуратной линейной оценки полного Бойера-Мура.

### Апостолико-Джанкарло

Апостолико-Джанкарло можно понимать как более системную версию той же идеи.

Он использует те же сдвиги Бойера-Мура:

```text
bad character
good suffix
```

Но добавляет память о проверенных совпадениях:

```text
skip[pos] = сколько символов текста, заканчивающихся в pos,
            уже известно как совпавшие с суффиксом образца
```

И ещё массив для образца:

```text
suff[j] = насколько известный суффикс применим
          к текущей позиции j образца
```

То есть:

```text
Бойер-Мур              — хорошо выбирает сдвиг.
Галиль                 — не пересравнивает один известный интервал.
Апостолико-Джанкарло   — хранит больше информации через skip/suff.
```

## 15. Полный пример работы

```text
T = ZZABXABCD
P = ABCD
```

### Попытка 1: `s = 0`

```text
T: Z Z A B X A B C D
P: A B C D
         ↑ сравниваем справа
```

Сравниваем:

```text
P[3] = D
T[3] = B
```

Несовпадение. Плохой символ `B`.

В образце `ABCD` последний `B` стоит в позиции `1`.

```text
bad_shift = j - last[B] = 3 - 1 = 2
```

Хорошего суффикса нет, потому что не совпал даже последний символ.

Сдвигаем на `2`.

### Попытка 2: `s = 2`

```text
T: Z Z A B X A B C D
       A B C D
```

Сравниваем справа:

```text
D vs A?  P[3] = D, T[5] = A  mismatch
```

Плохой символ `A`, last[A] = 0:

```text
shift = 3 - 0 = 3
```

### Попытка 3: `s = 5`

```text
T: Z Z A B X A B C D
             A B C D
```

Сравниваем справа:

```text
D == D
C == C
B == B
A == A
```

Нашли вхождение в позиции `5`.

## 16. Код: плохой символ + хороший суффикс

Ниже практическая кодовая схема классического Бойера–Мура.

Здесь правило плохого символа реализовано через простую таблицу `last`, а хороший суффикс — через эквивалентную таблицу `shift`. Лекционные таблицы `R`, `N`, `L`, `small_l` выше нужны, чтобы понимать, откуда берутся эти сдвиги и какие варианты предобработки бывают.

```cpp
#include <bits/stdc++.h>
using namespace std;

const int ALPHA = 256;

vector<int> build_last(const string& p) {
    vector<int> last(ALPHA, -1);
    for (int i = 0; i < (int)p.size(); i++) {
        last[(unsigned char)p[i]] = i;
    }
    return last;
}

void preprocess_strong_suffix(const string& pat, vector<int>& shift, vector<int>& bpos) {
    int m = (int)pat.size();
    int i = m, j = m + 1;
    bpos[i] = j;

    while (i > 0) {
        while (j <= m && pat[i - 1] != pat[j - 1]) {
            if (shift[j] == 0) shift[j] = j - i;
            j = bpos[j];
        }
        i--;
        j--;
        bpos[i] = j;
    }
}

void preprocess_case2(vector<int>& shift, vector<int>& bpos) {
    int m = (int)shift.size() - 1;
    int j = bpos[0];
    for (int i = 0; i <= m; i++) {
        if (shift[i] == 0) shift[i] = j;
        if (i == j) j = bpos[j];
    }
}

vector<int> build_good_suffix(const string& p) {
    int m = (int)p.size();
    vector<int> shift(m + 1, 0), bpos(m + 1, 0);
    preprocess_strong_suffix(p, shift, bpos);
    preprocess_case2(shift, bpos);
    return shift;
}

vector<int> boyer_moore(const string& text, const string& pattern) {
    int n = (int)text.size();
    int m = (int)pattern.size();
    vector<int> ans;
    if (m == 0) return ans;

    vector<int> last = build_last(pattern);
    vector<int> gs = build_good_suffix(pattern);

    int s = 0;
    while (s <= n - m) {
        int j = m - 1;

        while (j >= 0 && pattern[j] == text[s + j]) {
            j--;
        }

        if (j < 0) {
            ans.push_back(s);
            s += gs[0];
        } else {
            int bad = max(1, j - last[(unsigned char)text[s + j]]);
            int good = gs[j + 1];
            s += max(bad, good);
        }
    }

    return ans;
}
```

## 17. Сложность

Предобработка:

```text
O(m + |Σ|)
```

Поиск:

- на практике часто очень быстрый, часто пропускает большие куски текста;
- в худшем случае без дополнительных оптимизаций может быть плохим на специальных строках;
- с правилом Галиля можно получить линейную оценку для поиска всех вхождений;
- Апостолико-Джанкарло усиливает эту идею через массивы `skip` и `suff`, чтобы не сравнивать повторно уже известные совпавшие блоки.

Для зачёта по этому пункту обычно важно объяснить именно две эвристики сдвига:

```text
плохой символ
хороший суффикс
```

## 18. Что сказать на зачёте

Короткий ответ:

> Бойер–Мур прикладывает образец к тексту и сравнивает символы справа налево. При несовпадении он считает сдвиг по правилу плохого символа: совместить плохой символ текста с его последним вхождением в образце, либо сдвинуть образец за него. Также считает сдвиг по правилу хорошего суффикса: уже совпавший суффикс образца совместить с другой его копией в образце, а если такой нет — с максимальным префиксом образца, являющимся суффиксом этого совпавшего куска. Итоговый сдвиг — максимум из двух правил.

Если спрашивают про оптимизации:

> Для плохого символа можно хранить не просто `last[c]`, а таблицу `R[c][j]`: последнее вхождение символа `c` левее текущей позиции `j`, это даёт более сильный сдвиг. Для хорошего суффикса строят функцию `N`, а по ней таблицы `L` и `small_l`: `L` ищет правое внутреннее вхождение хорошего суффикса, а `small_l` — максимальный префикс образца, совпадающий с хвостом хорошего суффикса. После полного совпадения сдвигаются на `m - small_l[1]`. Правило Галиля и алгоритм Апостолико-Джанкарло дополнительно не пересравнивают уже проверенные совпавшие куски текста.
