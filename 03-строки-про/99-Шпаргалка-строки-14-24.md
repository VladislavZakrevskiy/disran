# Шпаргалка: строки, вопросы 14–24

## 14. Наивный поиск

Перебираем старт `s = 0..n-m`, сравниваем `P[j]` с `T[s+j]`.

```text
Время: O(nm)
Память: O(1)
```

---

## 15. Z-функция

`z[i]` — LCP строки `S` и суффикса `S[i..]`.

Линейный алгоритм держит правый Z-блок `[l,r]`.

Если `i <= r`:

```text
z[i] = min(r-i+1, z[i-l])
```

потом расширяем.

Поиск `P` в `T`:

```text
S = P + '#' + T
z[i] >= |P| → вхождение
```

```text
Время: O(n+m)
```

---

## 16. КМП

`pi[i]` — длина наибольшего собственного префикса `S[0..i]`, являющегося суффиксом.

При mismatch:

```text
q = pi[q-1]
```

а не начинаем заново.

Классический поиск:

```text
Время: O(n+m)
Память: O(m)
```

Построение `pi` из `z`:

```text
for i:
  for j = z[i]-1 downto 0 while pi[i+j]==0:
      pi[i+j]=j+1
```

Каждая ячейка пишется один раз → `O(n)`.

КМП реального времени: строим автомат `go[state][char]`, потом каждый символ текста — один переход.

---

## 17. Бойер–Мур

Сравнивает справа налево.

При mismatch на `j`:

```text
bad character shift = совместить плохой символ текста с последним таким символом в P
 good suffix shift = совместить уже совпавший суффикс с другой копией в P или с префиксом P
```

Берём:

```text
shift = max(bad, good)
```

---

## 18. Апостолико–Джанкарло

Это Бойер–Мур + память о совпавших кусках.

- Сдвиги как в Бойере–Муре.
- `skip[pos]` хранит длину уже известного совпадения, заканчивающегося в позиции текста.
- `suff[i]` по образцу говорит, можно ли этот известный блок применить к текущему месту.

Повторные сравнения заменяются прыжками.

```text
Время: O(n+m)
```

---

## 19. Ахо–Корасик

Строим:

1. trie образцов;
2. suffix links;
3. output links / списки ответов.

При чтении текста автомат переходит по `go[v][c]`.

```text
Время: O(sum |Pi| + |T| + answers)
```

Джокеры:

```text
P = ab?cd?e
pieces: ab offset 0, cd offset 3, e offset 6
```

Ищем pieces через AC. Для найденного куска:

```text
start = pos - offset
cnt[start]++
```

Если `cnt[start] == number_of_pieces`, позиция подходит.

## 20. Суффиксное дерево

Compact trie всех суффиксов `S$`.

- Рёбра хранят подстроки через индексы `[l,r]`.
- Поиск `P`: пройти по дереву за `O(|P|)`.
- Листья под найденной точкой — позиции вхождений.

Наивное построение: вставляем все суффиксы → `O(n^2)`.

Неявное дерево: без `$`, некоторые суффиксы заканчиваются внутри рёбер.

Обобщённое дерево: несколько строк с разными терминаторами.

---

## 21. Укконен

Строит суффиксное дерево онлайн за `O(n)`.

Ключи:

- `globalEnd`: все листья продлеваются автоматически;
- `activeNode, activeEdge, activeLength`: активная точка;
- `remainder`: сколько суффиксов осталось обработать;
- suffix links: перейти от `xα` к `α`;
- skip/count: прыгать по рёбрам по длинам;
- Rule 3: если символ уже есть, фаза заканчивается.

Линейность: листьев `O(n)`, внутренних вершин `O(n)`, переходов по ссылкам и skip/count суммарно `O(n)`.

---

## 22. Приложения суффиксного дерева

- Поиск `P` в `S`: `O(|P| + occ)`.
- Набор запросов: построить дерево один раз, искать каждый запрос.
- База текстов: generalized suffix tree, листья помечены документами.
- LCS двух строк: самая глубокая вершина с листьями двух цветов.
- LCS многих строк: самая глубокая вершина со всеми цветами.
- Число вхождений подстроки: число листьев в поддереве.
- Длиннейшая повторяющаяся подстрока: самая глубокая внутренняя вершина.
- Число различных подстрок: сумма длин рёбер.

## 23. Суффиксный массив

`SA` — позиции суффиксов в лексикографическом порядке.

Пример `banana$`:

```text
SA = [6,5,3,1,0,4,2]
```

Через suffix tree: DFS листьев в лексикографическом порядке.

Поиск `P`: бинарный поиск по суффиксам.

```text
Просто: O(|P| log n + occ)
С LCP: можно лучше
Память: O(n)
```

---

## 24. Суффиксный массив через циклические строки

Добавляем `$`.

Сортируем циклические сдвиги по длинам:

```text
1, 2, 4, 8, ...
```

На шаге `k` используем пары:

```text
(c[i], c[i + 2^k])
```

Цифровая сортировка:

1. `pn[i] = p[i] - 2^k`;
2. counting sort по `c[pn[i]]`;
3. пересчитать классы.

```text
Время: O(n log n)
Память: O(n)
```
