# 18. Алгоритм Апостолико–Джанкарло и доказательство линейности

## 1. Зачем нужен Апостолико–Джанкарло

Алгоритм Бойера–Мура очень быстрый на практике, но без дополнительных правил может повторно сравнивать одни и те же участки текста.

Особенно неприятный пример:

```text
P = aaaaa
T = aaaaaaaaaaaaaaaaa
```

При многих выравниваниях Бойер–Мур справа налево снова и снова сравнивает почти один и тот же набор символов.

**Апостолико–Джанкарло** — это модификация Бойера–Мура, которая говорит:

> Если мы уже знаем, что некоторый кусок текста совпадает с суффиксом образца, не надо сравнивать этот кусок повторно.

То есть это Бойер–Мур + память о уже совпавших кусках.

---

## 2. Что остаётся от Бойера–Мура

Важно:

```text
Сдвиги в Апостолико–Джанкарло такие же, как в Бойере–Муре.
```

То есть используются:

1. правило плохого символа;
2. правило хорошего суффикса.

Отличие не в том, **куда сдвигаемся**, а в том, **как проверяем текущее выравнивание**.

Бойер–Мур:

```text
каждый раз сравнивает символы справа налево явно
```

Апостолико–Джанкарло:

```text
часть сравнений пропускает, если этот кусок текста уже был проверен раньше
```

---

## 3. Какие таблицы нужны

Пусть:

```text
P — образец длины m
T — текст длины n
```

Нужны три идеи.

### 3.1 Таблицы Бойера–Мура

Как раньше:

```text
bad character table
 good suffix table
```

Они нужны для сдвигов.

### 3.2 Массив `suff` для образца

`suff[i]` — длина наибольшего суффикса всего образца `P`, который заканчивается в позиции `i` образца.

Иначе:

```text
suff[i] = max k, такой что P[i-k+1 .. i] = P[m-k .. m-1]
```

Пример:

```text
P = ababa
```

Суффиксы всего образца:

```text
a, ba, aba, baba, ababa
```

Для позиции `i = 2` подстрока, заканчивающаяся в `2`:

```text
P[0..2] = aba
```

Она равна суффиксу всего образца `aba`, значит:

```text
suff[2] = 3
```

### 3.3 Массив `skip` для текста

`skip[pos]` хранит, сколько символов текста, заканчивающихся в позиции `pos`, уже известно как совпадающих с суффиксом образца.

То есть:

```text
skip[pos] = k
```

означает:

```text
T[pos-k+1 .. pos] уже проверено и равно P[m-k .. m-1]
```

---

## 4. Идея проверки одного выравнивания

Пусть образец приложен с началом `s`.

Как в Бойере–Муре, идём справа налево:

```text
j = m - 1
```

Обычный Бойер–Мур сделал бы:

```text
while j >= 0 and P[j] == T[s+j]:
    j--
```

Апостолико–Джанкарло перед сравнением смотрит:

```text
k = skip[s+j]
```

Если `k > 0`, значит кусок текста, заканчивающийся в `s+j`, уже был проверен раньше.

Но этот кусок можно безопасно перепрыгнуть только если он действительно соответствует нужному куску образца в текущем выравнивании. Для этого используется `suff[j]`.

Упрощённо:

```text
если skip[s+j] <= suff[j], можно перепрыгнуть skip[s+j] символов;
иначе перепрыгиваем только гарантированную часть suff[j]
или сразу понимаем, где будет несовпадение.
```

Главное для зачёта:

> `skip` хранит информацию о тексте, `suff` проверяет, можно ли применить эту информацию к текущей позиции образца.

---

## 5. Схема алгоритма по шагам

Для каждого выравнивания `s`:

1. Ставим `j = m - 1`.
2. Идём справа налево.
3. Если `skip[s+j] = 0`, сравниваем `P[j]` и `T[s+j]` явно.
4. Если совпало, уменьшаем `j`.
5. Если `skip[s+j] > 0`, используем `suff[j]` и перепрыгиваем уже известный блок.
6. Когда нашли несовпадение или полное совпадение, запоминаем:

```text
skip[s + m - 1] = сколько символов совпало в конце текущего окна
```

7. Сдвигаем окно по правилам Бойера–Мура.

---

## 6. Маленький пример: зачем нужен `skip`

Пусть:

```text
P = aaaaab
T = aaaaaaaaaaaaab
```

При одном выравнивании мы могли проверить справа налево, что последние несколько `a` совпали.

Например, известно:

```text
T[5..9] = aaaaa
```

и это совпадает с суффиксом некоторой части образца.

Когда окно сдвинется, этот же фрагмент текста может снова оказаться под образцом.

Бойер–Мур начал бы снова сравнивать:

```text
a == a
a == a
a == a
...
```

Апостолико–Джанкарло смотрит в `skip` и говорит:

```text
этот блок уже проверяли, можно не тратить сравнения повторно
```

---

## 7. Более конкретная схема с переменными

Обозначения:

```text
s — начало текущего окна в тексте
j — текущая позиция в образце, сравниваем справа налево
matched = m - 1 - j — сколько символов справа уже совпало
```

Псевдокод уровня зачёта:

```text
preprocess BM tables
preprocess suff for pattern
skip[0..n-1] = 0

s = 0
while s <= n - m:
    j = m - 1

    while j >= 0:
        k = skip[s + j]

        if k > 0 and k <= suff[j]:
            # уже известный блок подходит текущему месту образца
            j -= k
            continue

        if P[j] == T[s + j]:
            j -= 1
        else:
            break

    matched = m - 1 - j
    skip[s + m - 1] = matched

    if j < 0:
        output s
        s += BM_shift_after_full_match
    else:
        s += BM_shift_after_mismatch(j)
```

Это не промышленная реализация всех тонких случаев, но это правильная экзаменационная картина:

```text
BM отвечает за сдвиг,
skip+suff отвечают за пропуск повторных сравнений.
```

## 8. Почему алгоритм линейный

Ключевая мысль доказательства:

> Явное сравнение символа текста делается только тогда, когда о нём ещё нет достаточной информации в `skip`. После сравнения информация запоминается и позже используется для пропуска.

Можно рассуждать так.

### 8.1 Что происходит при явных сравнениях

Если алгоритм явно сравнил символы и получил совпадение, то часть совпавшего суффикса записывается в `skip`.

Значит, при следующем попадании в этот участок текста алгоритм не будет обязан сравнивать его заново.

### 8.2 Что происходит при несовпадении

Если найдено несовпадение, окно сдвигается вправо по правилам Бойера–Мура.

Окно никогда не двигается влево.

### 8.3 Почему нет квадратичности

В плохом Бойере–Муре один и тот же длинный блок текста мог сравниваться много раз.

В Апостолико–Джанкарло этот блок после первого сравнения становится известным через `skip`.

Значит, повторная работа заменяется прыжком.

Итоговая оценка:

```text
O(n + m)
```

Память:

```text
O(n + m)
```

где `O(n)` — массив `skip`, `O(m)` — таблицы образца.

---

## 9. Связь с правилом Галиля

Правило Галиля для Бойера–Мура тоже говорит: если часть текста уже гарантированно совпадает, её можно не сравнивать.

Апостолико–Джанкарло можно воспринимать как более общий вариант этой идеи:

```text
Галиль: запоминаем один защищённый интервал.
Апостолико–Джанкарло: храним информацию о совпавших суффиксах в skip.
```

---

## 10. Что точно надо сказать на зачёте

Готовый ответ:

> Алгоритм Апостолико–Джанкарло является модификацией Бойера–Мура. Он использует те же сдвиги по правилам плохого символа и хорошего суффикса, но ускоряет проверку окна. Для этого хранится массив `skip`: для позиции текста он показывает длину уже известного совпадения, заканчивающегося в этой позиции. Также для образца считается массив `suff`, который говорит, насколько такой известный суффикс применим к текущей позиции образца. При сравнении справа налево алгоритм не сравнивает повторно уже известные блоки, а перепрыгивает их. Линейность следует из того, что каждый явно проверенный блок затем запоминается, а повторные проверки заменяются переходами; окно двигается только вправо. Поэтому время поиска `O(n + m)`.
