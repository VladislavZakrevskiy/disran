# 2. Красно-чёрное дерево

Тут главное **сначала идеально рассказать свойства**, потому что все случаи из них следуют.

Говоришь:

> Красно-чёрное дерево — это бинарное дерево поиска, в котором каждой вершине дополнительно присвоен красный или чёрный цвет.

## Свойства

Я бы называл именно так:

1. Каждая вершина красная или чёрная.
2. Корень чёрный.
3. `NIL`-листья считаются чёрными.
4. У красной вершины дети только чёрные.

То есть:

```
RED
├── BLACK
└── BLACK
```

Красный-красный запрещён.

5. Из каждой вершины до любого `NIL` проходит одинаковое число чёрных вершин.

Это называется **black height**.

---

# Зачем эти правила?

Очень хороший момент для защиты:

> Они не требуют такого строгого баланса, как AVL, но гарантируют, что самый длинный путь не более чем в два раза длиннее самого короткого.

Поэтому:

\[ h \le 2\log_2(n+1) \]

И операции:

\[ O(\log n) \]

---

# Вставка в КЧ-дерево

Главная идея:

> Новую вершину всегда вставляем красной.

Почему не чёрной?

Если вставить чёрную:

```
black height
```

на одном пути сразу увеличится.

Если вставить красную — количество чёрных вершин не изменится.

---

## После вставки всё хорошо, если родитель чёрный

```
     BLACK
       |
      RED
```

Ничего делать не надо.

---

## Проблема возникает только такая

```
       RED parent
        |
       RED new
```

То есть:

> красная вершина имеет красного родителя.

Теперь смотрим на:

- `P` — parent;
- `G` — grandparent;
- `U` — uncle.

```
          G
         / \
        P   U
       /
      X
```

---

# КЧ вставка: случай 1 — дядя красный

```
          G(B)
         /    \
      P(R)    U(R)
      /
    X(R)
```

Есть конфликт:

```
P(R) - X(R)
```

Но дядя тоже красный.

Делаем:

```
P → BLACK
U → BLACK
G → RED
```

Получаем:

```
          G(R)
         /    \
      P(B)    U(B)
      /
    X(R)
```

И продолжаем проверку **от G вверх**.

На защите:

> Если отец и дядя красные, поворот не нужен. Перекрашиваем отца и дядю в чёрный, деда в красный и переносим проблему на уровень выше.

Если дед стал корнем:

```
root → BLACK
```

---

# Случай 2 — дядя чёрный

Вот здесь нужны повороты.

Причём опять есть:

```
прямая линия
```

или

```
зигзаг
```

---

# LL

```
          G(B)
         /
       P(R)
       /
     X(R)
```

Дядя справа чёрный.

Что делаем:

```
P → BLACK
G → RED

rotateRight(G)
```

Получаем:

```
        P(B)
       /   \
    X(R)   G(R)
```

---

# RR

Симметрично:

```
    G(B)
       \
       P(R)
          \
          X(R)
```

Делаем:

```
P → BLACK
G → RED

rotateLeft(G)
```

---

# LR

```
        G
       /
      P
       \
        X
```

Сначала превращаем зигзаг в линию:

```
rotateLeft(P)
```

Получается LL.

А потом применяем LL.

---

# RL

```
    G
     \
      P
     /
    X
```

Сначала:

```
rotateRight(P)
```

Получаем RR.

Потом обычный случай RR.

---

# Как рассказать вставку КЧ вообще без зубрёжки

Вот этот алгоритм прям выучи:

```
Вставил красную вершину.

Родитель чёрный
→ всё.

Родитель красный:
    смотрим на дядю.

    Дядя красный
    → перекраска
    → идём к деду.

    Дядя чёрный:
        зигзаг
        → поворот родителя
        → превращаем в линию.

        линия
        → поворот деда
        → отец BLACK
        → дед RED.

В конце root = BLACK.
```

Вот это очень хороший ответ.

# Удаление из КЧ-дерева

Это обычно самая страшная часть.

Но логика довольно понятная.

Главная проблема:

> При удалении красной вершины ничего не нарушается. Настоящая проблема возникает, когда мы удаляем чёрную вершину, потому что один путь теряет одну чёрную вершину.

Это представляют как состояние:

# "двойная чёрная" вершина

`x` — вершина, на которой сейчас находится нехватка одного чёрного цвета.

---

# Сначала простые случаи

## Удаляем красную

```
... RED ...
```

Просто удаляем.

Потому что black height не изменился.

---

## Удаляем чёрную с красным ребёнком

Например:

```
    BLACK
       \
       RED
```

Заменяем вершину ребёнком:

```
    BLACK
```

То есть красного ребёнка красим в чёрный.

Готово.

---

# Сложный случай

Удалили чёрную вершину с чёрным/NIL ребёнком.

Получаем:

```
DOUBLE BLACK x
```

Теперь смотрим на **брата `S`**.

Например `x` — левый ребёнок:

```
        P
       / \
      X   S
```

Я дальше буду рассматривать именно эту ориентацию.

Для правой всё зеркально.

---

# Случай 1 — брат красный

```
        P(B)
       /    \
    X(BB)   S(R)
            / \
          ... ...
```

Красный брат означает, что его дети обязательно чёрные.

Делаем:

```
S → BLACK
P → RED
rotateLeft(P)
```

После этого:

> Мы не решили double black, но получили ситуацию, в которой брат X уже чёрный.

То есть этот случай просто преобразует дерево в один из следующих случаев.

### Запомнить

**Красный брат → крутим родителя в сторону X.**

Если `X` слева:

```
rotateLeft(P)
```

---

# Теперь брат чёрный

```
        P
       / \
    X(BB) S(B)
```

Смотрим на детей брата.

И удобно назвать их:

```
near  = ближний к X
far   = дальний от X
```

Если `X` слева:

```
        P
       / \
      X   S
         / \
      near far
```

---

# Случай 2 — брат чёрный, оба ребёнка брата чёрные

```
        P(?)
       /    \
    X(BB)   S(B)
           /   \
         B       B
```

Красим брата в красный:

```
S → RED
```

Почему?

Мы как будто убираем одну чёрную вершину и с правого пути тоже.

Теперь баланс относительно этих двух путей восстановлен.

Но нехватка чёрного перемещается к `P`.

```
double black → parent
```

Если родитель был красным — его просто красим в чёрный и заканчиваем.

Если чёрным — проблема идёт выше.

На защите:

> Если брат чёрный и оба его ребёнка чёрные, красим брата в красный и переносим дополнительную черноту на родителя.

---

# Случай 3 — брат чёрный, ближний ребёнок красный, дальний чёрный

```
        P
       / \
    X(BB) S(B)
           / \
         R     B
        near  far
```

Это "неудобная" конфигурация.

Мы хотим получить следующий случай.

Делаем поворот вокруг брата:

```
near → BLACK
S    → RED

rotateRight(S)
```

если `X` слева.

Получаем ситуацию, где:

```
far child = RED
```

То есть свели случай 3 к случаю 4.

---

# Случай 4 — брат чёрный, дальний ребёнок красный

Самый финальный случай:

```
        P(?)
       /    \
    X(BB)   S(B)
           /   \
         ?      R
               far
```

Что делаем:

```
S.color = P.color
P → BLACK
far → BLACK

rotateLeft(P)
```

И всё.

Double black исчезает.

---

# КЧ удаление — суперкороткая схема

Выучи это:

```
Удалили RED
→ ничего.

Удалили BLACK + RED child
→ child красим BLACK.

Удалили BLACK
→ double black X.

Смотрим на S = sibling.

1. S RED
   → перекраска + поворот parent
   → получаем BLACK sibling.

2. S BLACK, оба ребёнка BLACK
   → S красный
   → double black поднимаем к parent.

3. S BLACK,
   near RED,
   far BLACK
   → поворот sibling
   → превращаем в случай 4.

4. S BLACK,
   far RED
   → перекраска + поворот parent
   → finished.
```

---

# Самая важная картинка для удаления

Представляй всегда:

```
             P
            / \
       X(BB)   S
               / \
           near   far
```

И спрашиваешь себя:

### Какого цвета S?

```
RED
→ поворот parent
```

Если BLACK:

### Какие дети?

```
BLACK BLACK
→ sibling RED
→ проблема наверх
```

```
near RED
far BLACK
→ повернуть sibling
```

```
far RED
→ повернуть parent
→ конец
```

Это реально почти весь алгоритм.

# Как связать AVL и КЧ на защите

Если преподаватель спросит разницу:

### AVL

Очень строго балансирует высоты:

\[ |h_L-h_R|\le1 \]

Поэтому поиск очень быстрый.

Но вставки/удаления могут требовать больше балансировок.

---

### Красно-чёрное

Баланс слабее.

```
самый длинный путь
≤
2 × самый короткий
```

Зато изменения структуры происходят сравнительно редко.

Поэтому КЧ-деревья часто используются для динамических `map/set`.

Например концептуально:

```
std::map
std::set
```

обычно реализуются сбалансированным деревом поиска, часто красно-чёрным.

---

# Если тебе дали дерево и говорят "что делать?"

Для **AVL**:

```
1. Найди вершину BF = ±2.

2. Посмотри, куда она перевешивает.

       +2 → LEFT
       -2 → RIGHT

3. Посмотри, куда перевешивает ребёнок.

LEFT + LEFT   → LL → right rotate
RIGHT + RIGHT → RR → left rotate

LEFT + RIGHT  → LR → double
RIGHT + LEFT  → RL → double
```

---

Для **КЧ после вставки**:

```
новая X красная
      ↓
parent BLACK?
  ├─ да → конец
  │
  └─ нет
      ↓
    uncle RED?
      ├─ да → recolor → вверх
      │
      └─ нет
          ↓
        zigzag?
          ├─ да → rotate parent
          ↓
        rotate grandparent
        + recolor
```

---

Для **КЧ после удаления**:

```
              sibling
                 ↓

             RED?
            /    \
          yes     no
           ↓       ↓
    rotate parent  дети?
                   ↓

             BLACK + BLACK
                   ↓
              recolor S
              X = parent

             near RED
             far BLACK
                   ↓
             rotate sibling

             far RED
                   ↓
             rotate parent
                   ↓
                  END
```

## Что я бы прям выучил перед защитой

**AVL:**

> "Разбалансированную вершину определяем по balance factor. Есть четыре случая: LL и RR исправляются одним поворотом, LR и RL — двумя. LL — правый поворот, RR — левый, LR — левый у сына и правый у родителя, RL — наоборот."

**КЧ вставка:**

> "Новую вершину вставляем красной. Если отец чёрный — всё хорошо. Если отец красный, смотрим на дядю. Красный дядя — перекраска и поднимаемся вверх. Чёрный дядя — повороты: зигзаг сначала превращаем в линию поворотом родителя, затем поворачиваем деда и перекрашиваем."

**КЧ удаление:**

> "Проблема возникает при удалении чёрной вершины — появляется double black. Смотрим на брата. Красный брат преобразуется поворотом в случай с чёрным братом. Если брат чёрный и оба его ребёнка чёрные — красим брата в красный и переносим проблему вверх. Если ближний ребёнок красный, а дальний чёрный — поворачиваем брата. Если дальний красный — выполняем финальный поворот родителя с перекраской."

Если вот эти **три абзаца + картинки случаев** уверенно рассказываешь, тему AVL/КЧ на защите ты закрываешь очень прилично.
