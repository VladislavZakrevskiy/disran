# PATRICIA trie — конспект “по шагам”

> PATRICIA = Practical Algorithm To Retrieve Information Coded in Alphanumeric. Это сжатый двоичный trie, где вместо хранения длинных цепочек мы запоминаем, **по какому биту надо сравнивать ключи**.

Главная мысль:

```text
Обычный trie идёт по каждому символу/биту.
Compact trie сжимает цепочки.
PATRICIA идёт только по битам, где реально есть развилка.
```

Для экзамена удобно думать так:

```text
PATRICIA trie = compact trie для битовых строк + индексы проверяемых битов.
```

---

## 1. Зачем вообще PATRICIA

Пусть ключи — строки или числа. Их можно представить как последовательности битов.

Например, для простоты ключи длиной 4 бита:

```text
A = 0000
B = 0010
C = 1010
D = 1011
```

Обычный двоичный trie смотрел бы каждый бит:

```text
бит 0 → бит 1 → бит 2 → бит 3
```

Но если на каких-то уровнях нет выбора, это пустая трата узлов.

PATRICIA оставляет только места, где ключи реально различаются.

---

## 2. Главное понятие: discriminating bit

**Discriminating bit** — первый бит, в котором два ключа отличаются.

Пример:

```text
0000
0010
```

Сравним по позициям:

```text
позиция: 0 1 2 3
A:       0 0 0 0
B:       0 0 1 0
```

Первое отличие на позиции `2`.

Значит, чтобы различить `0000` и `0010`, достаточно проверить бит `2`:

```text
bit[2] = 0 → 0000
bit[2] = 1 → 0010
```

---

## 3. Как выглядит узел PATRICIA

Узел обычно хранит:

```text
bitIndex — номер бита, который надо проверить
left/right — переходы по 0/1
key — ключ, если это лист или representative key
```

Упрощённо:

```cpp
struct Node {
    int bit;       // какой бит проверяем
    string key;    // ключ в листе или опорный ключ
    Node* left;    // если bit = 0
    Node* right;   // если bit = 1
};
```

В учебной версии можно считать:

```text
внутренний узел = вопрос “какой бит на позиции i?”
лист = реальный ключ
```

---

## 4. Мини-пример на ключах 4 бита

Ключи:

```text
A = 0000
B = 0010
C = 1010
D = 1011
```

### Сначала сравним все ключи

Главная развилка между `A/B` и `C/D`:

```text
A = 0xxx
B = 0xxx
C = 1xxx
D = 1xxx
```

Первый бит `bit[0]` делит ключи на две группы:

```text
bit[0] = 0 → A, B
bit[0] = 1 → C, D
```

Теперь внутри левой группы:

```text
A = 0000
B = 0010
```

Они отличаются в `bit[2]`.

Внутри правой группы:

```text
C = 1010
D = 1011
```

Они отличаются в `bit[3]`.

### Дерево

```text
              [bit 0]
             /       \
          0 /         \ 1
           /           \
       [bit 2]       [bit 3]
       /     \        /     \
      A       B      C       D
   0000    0010   1010    1011
```

Это и есть идея PATRICIA:

```text
не проверяем bit[1], потому что он нигде не нужен для развилки.
```

---

## 5. Поиск в PATRICIA по шагам

Используем дерево:

```text
              [bit 0]
             /       \
          0 /         \ 1
           /           \
       [bit 2]       [bit 3]
       /     \        /     \
      A       B      C       D
   0000    0010   1010    1011
```

Ищем ключ:

```text
1011
```

Шаги:

```text
1. В корне проверяем bit[0].
   У 1011 bit[0] = 1.
   Идём вправо.

2. В узле [bit 3] проверяем bit[3].
   У 1011 bit[3] = 1.
   Идём вправо.

3. Пришли в лист D = 1011.

4. Сравниваем искомый ключ с ключом в листе.
   1011 == 1011.
   Ответ: ключ найден.
```

Почему в конце надо сравнивать ключ целиком?

Потому что PATRICIA проверяет не все биты, а только развилки. Можно прийти в “ближайший” лист, но ключ может не совпасть.

---

## 6. Пример поиска отсутствующего ключа

Ищем:

```text
1001
```

Дерево то же.

Шаги:

```text
1. bit[0] у 1001 = 1 → идём вправо.
2. bit[3] у 1001 = 1 → идём вправо.
3. Пришли в лист D = 1011.
4. Сравниваем полностью:
   1001 != 1011.
5. Ответ: ключа нет.
```

Очень важная идея:

```text
Маршрут привёл нас к кандидату.
Но наличие ключа подтверждается только полным сравнением с листом.
```

---

## 7. Вставка в PATRICIA: общий план

Вставка делается так:

```text
1. Ищем ключ как обычно.
2. Если пришли в лист с таким же ключом → ключ уже есть.
3. Если пришли в другой ключ → находим первый бит, где новый ключ отличается от найденного.
4. Вставляем новый внутренний узел с этим bitIndex.
5. Развешиваем два ключа по 0/1 на этом бите.
```

Это похоже на compact trie:

```text
нашли место, где строки разошлись → вставили развилку
```

---

## 8. Вставка по шагам: добавляем `0010`

Начинаем с одного ключа:

```text
A = 0000
```

Дерево:

```text
A: 0000
```

Вставляем:

```text
B = 0010
```

### Шаг 1. Ищем B

Пока есть только один лист:

```text
пришли в A = 0000
```

### Шаг 2. Сравниваем A и B

```text
A = 0000
B = 0010
```

Первое отличие:

```text
позиция 2
```

### Шаг 3. Создаём внутренний узел `[bit 2]`

```text
bit[2] у A = 0
bit[2] у B = 1
```

Получаем:

```text
        [bit 2]
        /     \
       0       1
      A        B
    0000     0010
```

---

## 9. Вставка по шагам: добавляем `1010`

Было:

```text
        [bit 2]
        /     \
       A       B
    0000     0010
```

Вставляем:

```text
C = 1010
```

### Шаг 1. Ищем C по текущему дереву

```text
1. В корне проверяем bit[2].
2. У 1010 bit[2] = 1.
3. Идём вправо.
4. Пришли в B = 0010.
```

### Шаг 2. Сравниваем C с найденным B

```text
B = 0010
C = 1010
```

Первое отличие:

```text
позиция 0
```

### Шаг 3. Новый bitIndex = 0

Новый узел должен стоять **выше**, чем `[bit 2]`, потому что `0 < 2`.

Почему?

```text
В PATRICIA по пути bitIndex должны возрастать.
Сначала проверяем более ранние биты.
```

После вставки:

```text
              [bit 0]
             /       \
            0         1
           /           \
       [bit 2]          C
       /     \        1010
      A       B
   0000    0010
```

---

## 10. Вставка по шагам: добавляем `1011`

Было:

```text
              [bit 0]
             /       \
            0         1
           /           \
       [bit 2]          C
       /     \        1010
      A       B
   0000    0010
```

Вставляем:

```text
D = 1011
```

### Шаг 1. Ищем D

```text
1. bit[0] у 1011 = 1 → вправо.
2. Пришли в C = 1010.
```

### Шаг 2. Сравниваем D и C

```text
C = 1010
D = 1011
```

Первое отличие:

```text
позиция 3
```

### Шаг 3. Создаём узел `[bit 3]`

```text
bit[3] у C = 0
bit[3] у D = 1
```

После:

```text
              [bit 0]
             /       \
            0         1
           /           \
       [bit 2]       [bit 3]
       /     \        /     \
      A       B      C       D
   0000    0010   1010    1011
```

---

## 11. Важный инвариант: bitIndex возрастает вниз

На любом пути от корня к листу номера битов должны идти по возрастанию.

Пример корректно:

```text
bit 0 → bit 2 → leaf
bit 0 → bit 3 → leaf
```

Некорректно:

```text
bit 2 → bit 0 → leaf
```

Почему это важно?

Потому что если сначала проверили более поздний бит, а потом более ранний, дерево перестаёт быть нормальным сжатым представлением префиксного дерева.

---

## 12. Как понять, куда вставлять новый внутренний узел

После того как нашли первый различающийся бит `d`, надо найти место, где:

```text
parent.bit < d < current.bit
```

Или если `d` меньше, чем бит корня, новый узел становится новым корнем.

### На пальцах

Есть путь:

```text
bit 0 → bit 5 → bit 8 → leaf
```

Новый различающийся бит:

```text
d = 6
```

Значит, новый узел надо вставить между `bit 5` и `bit 8`:

```text
bit 0 → bit 5 → bit 6 → bit 8 → leaf
```

Если `d = 3`:

```text
bit 0 → bit 3 → bit 5 → bit 8 → leaf
```

Если `d = -` такого не бывает, но если `d = 0`, а корень тоже bit 0 — это значит, что по этому биту уже есть развилка, надо смотреть дальше.

## 13. Обратные ссылки и самоссылки

В учебных картинках выше листья нарисованы как обычные листья:

```text
[bit 0] → [bit 2] → A
```

Но в классической PATRICIA часто делают немного иначе:

```text
указатель может вести не только вниз,
но и назад — к уже встреченному узлу.
```

Такие указатели называют:

```text
обратная ссылка = ссылка на предка или на уже пройденный узел
самоссылка = ссылка узла на самого себя
```

Зачем так делают?

```text
1. Чтобы не хранить отдельные leaf-узлы в привычном виде.
2. Чтобы остановить поиск, когда bitIndex перестал возрастать.
3. Чтобы удобно хранить representative key прямо в узлах.
```

Главное правило:

```text
Обычное движение вниз:
    следующий bitIndex больше текущего.

Остановка поиска:
    следующий bitIndex меньше или равен текущему.
```

То есть если мы были в узле `bit 2`, а переход ведёт в `bit 0` или снова в `bit 2`, это уже не спуск глубже. Это сигнал:

```text
дальше идти не надо,
мы пришли к кандидату,
сравни ключ целиком.
```

### Пример с одним ключом

Пусть в дереве только один ключ:

```text
A = 0000
```

В версии с самоссылкой это можно представить так:

```text
        [A, bit 0]
        /       \
       /         \
    self        self
```

Оба перехода могут вести обратно в сам узел. Это выглядит странно, но идея простая:

```text
ключ один,
реальной развилки ещё нет,
поэтому любой поиск заканчивается на A как на кандидате.
```

Ищем `0000`:

```text
1. Стартуем в A.
2. Переход ведёт обратно в A.
3. bitIndex не увеличился.
4. Останавливаемся.
5. Сравниваем 0000 с A.
6. Ключ найден.
```

Ищем `0010`:

```text
1. Стартуем в A.
2. Переход опять приводит к A.
3. Останавливаемся.
4. Сравниваем 0010 с 0000.
5. Ключа нет.
```

То есть самоссылка не означает “бесконечно ходить по кругу”. Она означает:

```text
это конец поиска,
проверь найденный кандидат.
```

### Пример после вставки двух ключей

Ключи:

```text
A = 0000
B = 0010
```

Они различаются в `bit[2]`, поэтому обычная учебная картинка такая:

```text
        [bit 2]
        /     \
       A       B
```

В классической реализации можно хранить ключи прямо в узлах, а “листья” заменить обратными ссылками:

```text
        [A, bit 2]
        /        \
       /          \
    to A         [B, bit 2]
                 /       \
              to A       to B
```

Смысл не в точной форме картинки, а в правиле остановки:

```text
если следующий bitIndex не больше текущего,
это обратная ссылка,
поиск закончен.
```

Для `A = 0000`:

```text
1. В узле bit 2 проверяем bit[2].
2. У A bit[2] = 0.
3. Идём по левой ссылке.
4. Она ведёт обратно к кандидату A.
5. Сравниваем полностью: 0000 == 0000.
```

Для `B = 0010`:

```text
1. В узле bit 2 проверяем bit[2].
2. У B bit[2] = 1.
3. Идём вправо.
4. Следующая ссылка приводит к кандидату B.
5. Сравниваем полностью: 0010 == 0010.
```

Для отсутствующего `0110`:

```text
1. bit[2] у 0110 = 1 → идём к кандидату B.
2. Сравниваем полностью:
   0110 != 0010.
3. Ответ: ключа нет.
```

### Как строятся обратные ссылки

Главная идея:

```text
в обычной картинке ветка ведёт в лист;
в реализации с обратными ссылками эта же ветка ведёт к узлу,
где хранится ключ этого листа.
```

То есть мы сначала можем думать обычным способом:

```text
        [bit 2]
        /     \
       A       B
```

А потом заменить листья ссылками на узлы-кандидаты:

```text
ветка 0 должна приводить к A
ветка 1 должна приводить к B
```

Отсюда правило:

```text
Для каждой ветки нового узла:
    1. Смотрим, какой ключ должен лежать в этой ветке.
    2. Если для этого ключа уже есть узел в дереве — ставим ссылку на него.
    3. Если это новый ключ и он лежит в самом новом узле — ставим самоссылку.
```

### Когда появляется самоссылка

Самоссылка появляется, когда узел сам хранит ключ, который должен быть результатом поиска по одной из его веток.

Например, вставляем первый ключ:

```text
A = 0000
```

Других узлов нет, поэтому единственный кандидат — сам `A`:

```text
        [A]
        / \
      to A to A
```

Обе ссылки можно считать самоссылками:

```text
куда бы поиск ни пошёл,
он должен остановиться на A как на кандидате.
```

Теперь вставим `B = 0010`.

Обычное дерево:

```text
        [bit 2]
        /     \
       A       B
```

Если новый узел хранит ключ `B`, то ветка для `B` может вести в сам новый узел:

```text
        [B, bit 2]
        /        \
       /          \
    to A         self
```

Почему так?

```text
bit[2] у A = 0 → левая ветка должна давать кандидата A
bit[2] у B = 1 → правая ветка должна давать кандидата B
```

Кандидат `A` уже был в дереве, поэтому ставим ссылку на старый узел `A`.
Кандидат `B` хранится прямо в новом узле, поэтому правая ссылка может быть самоссылкой.

Если реализация хранит ключ `A` в новом узле, картинка будет зеркально по смыслу:

```text
        [A, bit 2]
        /        \
       /          \
    self         to B
```

Обе версии выражают одну и ту же идею:

```text
ветка 0 приводит к A;
ветка 1 приводит к B.
```

### Как строить при вставке нового ключа

План такой:

```text
1. Ищем новый ключ как обычно.
2. Приходим к старому кандидату oldKey.
3. Находим первый различающийся бит d между key и oldKey.
4. Создаём новый узел с bitIndex = d.
5. Смотрим bit[d] у key и oldKey.
6. В одну ветку кладём ссылку на новый ключ.
7. В другую ветку кладём ссылку на старого кандидата или на старое поддерево.
```

Пример:

```text
oldKey = A = 0000
key    = B = 0010
```

Первый различающийся бит:

```text
d = 2
```

Смотрим значения:

```text
bit[2] у A = 0
bit[2] у B = 1
```

Значит:

```text
left  → A
right → B
```

Если новый узел хранит `B`, получаем:

```text
        [B, bit 2]
        /        \
       /          \
    to A         self
```

В другой реализации ключ `B` могли бы хранить в отдельном узле, тогда справа была бы не самоссылка, а обратная ссылка на этот узел. Для понимания алгоритма важно не это, а соответствие:

```text
левая ветка даёт кандидата A;
правая ветка даёт кандидата B.
```

Если потом вставляем `C = 1010`, поиск может сначала привести к кандидату `B = 0010`.

Сравниваем:

```text
B = 0010
C = 1010
```

Первый различающийся бит:

```text
d = 0
```

Смотрим:

```text
bit[0] у B = 0
bit[0] у C = 1
```

Значит новый узел `bit 0` должен стоять выше старого `bit 2`:

```text
              [C, bit 0]
              /        \
             /          \
       old subtree      self
       for A and B       C
```

Почему слева не просто `to B`?

Потому что по ветке `bit[0] = 0` лежит не один ключ, а целое старое поддерево:

```text
A = 0000
B = 0010
```

Поэтому ссылка вниз остаётся обычной ссылкой на старое поддерево `[bit 2]`.
А ветка `bit[0] = 1` пока содержит только новый ключ `C`, поэтому она может быть самоссылкой.

### Как решить, ссылка назад или обычная ссылка вниз

Смотри на `bitIndex`.

```text
Если ребёнок имеет bitIndex больше текущего —
это обычная ссылка вниз.

Если ребёнок имеет bitIndex меньше или равен текущему —
это обратная ссылка или самоссылка.
```

При построении это означает:

```text
ветка ведёт к группе из нескольких ключей → ссылка вниз на поддерево;
ветка ведёт к одному ключу-кандидату → обратная ссылка на узел с этим ключом;
ветка ведёт к ключу, который хранится в текущем узле → самоссылка.
```

Коротко:

```text
ссылка вниз = там ещё надо различать несколько ключей;
обратная ссылка = там уже один кандидат;
самоссылка = этот кандидат хранится прямо здесь.
```

### Пример с обратной ссылкой к предку

Возьмём дерево:

```text
A = 0000
B = 0010
C = 1010
D = 1011
```

Учебная форма:

```text
              [bit 0]
             /       \
          0 /         \ 1
           /           \
       [bit 2]       [bit 3]
       /     \        /     \
      A       B      C       D
```

В реализации с обратными ссылками часть переходов из нижних узлов может возвращать к узлам, где лежат ключи-кандидаты:

```text
              [A, bit 0]
             /          \
            /            \
       [B, bit 2]      [C, bit 3]
       /       \        /       \
    to A      to B   to C      to D
```

Здесь `to A`, `to B`, `to C`, `to D` — это не новые узлы-листья, а ссылки к узлам с соответствующими ключами.

Как понять, что это конец?

```text
по пути bitIndex должен расти:
bit 0 → bit 2 — нормально
bit 0 → bit 3 — нормально

а переход bit 2 → bit 0 или bit 2 → bit 2
уже не является спуском вниз
```

Поиск `1011`:

```text
1. В корне bit 0:
   у 1011 bit[0] = 1 → вправо.

2. Попали в узел bit 3:
   у 1011 bit[3] = 1 → вправо.

3. Правая ссылка ведёт к кандидату D.
   Дальше bitIndex не растёт, значит поиск остановлен.

4. Сравниваем полностью:
   1011 == 1011.
   Ключ найден.
```

Поиск `1001`:

```text
1. bit[0] = 1 → вправо.
2. bit[3] = 1 → к кандидату D.
3. Сравниваем полностью:
   1001 != 1011.
4. Ключа нет.
```

### Как это запомнить

```text
Обычный учебный PATRICIA:
    внутренний узел → внутренний узел → лист

Классический PATRICIA с обратными ссылками:
    идём, пока bitIndex растёт;
    как только bitIndex не растёт — это кандидат;
    обязательно сравниваем ключ целиком.
```

Самоссылка — частный случай обратной ссылки:

```text
обратная ссылка может вести к предку;
самоссылка ведёт в тот же самый узел.
```

Для экзамена достаточно фразы:

```text
В PATRICIA обратные ссылки и самоссылки используются как способ обозначить конец поиска:
если следующий индекс бита не больше текущего, мы не спускаемся дальше,
а считаем найденный узел кандидатом и сравниваем полный ключ.
```

## 14. Удаление в PATRICIA

Удаление концептуально похоже на compact trie:

```text
1. Найти ключ.
2. Если ключа нет — ничего не делать.
3. Удалить лист.
4. Если родитель после удаления имеет только одного ребёнка, сжать его.
```

Но в классических реализациях PATRICIA с обратными ссылками/самоссылками удаление выглядит технически сложнее. Для экзамена чаще достаточно понимать идею:

```text
Удаление убирает лист и лишний проверочный узел, если развилки больше нет.
```

---

## 15. Удаление по шагам

Дерево:

```text
              [bit 0]
             /       \
            0         1
           /           \
       [bit 2]       [bit 3]
       /     \        /     \
      A       B      C       D
   0000    0010   1010    1011
```

Удаляем:

```text
D = 1011
```

### Шаг 1. Находим D

```text
bit[0] = 1 → вправо
bit[3] = 1 → вправо
пришли в D
сравнили полностью → D найден
```

### Шаг 2. Удаляем лист D

Узел `[bit 3]` теперь имеет только одного живого ребёнка `C`:

```text
       [bit 3]
       /     \
      C      D  ← удаляем
```

После удаления D узел `[bit 3]` больше не нужен: он не делает выбор между двумя ключами.

### Шаг 3. Сжимаем

Правый ребёнок корня теперь просто `C`:

```text
              [bit 0]
             /       \
            0         1
           /           \
       [bit 2]          C
       /     \        1010
      A       B
   0000    0010
```

## 16. PATRICIA на строках

Строки можно рассматривать как битовые последовательности.

Например:

```text
cat
car
```

В ASCII эти строки отличаются где-то в битах символов `t` и `r`. PATRICIA может хранить индекс конкретного бита, где они различаются.

На уровне идеи:

```text
cat и car имеют общий префикс ca
развилка возникает внутри третьего символа
```

Поэтому PATRICIA часто объясняют как:

```text
радикс-дерево / compact trie, где переходы задаются битовыми позициями
```

## 17. Чем PATRICIA отличается от Compact Trie

| Вопрос | Compact Trie | PATRICIA |
|---|---|---|
| Что сжимается? | Цепочки символов | Цепочки битов |
| Что хранит внутренний узел? | Метку ребра-строку | Номер проверяемого бита |
| Как идём вниз? | Сравниваем кусок строки | Смотрим бит 0/1 |
| Что в листьях? | Обычно terminal/слово | Полный ключ |
| Зачем сравнение в листе? | Обычно тоже полезно | Обязательно, чтобы подтвердить ключ |

## 18. Сложность операций

Пусть:

```text
L = длина ключа в битах
n = число ключей
```

| Операция | Время | Почему |
|---|---:|---|
| Поиск | O(L) в худшем случае | надо смотреть биты и сравнить ключ в листе |
| Вставка | O(L) | поиск + поиск первого различающегося бита |
| Удаление | O(L) | поиск + локальное сжатие |
| Память | O(n) узлов | обычно около одного листа на ключ и внутренних узлов для развилок |

Практический смысл:

```text
PATRICIA экономит память по сравнению с обычным trie, потому что не хранит узлы без ветвлений.
```

## 19. Типичная ошибка: думать, что PATRICIA проверяет все биты

Нет.

Она проверяет только важные биты.

Например:

```text
0000
0010
```

Не надо проверять:

```text
bit[0], bit[1], bit[3]
```

Достаточно:

```text
bit[2]
```

## 20. Типичная ошибка: забыть финальное сравнение ключа

Дерево:

```text
              [bit 0]
             /       \
          ...        [bit 3]
                     /     \
                  1010    1011
```

Ищем:

```text
1001
```

По битам можно прийти в `1011`, но это не значит, что `1001` есть.

Правильный поиск:

```text
1. Спустились в лист.
2. Сравнили весь ключ.
3. Только после этого ответили “есть/нет”.
```

## 21. Псевдокод поиска

```cpp
Node* search(Node* root, Key key) {
    Node* v = root;

    while (!v->isLeaf()) {
        int b = getBit(key, v->bit);
        if (b == 0) v = v->left;
        else        v = v->right;
    }

    if (v->key == key) return v;
    return nullptr;
}
```

На пальцах:

```text
Пока не лист:
    спроси нужный бит;
    0 → налево;
    1 → направо.
В листе сравни ключ целиком.
```

## 22. Псевдокод вставки на уровне идеи

```cpp
void insert(Key key) {
    Node* leaf = searchCandidate(root, key);

    if (leaf->key == key) return;

    int d = firstDifferentBit(key, leaf->key);

    // найти место, где номера битов переходят через d
    Node* parent = nullptr;
    Node* cur = root;
    while (!cur->isLeaf() && cur->bit < d) {
        parent = cur;
        if (getBit(key, cur->bit) == 0) cur = cur->left;
        else cur = cur->right;
    }

    Node* newLeaf = new Leaf(key);
    Node* newInternal = new Internal(d);

    if (getBit(key, d) == 0) {
        newInternal->left = newLeaf;
        newInternal->right = cur;
    } else {
        newInternal->left = cur;
        newInternal->right = newLeaf;
    }

    attach(parent, cur, newInternal);
}
```

Это не промышленный код, а учебная схема. Главное — понять два шага:

```text
найти первый различающийся бит
вставить проверку этого бита в правильное место по возрастанию bitIndex
```

## 23. Шпаргалка к экзамену

```text
PATRICIA trie — это сжатый двоичный trie.
Внутренний узел хранит номер бита, по которому надо ветвиться.
Лист хранит полный ключ.
```

Поиск:

```text
идём по проверяемым битам до листа;
в листе сравниваем полный ключ.
```

Вставка:

```text
ищем кандидата;
если ключ другой — находим первый различающийся бит;
создаём новый внутренний узел для этого бита;
развешиваем старый и новый ключ по 0/1.
```

Удаление:

```text
удаляем лист;
если проверочный узел больше не разделяет два ключа — сжимаем его.
```

Сложность:

```text
O(L), где L — длина ключа в битах.
Память O(n), потому что нет длинных цепочек без ветвлений.
```
