Главная мысль:

```text
Красно-чёрное дерево = обычное BST + цвета, которые не дают дереву превратиться в палку.
```

Вставка почти всегда чинит нарушение:

```text
красный родитель + красный ребёнок
```

Удаление почти всегда чинит нарушение:

```text
на одном пути стало на 1 чёрный узел меньше
```

## Глава 5. Основы красно-чёрного дерева

### 5.1 История

В 1972 году немецкий информатик **Рудольф Байер** изобрёл структуру, которую назвал «симметричное бинарное B-дерево». В 1978 году **Леонидас Гуибас** и **Роберт Седжвик** переосмыслили эту идею, раскрасив узлы в красный и чёрный цвета — так родилось **красно-чёрное дерево** (Red-Black Tree).

Сегодня это, пожалуй, **самая практически важная** сбалансированная структура данных:
- **C++**: `std::map`, `std::set`, `std::multimap`, `std::multiset`
- **Java**: `TreeMap`, `TreeSet`
- **Linux**: планировщик CFS, управление виртуальной памятью (`mm_struct`)
- **.NET**: `SortedDictionary`, `SortedSet`

Почему именно красно-чёрное, а не AVL? Потому что при модификациях (вставка, удаление) оно требует **меньше поворотов** — максимум 2 при вставке и максимум 3 при удалении. Для библиотек общего назначения это важнее, чем чуть лучший баланс AVL.

### 5.2 Пять свойств

> **Красно-чёрное дерево** — это бинарное дерево поиска, в котором каждый узел окрашен в красный или чёрный цвет, и выполняются **пять свойств:**

| # | Свойство | Что означает |
|---|----------|-------------|
| 1 | Каждый узел — **красный** или **чёрный** | Цвет — это 1 бит информации |
| 2 | **Корень** — чёрный | Если после операции корень красный — просто перекрашиваем |
| 3 | Все **листья (NIL)** — чёрные | NIL — фиктивные «пустые» узлы, не хранят данных |
| 4 | У **красного** узла оба ребёнка **чёрные** | Нет двух красных подряд (на любом пути от корня к листу) |
| 5 | Для каждого узла все пути от него до листьев-потомков содержат **одинаковое число чёрных узлов** | Это число называется **чёрной высотой** |

**Свойство 4** можно сформулировать иначе: родитель красного узла всегда чёрный.

**Свойство 5** — ключевое. Оно гарантирует, что дерево не может сильно перекоситься.

### 5.3 Чёрная высота (Black Height)

**Чёрная высота** узла `v` — это число чёрных узлов на любом пути от `v` (не считая сам `v`) до листа NIL.

Обозначение: `bh(v)`

Примеры:
- Чёрная высота NIL-листа = 0
- Если корень чёрный, и оба его ребёнка — NIL, то `bh(root) = 1`

### 5.4 Доказательство: высота ≤ 2·log₂(n+1)

**Лемма:** Поддерево с корнем в узле `v` содержит не менее **2^bh(v) − 1** внутренних узлов.

*Доказательство* (по индукции по высоте):
- **База:** `v` = NIL → bh = 0, узлов = 0 = 2⁰ − 1 ✓
- **Шаг:** У `v` есть дети. Каждый ребёнок имеет чёрную высоту ≥ bh(v) − 1 (если ребёнок чёрный, ровно bh(v)−1; если красный, то bh(v)). По индукции каждое поддерево содержит ≥ 2^(bh(v)−1) − 1 узлов. Итого:
  ```
  n(v) ≥ 2·(2^(bh(v)−1) − 1) + 1 = 2^bh(v) − 1  ✓
  ```

**Следствие:** По свойству 4, на любом пути длины h от корня до листа не менее половины узлов чёрные (красные не могут идти подряд). Значит, `bh(root) ≥ h/2`, и:

```
n ≥ 2^(h/2) − 1
n + 1 ≥ 2^(h/2)
h ≤ 2·log₂(n + 1)
```

> **Высота красно-чёрного дерева не превышает 2·log₂(n+1)**

Для сравнения: AVL гарантирует ≤ 1.44·log₂(n). Красно-чёрное дерево менее строго сбалансировано, но всё равно O(log n).

### 5.5 Sentinel-узел (NIL)

На практике вместо `nullptr` для пустых ссылок используют один общий **sentinel-узел** — фиктивный чёрный узел:

```cpp
struct Node {
    int key;
    bool red;       // true = красный, false = чёрный
    Node* left;
    Node* right;
    Node* parent;   // указатель на родителя — нужен для балансировки!
};

Node* NIL;  // глобальный sentinel

void init() {
    NIL = new Node();
    NIL->red = false;  // NIL всегда чёрный (свойство 3)
    NIL->left = NIL->right = NIL->parent = NIL;
}
```

Зачем sentinel?
- Не нужно проверять `nullptr` — все листья указывают на один и тот же объект `NIL`
- Код балансировки становится проще (нет особых случаев для пустых указателей)
- `NIL->red == false` — свойство 3 выполняется автоматически

### 5.6 Связь с 2-3-4 деревьями

Красно-чёрное дерево — это **изоморфное представление** 2-3-4 дерева (B-дерева порядка 4):

```
2-3-4 узел с 1 ключом  ↔  один чёрный узел
2-3-4 узел с 2 ключами ↔  чёрный узел + один красный ребёнок
2-3-4 узел с 3 ключами ↔  чёрный узел + два красных ребёнка
```

Эта связь объясняет, **почему свойства именно такие** — они гарантируют корректное представление 2-3-4 дерева. Если тебе легче думать в терминах 2-3-4 деревьев, держи это в голове.

## Глава 6. Вставка в красно-чёрное дерево

### 6.1 Базовая идея

1. Вставляем узел как в обычное BST
2. Красим новый узел в **красный** цвет
3. Исправляем нарушения свойств

**Почему красный?** Красный узел не меняет чёрную высоту ни одного пути (свойство 5 не нарушается). Может нарушиться только свойство 4 (два красных подряд) или свойство 2 (если вставили в пустое дерево — корень красный). Это проще исправить.

### 6.2 Какие свойства могут нарушиться?

| Свойство | Нарушается? | Когда |
|----------|-------------|-------|
| 1 | Нет | Мы явно красим узел |
| 2 | Может | Если дерево было пустым (новый узел — корень) |
| 3 | Нет | NIL-листья не меняются |
| 4 | Может | Если родитель нового узла тоже красный |
| 5 | Нет | Новый узел красный → чёрная высота не изменилась |

### 6.3 Фиксация: три случая

Обозначения:
- **z** — вставленный (или «проблемный») узел (красный)
- **p** — родитель z
- **g** — дедушка z (родитель p)
- **u** — дядя z (брат p, другой ребёнок g)

Фиксация нужна, только когда `p` — красный (иначе свойство 4 не нарушено).

Если `p` красный, то `g` обязательно существует и он **чёрный** (до вставки дерево было корректным, два красных подряд было нельзя).

---

**Случай 1: Дядя красный** → перекраска

```
        g (B)                g (R) ← новый «проблемный»
       / \                  / \
     p (R) u (R)    →    p (B) u (B)
    /                    /
  z (R)                z (R)
```

- Перекрашиваем p и u в чёрный
- Перекрашиваем g в красный
- Теперь g может нарушать свойство 4 со своим родителем → **повторяем** процедуру для g (z = g)
- Поворотов нет — только перекраска

---

**Случай 2: Дядя чёрный, z — «внутренний» ребёнок** → поворот к случаю 3

«Внутренний» означает: z — правый ребёнок левого p, или z — левый ребёнок правого p.

```
      g (B)              g (B)
     / \                / \
   p (R) u (B)   →   z (R) u (B)
    \                /
    z (R)          p (R)
```

- Поворачиваем p (левый поворот, если z — правый ребёнок p)
- Теперь z и p поменялись ролями, но ситуация стала **случаем 3**

---

**Случай 3: Дядя чёрный, z — «внешний» ребёнок** → поворот + перекраска

«Внешний» означает: z — левый ребёнок левого p, или z — правый ребёнок правого p.

```
        g (B)              p (B)
       / \               /   \
     p (R) u (B)  →   z (R)   g (R)
    /                          \
  z (R)                        u (B)
```

- Поворачиваем g (правый поворот, если p — левый ребёнок g)
- Перекрашиваем p в чёрный, g в красный
- **Готово!** Все свойства восстановлены

### 6.4 Все случаи симметричны

Выше описаны случаи, когда `p` — **левый** ребёнок `g`. Если `p` — **правый** ребёнок, всё зеркально (меняем «лево» на «право»).

### 6.5 Итого по вставке

| Действие | Случай 1 | Случай 2 | Случай 3 |
|----------|---------|---------|---------|
| Перекраска | Да | Нет | Да |
| Поворот | Нет | 1 | 1 |
| Переход | Повторяем для g | → Случай 3 | Конец |

**Максимум поворотов при вставке: 2** (случай 2 → случай 3).
**Максимум перекрасок: O(log n)** (случай 1 может повторяться вверх по дереву).

### 6.6 Код вставки

```cpp
void insert(Node*& root, int key) {
    // 1. Обычная вставка BST
    Node* z = new Node();
    z->key = key;
    z->red = true;
    z->left = z->right = NIL;

    Node* y = NIL;
    Node* x = root;
    while (x != NIL) {
        y = x;
        if (key < x->key) x = x->left;
        else if (key > x->key) x = x->right;
        else { delete z; return; } // ключ уже есть
    }
    z->parent = y;
    if (y == NIL) root = z;
    else if (key < y->key) y->left = z;
    else y->right = z;

    // 2. Фиксация
    insert_fixup(root, z);
}

void insert_fixup(Node*& root, Node* z) {
    while (z->parent->red) {
        if (z->parent == z->parent->parent->left) {
            Node* u = z->parent->parent->right; // дядя
            if (u->red) {
                // Случай 1: дядя красный
                z->parent->red = false;
                u->red = false;
                z->parent->parent->red = true;
                z = z->parent->parent;
            } else {
                if (z == z->parent->right) {
                    // Случай 2: z — правый ребёнок → поворот к случаю 3
                    z = z->parent;
                    rotate_left(root, z);
                }
                // Случай 3: z — левый ребёнок
                z->parent->red = false;
                z->parent->parent->red = true;
                rotate_right(root, z->parent->parent);
            }
        } else {
            // Симметрично (parent — правый ребёнок)
            Node* u = z->parent->parent->left;
            if (u->red) {
                z->parent->red = false;
                u->red = false;
                z->parent->parent->red = true;
                z = z->parent->parent;
            } else {
                if (z == z->parent->left) {
                    z = z->parent;
                    rotate_right(root, z);
                }
                z->parent->red = false;
                z->parent->parent->red = true;
                rotate_left(root, z->parent->parent);
            }
        }
    }
    root->red = false; // свойство 2
}
```

Повороты с поддержкой parent-указателей:

```cpp
void rotate_left(Node*& root, Node* x) {
    Node* y = x->right;
    x->right = y->left;
    if (y->left != NIL) y->left->parent = x;
    y->parent = x->parent;
    if (x->parent == NIL) root = y;
    else if (x == x->parent->left) x->parent->left = y;
    else x->parent->right = y;
    y->left = x;
    x->parent = y;
}

void rotate_right(Node*& root, Node* y) {
    Node* x = y->left;
    y->left = x->right;
    if (x->right != NIL) x->right->parent = y;
    x->parent = y->parent;
    if (y->parent == NIL) root = x;
    else if (y == y->parent->left) y->parent->left = x;
    else y->parent->right = x;
    x->right = y;
    y->parent = x;
}
```

## Глава 7. Удаление из красно-чёрного дерева

Удаление — самая сложная операция. Не паникуй: мы разберём каждый случай.

### 7.1 Базовый план

1. Находим узел `z` с нужным ключом
2. Удаляем его как в обычном BST (используя `transplant` — подмену поддерева)
3. Если удалённый узел (или его заместитель) был **чёрный**, нарушается свойство 5 → нужна фиксация

### 7.2 Проблема «двойного чёрного»

Когда мы удаляем чёрный узел, на одном из путей становится **на 1 чёрный узел меньше**. Концептуально мы представляем, что узел-заместитель получает «дополнительную чёрноту»:
- Если он был красным → просто красим в чёрный. **Готово!**
- Если он был чёрным → он становится «дважды чёрным» (double black) — это нелегальное состояние, которое нужно исправить

### 7.3 Вспомогательная операция: transplant

```cpp
void transplant(Node*& root, Node* u, Node* v) {
    if (u->parent == NIL) root = v;
    else if (u == u->parent->left) u->parent->left = v;
    else u->parent->right = v;
    v->parent = u->parent;
}
```

### 7.4 Код удаления

```cpp
void remove(Node*& root, int key) {
    Node* z = search(root, key);
    if (z == NIL) return;

    Node* y = z;
    bool y_original_red = y->red;
    Node* x;

    if (z->left == NIL) {
        x = z->right;
        transplant(root, z, z->right);
    } else if (z->right == NIL) {
        x = z->left;
        transplant(root, z, z->left);
    } else {
        // Два ребёнка: находим преемника (минимум в правом поддереве)
        y = minimum(z->right);
        y_original_red = y->red;
        x = y->right;

        if (y->parent == z) {
            x->parent = y;  // важно для NIL
        } else {
            transplant(root, y, y->right);
            y->right = z->right;
            y->right->parent = y;
        }
        transplant(root, z, y);
        y->left = z->left;
        y->left->parent = y;
        y->red = z->red;
    }

    delete z;

    if (!y_original_red) {
        delete_fixup(root, x);
    }
}
```

### 7.5 Четыре случая фиксации

Фиксация вызывается для узла `x` — «дважды чёрного». Мы рассматриваем его **брата** `w` (другой ребёнок родителя x).

Ниже случаи для `x` — **левого** ребёнка (правые — симметричны).

---

**Случай 1: Брат `w` — красный**

```
       p (B)                w (B)
      / \                  / \
   x (BB) w (R)    →    p (R)  D
         / \            / \
        C   D        x (BB) C
```

- Перекрашиваем w в чёрный, p в красный
- Левый поворот вокруг p
- Теперь у x новый брат — он **чёрный** → переходим к случаям 2, 3 или 4

---

**Случай 2: Брат `w` — чёрный, оба ребёнка w — чёрные**

```
       p (?)                p (?) ← «поднимаем» проблему
      / \                  / \
   x (BB) w (B)    →    x (B) w (R)
         / \                  / \
       C(B) D(B)           C(B) D(B)
```

- Перекрашиваем w в красный
- «Снимаем» одну чёрноту с x
- Переносим проблему на p: если p был красным → красим в чёрный, **конец**; если чёрным → p становится «дважды чёрным», **повторяем**

---

**Случай 3: Брат `w` — чёрный, ближний ребёнок w — красный, дальний — чёрный**

```
       p (?)                 p (?)
      / \                   / \
   x (BB) w (B)    →    x (BB) C (B)
         / \                      \
       C(R) D(B)                  w (R)
                                    \
                                    D(B)
```

- Перекрашиваем C в чёрный, w в красный
- Правый поворот вокруг w
- Теперь у x новый брат с **красным дальним ребёнком** → **случай 4**

---

**Случай 4: Брат `w` — чёрный, дальний ребёнок w — красный**

```
         p (?)                   w (цвет p)
        / \                     / \
     x (BB) w (B)    →      p (B)  D (B)
           / \              / \
          C   D(R)       x (B) C
```

- w получает цвет p
- p красим в чёрный
- Дальний ребёнок D красим в чёрный
- Левый поворот вокруг p
- **Готово!** Все свойства восстановлены

### 7.6 Переходы между случаями

```
Случай 1 → Случай 2, 3 или 4
Случай 2 → повтор для родителя (или конец)
Случай 3 → Случай 4
Случай 4 → Конец
```

**Максимум поворотов при удалении: 3** (случай 1 → случай 3 → случай 4 = 1 + 1 + 1).

### 7.7 Код фиксации удаления

```cpp
void delete_fixup(Node*& root, Node* x) {
    while (x != root && !x->red) {
        if (x == x->parent->left) {
            Node* w = x->parent->right; // брат

            // Случай 1: брат красный
            if (w->red) {
                w->red = false;
                x->parent->red = true;
                rotate_left(root, x->parent);
                w = x->parent->right;
            }

            // Случай 2: оба ребёнка брата чёрные
            if (!w->left->red && !w->right->red) {
                w->red = true;
                x = x->parent;
            } else {
                // Случай 3: правый ребёнок брата чёрный
                if (!w->right->red) {
                    w->left->red = false;
                    w->red = true;
                    rotate_right(root, w);
                    w = x->parent->right;
                }
                // Случай 4: правый ребёнок брата красный
                w->red = x->parent->red;
                x->parent->red = false;
                w->right->red = false;
                rotate_left(root, x->parent);
                x = root; // выход из цикла
            }
        } else {
            // Симметрично (x — правый ребёнок)
            Node* w = x->parent->left;

            if (w->red) {
                w->red = false;
                x->parent->red = true;
                rotate_right(root, x->parent);
                w = x->parent->left;
            }

            if (!w->right->red && !w->left->red) {
                w->red = true;
                x = x->parent;
            } else {
                if (!w->left->red) {
                    w->right->red = false;
                    w->red = true;
                    rotate_left(root, w);
                    w = x->parent->left;
                }
                w->red = x->parent->red;
                x->parent->red = false;
                w->left->red = false;
                rotate_right(root, x->parent);
                x = root;
            }
        }
    }
    x->red = false;
}
```

## Глава 8. Анализ и практика

### 8.1 Сводка сложностей

| Операция | Сложность | Поворотов | Перекрасок |
|----------|-----------|-----------|------------|
| Поиск | O(log n) | 0 | 0 |
| Вставка | O(log n) | ≤ 2 | O(log n) |
| Удаление | O(log n) | ≤ 3 | O(log n) |

### 8.2 Сравнение AVL и красно-чёрного дерева

| Критерий | AVL | Красно-чёрное |
|----------|-----|---------------|
| Высота | ≤ 1.44·log₂(n) | ≤ 2·log₂(n+1) |
| Поиск | **Быстрее** (дерево ниже) | Чуть медленнее |
| Вставка (поворотов) | ≤ 2 | ≤ 2 |
| Удаление (поворотов) | **O(log n)** | **≤ 3** ✅ |
| Доп. память на узел | 1 int (высота) | 1 bit (цвет) + parent |
| Сложность реализации | Средняя | **Высокая** |
| Типичное применение | БД (много чтений) | STL, ОС (много модификаций) |

**Вывод:**
- Если преобладают **поиски** → AVL (ниже высота = быстрее поиск)
- Если преобладают **вставки/удаления** → красно-чёрное (меньше поворотов)
- На практике разница невелика, и красно-чёрное дерево побеждает из-за **универсальности**

### 8.3 Left-Leaning Red-Black Tree (LLRB)

В 2008 году **Роберт Седжвик** предложил упрощённый вариант — **левостороннее красно-чёрное дерево**. Дополнительное ограничение: красные узлы могут быть только **левыми** ребёнками.

Преимущества:
- Код **значительно проще** (нет симметричных случаев)
- Соответствует 2-3 дереву (а не 2-3-4)
- Реализуется рекурсивно, как AVL

Именно LLRB используется в нашей интерактивной визуализации выше.

Код LLRB вставки (всего ~20 строк):

```cpp
Node* insert(Node* h, int key) {
    if (!h) return new Node(key, RED);

    if (key < h->key)      h->left  = insert(h->left,  key);
    else if (key > h->key)  h->right = insert(h->right, key);
    else return h;

    // Три инварианта LLRB:
    if (isRed(h->right) && !isRed(h->left))       h = rotateLeft(h);
    if (isRed(h->left) && isRed(h->left->left))    h = rotateRight(h);
    if (isRed(h->left) && isRed(h->right))          flipColors(h);

    return h;
}
```

### 8.4 Где используется красно-чёрное дерево

| Где | Что |
|-----|-----|
| **C++ STL** | `std::map`, `std::set`, `std::multimap`, `std::multiset` |
| **Java** | `java.util.TreeMap`, `java.util.TreeSet` |
| **Linux kernel** | CFS (Completely Fair Scheduler) — планировщик процессов |
| **Linux kernel** | `mm_struct` — управление виртуальной памятью |
| **Nginx** | Таймеры событий |
| **Epoll** | Управление файловыми дескрипторами |

# Дополнение A. Повороты “на пальцах”

## A.1 Левый поворот

До:

```text
        x
       / \
      A   y
         / \
        B   C
```

После левого поворота вокруг `x`:

```text
        y
       / \
      x   C
     / \
    A   B
```

Что произошло:

```text
1. y поднялся наверх.
2. x стал левым ребёнком y.
3. B переехало из левого ребёнка y в правого ребёнка x.
```

Почему порядок BST не сломался?

До и после порядок ключей одинаковый:

```text
A < x < B < y < C
```

То есть поворот меняет форму дерева, но не меняет отсортированный порядок.

---

## A.2 Правый поворот

До:

```text
        y
       / \
      x   C
     / \
    A   B
```

После правого поворота вокруг `y`:

```text
        x
       / \
      A   y
         / \
        B   C
```

Порядок тоже сохраняется:

```text
A < x < B < y < C
```

# Дополнение B. Вставка: как не утонуть в случаях

## B.1 Что может сломаться после вставки

Новый узел вставляют как в обычное BST и красят в красный.

Почему красный?

```text
Красный узел не увеличивает чёрную высоту.
```

После вставки может сломаться только одно важное правило:

```text
Нельзя иметь два красных подряд.
```

То есть плохая ситуация выглядит так:

```text
    pR
   /
 zR
```

или так:

```text
pR
  \
  zR
```

Где:

```text
z = вставленный/проблемный узел
p = parent(z)
g = grandparent(z)
u = uncle(z), брат p
```

Если `p` чёрный — всё, чинить нечего.

Если `p` красный — начинается fixup.

---

## B.2 Случай 1 вставки: дядя красный

Условие:

```text
p красный
u красный
g чёрный
```

Картинка:

```text
        gB
       /  \
     pR    uR
    /
  zR
```

Что делаем:

```text
p -> чёрный
u -> чёрный
g -> красный
z = g
продолжаем выше
```

После:

```text
        gR
       /  \
     pB    uB
    /
  zR
```

Почему продолжаем выше?

Потому что `g` стал красным. Если у `g` родитель тоже красный, нарушение поднялось наверх.

### Пример по шагам

Вставляем:

```text
10, 5, 15, 1
```

После `10, 5, 15`:

```text
      10B
     /   \
   5R    15R
```

Вставляем `1`:

```text
      10B
     /   \
   5R    15R
  /
1R
```

Обозначения:

```text
z = 1R
p = 5R
g = 10B
u = 15R
```

Дядя красный, значит случай 1.

Перекрашиваем:

```text
      10R
     /   \
   5B    15B
  /
1R
```

Но `10R` — корень. Корень обязан быть чёрным:

```text
      10B
     /   \
   5B    15B
  /
1R
```

Готово.

---

## B.3 Случай 2 вставки: дядя чёрный, треугольник

Условие:

```text
p красный
u чёрный
z стоит “внутри”
```

Левая версия:

```text
      gB
     /  \
   pR    uB
     \
     zR
```

Это форма:

```text
left-right
```

На пальцах:

```text
z не снаружи, а как бы “между” p и g.
```

Что делаем:

```text
левый поворот вокруг p
```

Получаем:

```text
      gB
     /  \
   zR    uB
   /
 pR
```

Теперь это уже случай 3:

```text
left-left
```

Важно:

```text
Случай 2 сам дерево не чинит.
Он только превращает треугольник в линию.
```

## B.4 Случай 3 вставки: дядя чёрный, линия

Условие:

```text

z стоит “снаружи”
```

Левая версия:

```text
        gB
       /  \
     pR    uB
    /
  zR
```

Это форма:

```text

```

Что делаем:

```text

```

После:

```text
       pB
      /  \
    zR    gR
          / \
        NIL uB
```

Готово.

## B.6 Зеркальные случаи вставки

Всё выше было для ситуации, где `p` — левый ребёнок `g`.

Если `p` справа, всё зеркально.

### Right-left

```text
      gB
     /  \
   uB    pR
        /
      zR
```

Это треугольник.

Действие:

```text
правый поворот вокруг p
потом левый поворот вокруг g
```

### Right-right

```text
      gB
     /  \
   uB    pR
           \
           zR
```

Это линия.

Действие:

```text
p -> чёрный
g -> красный
левый поворот вокруг g
```

---

## B.7 Шпаргалка по вставке

```text
Если родитель чёрный:
    готово.

Если родитель красный:
    найти дядю.

Если дядя красный:
    перекраска, проблема вверх.

Если дядя чёрный:
    если треугольник:
        поворот вокруг parent
    теперь линия:
        перекраска parent/grandparent
        поворот вокруг grandparent
```

Таблица:

| Форма | Дядя | Действие |
|------|------|----------|
| любая | красный | `p` и `u` в чёрный, `g` в красный |
| LL | чёрный | right-rotate(`g`) |
| LR | чёрный | left-rotate(`p`), потом right-rotate(`g`) |
| RR | чёрный | left-rotate(`g`) |
| RL | чёрный | right-rotate(`p`), потом left-rotate(`g`) |

# Дополнение D. Удаление “на пальцах”

## D.1 Почему удаление сложнее вставки

При вставке новый узел красный, поэтому чёрная высота не меняется.

При удалении можно удалить чёрный узел.

Если чёрный узел исчез, на одном пути стало на один чёрный меньше.

Это и есть проблема.

---

## D.2 Double black

Если удалили чёрный узел, то его заместитель `x` как будто получает дополнительную чёрноту.

Если `x` был красный:

```text
xR + дополнительная чёрнота = xB
```

То есть просто красим `x` в чёрный и всё.

Если `x` был чёрный или `NIL`, получается:

```text
xBB
```

Это называется double black.

Задача `delete_fixup`:

```text
убрать double black
```

---

## D.3 Четыре случая удаления

Сначала рассматриваем ситуацию, где `x` — левый ребёнок:

```text
       p
      / \
     x   w
```

Где:

```text
x = double black
p = parent(x)
w = sibling(x), брат
```

Если `x` справа — всё зеркально.

---

## D.4 Случай 1 удаления: брат красный

Условие:

```text
w красный
```

Картинка:

```text
        pB
       /  \
     xBB   wR
           / \
          C   D
```

Так как `w` красный, его дети точно чёрные.

Действие:

```text
w -> чёрный
p -> красный
левый поворот вокруг p
```

После:

```text
          wB
         /  \
       pR    D
      /  \
    xBB   C
```

Зачем это?

```text
Мы не решили проблему, но сделали брата x чёрным.
Теперь можно перейти к случаям 2, 3 или 4.
```

---

## D.5 Случай 2 удаления: брат чёрный, оба ребёнка брата чёрные

Условие:

```text
w чёрный
w.left чёрный
w.right чёрный
```

Картинка:

```text
        p?
       /  \
     xBB   wB
           / \
          CБ  DБ
```

Действие:

```text
w -> красный
x теряет double black
проблема поднимается в p
```

После:

```text
        p?
       /  \
      xB   wR
```

Если `p` был красный, он становится чёрным — и всё.

Если `p` был чёрный, он становится новым double black — продолжаем выше.

---

## D.6 Случай 3 удаления: брат чёрный, ближний красный, дальний чёрный

Для `x` слева:


Теперь у `x` новый брат `CБ`, и его дальний ребёнок `wR` красный.

То есть мы получили случай 4.

```text

```

Проблема перешла в `10R`.

Так как `10` красный, красим его в чёрный:

```text
          20B
         /   \
       10B   30B
      /   \
    NIL   15R
```

Готово.

# Дополнение F. Как читать код `delete_fixup`

Код:

```cpp
while (x != root && !x->red) {
    ...
}
x->red = false;
```

В коде нет отдельного цвета `double black`.

Алгоритм подразумевает:

```text
если мы вошли в delete_fixup, то x считается double black
```

Почему выход, если `x` красный?

```text
красный + лишняя чёрнота = обычный чёрный
```

Почему выход, если `x` корень?

```text
у корня нет родителя, относительно которого нужно сохранять баланс
лишнюю чёрноту можно просто снять
```

## F.1 Почему сначала проверяют красного брата

```cpp
if (w->red) {
    ...
}
```

Потому что случаи 2, 3, 4 требуют:

```text
брат чёрный
```

Если брат красный, мы поворотом делаем его чёрным и дальше уже попадаем в 2/3/4.

## F.2 Почему случай 3 проверяется через дальнего ребёнка

Для `x` слева дальний ребёнок — `w.right`.

```cpp
if (!w->right->red) {
    // случай 3
}
```

Мы уже знаем, что не случай 2, то есть хотя бы один ребёнок брата красный.

Если дальний чёрный, значит красный ближний.

Это и есть случай 3.

# Дополнение G. Самая короткая памятка

## Вставка

```text
1. Вставили красный узел.
2. Если родитель чёрный — готово.
3. Если родитель красный:
   - дядя красный -> перекраска, проблема вверх
   - дядя чёрный + треугольник -> поворот parent
   - дядя чёрный + линия -> поворот grandparent, готово
```

## Удаление

```text
1. Удалили красный -> готово.
2. Удалили чёрный -> появился double black.
3. Красный брат -> повернуть, чтобы брат стал чёрным.
4. Чёрный брат + 2 чёрных ребёнка -> перекрасить брата, проблему вверх.
5. Чёрный брат + красный ближний -> превратить в случай 4.
6. Чёрный брат + красный дальний -> финальный поворот.
```

## Главная интуиция

```text
Вставка чинит два красных подряд.
Удаление чинит нехватку одного чёрного узла на пути.
```
