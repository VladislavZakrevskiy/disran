# Глава 0. Введение

## Зачем нам сбалансированные деревья?

Представь, что тебе нужно хранить данные так, чтобы можно было **быстро** выполнять три операции:

- **Поиск** — есть ли элемент с заданным ключом?
- **Вставка** — добавить новый элемент
- **Удаление** — убрать элемент по ключу

Какие варианты у нас есть?

### Массив (отсортированный)

| Операция | Сложность |
|----------|-----------|
| Поиск (бинарный) | O(log n) ✅ |
| Вставка | O(n) ❌ — нужно сдвигать элементы |
| Удаление | O(n) ❌ — нужно сдвигать элементы |

Поиск быстрый, но вставка и удаление — катастрофа.

### Связный список

| Операция | Сложность |
|----------|-----------|
| Поиск | O(n) ❌ — линейный перебор |
| Вставка (в начало) | O(1) ✅ |
| Удаление (по указателю) | O(1) ✅ |

Вставка быстрая, но поиск — катастрофа.

### Хеш-таблица

| Операция | Сложность (в среднем) |
|----------|-----------|
| Поиск | O(1) ✅ |
| Вставка | O(1) ✅ |
| Удаление | O(1) ✅ |

Кажется идеально! Но у хеш-таблицы есть **принципиальные ограничения**:
- Нет порядка: нельзя быстро найти минимум, максимум, следующий/предыдущий элемент
- Нельзя быстро обойти элементы в отсортированном порядке
- Худший случай — O(n)

### Бинарное дерево поиска (BST) — наша надежда

**Бинарное дерево поиска** — структура, где для каждого узла:
- Все ключи в **левом** поддереве **меньше** ключа узла
- Все ключи в **правом** поддереве **больше** ключа узла

В идеале все операции работают за **O(h)**, где h — высота дерева. Если дерево «красивое» (сбалансированное), то h ≈ log₂(n), и мы получаем:

| Операция | Сложность |
|----------|-----------|
| Поиск | O(log n) ✅ |
| Вставка | O(log n) ✅ |
| Удаление | O(log n) ✅ |
| Минимум/Максимум | O(log n) ✅ |
| Обход в порядке | O(n) ✅ |

**Лучшее из обоих миров!** Но есть проблема...

## Проблема вырождения BST

Что произойдёт, если мы вставим элементы **1, 2, 3, 4, 5** в обычное BST?

Дерево превратится в «палку» — связный список! Высота станет h = n, и все операции деградируют до **O(n)**.

Попробуй сам — вставляй числа в дерево и наблюдай, как оно вырождается:

Поиграй с визуализацией выше — это ключевая интуиция всего курса. **Одни и те же данные**, вставленные в разном порядке, дают деревья с **радикально разной** высотой.

---

## Что такое «баланс»?

**Сбалансированное дерево** — это дерево, в котором высота гарантированно остаётся **O(log n)**, независимо от порядка вставок и удалений.

Разные деревья достигают этого разными способами:

| Дерево                | Стратегия баланса                                                |
| --------------------- | ---------------------------------------------------------------- |
| **AVL**               | Разница высот левого и правого поддерева ≤ 1 (строгий инвариант) |
| **Красно-чёрное**     | Раскраска узлов + 5 свойств → высота ≤ 2·log(n)                  |
| **Декартово (Treap)** | Случайные приоритеты → ожидаемая высота O(log n)                 |

---

## Повороты — главный инструмент

Все детерминированные сбалансированные деревья используют **повороты** — локальные перестройки дерева, которые:
- Сохраняют свойство BST (порядок ключей)
- Меняют высоту поддеревьев
- Работают за **O(1)**

Выглядит поворот так:

```
    y           x
   / \   →     / \
  x   C       A   y
 / \             / \
A   B           B   C
```

Это **правый поворот** вокруг y. Обрати внимание: порядок A < x < B < y < C сохраняется!

## Нотация сложности — краткое напоминание

| Запись | Что значит | Пример |
|--------|-----------|--------|
| O(1) | Константа, не зависит от n | Обращение к элементу массива |
| O(log n) | Логарифм — очень медленный рост | Бинарный поиск |
| O(n) | Линейно | Проход по массиву |
| O(n log n) | «Почти линейно» | Хорошая сортировка |
| O(n²) | Квадрат — уже плохо | Вложенный цикл |

Для n = 1 000 000:
- log₂(n) ≈ **20** — практически мгновенно
- n = **1 000 000** — терпимо
- n² = **10¹²** — ты не дождёшься

Именно поэтому разница между O(n) и O(log n) для деревьев — это разница между **«работает»** и **«не работает»**.

## Общий интерфейс сбалансированных деревьев

Все три дерева, которые мы будем изучать, поддерживают один и тот же набор операций:

```
Search(key)    → найти узел с ключом key
Insert(key)    → вставить ключ
Delete(key)    → удалить ключ
Min() / Max()  → минимальный / максимальный ключ
Next(key)      → следующий ключ (successor)
Prev(key)      → предыдущий ключ (predecessor)
```

Все операции работают за **O(log n)** в худшем случае (для AVL и красно-чёрного) или в среднем (для декартова).
