# Trie и Compact Trie — конспект “по шагам”

> Цель: понять, как хранить набор строк так, чтобы поиск слова работал не через сравнение со всеми словами, а через посимвольный спуск по дереву.

Главная мысль:

```text
Trie = дерево по символам.
Один шаг вниз = прочитали один символ строки.
```

Например, хотим хранить слова:

```text
an, ant, all, also, be, bee
```

Обычный список думал бы так:

```text
сравни слово с an
сравни слово с ant
сравни слово с all
...
```

Trie думает так:

```text
первая буква какая?
вторая буква какая?
третья буква какая?
...
```

То есть одинаковые префиксы хранятся один раз.

---

## 1. Что такое Trie

**Trie** — это корневое дерево, где:

- рёбра обычно подписаны символами;
- путь от корня до узла образует некоторую строку;
- узел может быть помечен как `terminal`, если в этом месте заканчивается слово.

Важно:

```text
terminal = здесь заканчивается слово
```

Это нужно, потому что одно слово может быть префиксом другого.

Например, слова:

```text
an
ant
```

Дерево:

```text
(root)
  |
  a
  |
  n*      ← тут заканчивается an
  |
  t*      ← тут заканчивается ant
```

Звёздочка `*` означает `terminal = true`.

Без terminal мы бы не поняли, есть ли слово `an` отдельно, или есть только `ant`.

## 2. Первый пример построения Trie

Пусть надо вставить слова:

```text
to, tea, ten, in, inn
```

### Шаг 1. Вставляем `to`

Идём от корня:

```text
t нет → создаём
из t нет o → создаём
после o ставим terminal
```

Получается:

```text
(root)
  |
  t
  |
  o*
```

### Шаг 2. Вставляем `tea`

Слово `tea`:

```text
t уже есть → идём туда
e нет → создаём
a нет → создаём
ставим terminal на a
```

Теперь:

```text
(root)
  |
  t
 / \
o*  e
     |
     a*
```

Заметь:

```text
буква t общая для to и tea
```

### Шаг 3. Вставляем `ten`

```text
t есть
e есть
n нет → создаём
n terminal
```

```text
(root)
  |
  t
 / \
o*  e
    / \
   a*  n*
```

### Шаг 4. Вставляем `in`

У корня ещё нет ветки `i`:

```text
(root)
 /   \
t     i
/\    |
o* e  n*
  /\
 a* n*
```

### Шаг 5. Вставляем `inn`

```text
i есть
n есть и уже terminal для слова in
ещё один n нет → создаём
последний n terminal
```

Финально:

```text
(root)
 /        \
t          i
/\          \
o* e         n*
  /\          \
 a* n*         n*
```

Слова, которые лежат в дереве:

```text
to, tea, ten, in, inn
```

## 3. Поиск слова в Trie

Идея поиска:

```text
идём по символам строки;
если нужного ребра нет → слова нет;
если строка закончилась → проверяем terminal.
```

### Пример дерева

Берём дерево:

```text
(root)
 /        \
t          i
/\          \
o* e         n*
  /\          \
 a* n*         n*
```

### Поиск `tea`

```text
1. start в root
2. символ 't': у root есть ребёнок t → идём
3. символ 'e': у t есть ребёнок e → идём
4. символ 'a': у e есть ребёнок a → идём
5. строка закончилась
6. узел a terminal? да
Ответ: tea есть
```

В виде маршрута:

```text
root → t → e → a*
```

### Поиск `te`

```text
1. root → t → e
2. строка закончилась
3. узел e terminal? нет
Ответ: te нет
```

Хотя путь `t-e` существует, это только префикс слов `tea` и `ten`, но не отдельное слово.

### Поиск `ted`

```text
1. root → t → e
2. нужен символ d
3. у e нет ребёнка d
Ответ: ted нет
```

### Поиск `in`

```text
root → i → n*
```

Узел `n` terminal, значит `in` есть.

### Поиск `inn`

```text
root → i → n* → n*
```

Последний `n` тоже terminal, значит `inn` есть.

## 4. Вставка слова в Trie

Псевдокод:

```cpp
void insert(Node* root, string s) {
    Node* v = root;
    for (char c : s) {
        if (!v->next.count(c)) {
            v->next[c] = new Node();
        }
        v = v->next[c];
    }
    v->terminal = true;
}
```

### Разбор кода на пальцах

```cpp
Node* v = root;
```

Мы стоим в корне.

```cpp
for (char c : s)
```

Берём буквы слова по одной.

```cpp
if (!v->next.count(c))
    v->next[c] = new Node();
```

Если из текущего узла нет ребра по этой букве — создаём новый узел.

```cpp
v = v->next[c];
```

Переходим по ребру.

```cpp
v->terminal = true;
```

После последней буквы отмечаем, что слово закончилось именно здесь.

## 5. Пошаговая вставка слова `cart`

Пусть уже есть слова:

```text
car, cat
```

Trie:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
```

Вставляем `cart`.

### Шаги

```text
1. c есть → идём
2. a есть → идём
3. r есть → идём
4. слово ещё не закончилось, нужен t
5. из r нет t → создаём
6. t помечаем terminal
```

После:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
|
t*
```

Теперь в дереве есть:

```text
car
cart
cat
```

Очень важный момент:

```text
r остаётся terminal, потому что car всё ещё слово.
```

## 6. Удаление слова из Trie

Удаление сложнее, чем поиск и вставка, потому что нельзя просто стереть весь путь: часть пути может использоваться другими словами.

Правило:

```text
Сначала снимаем terminal.
Потом удаляем снизу вверх только те узлы, которые:
1) не terminal;
2) не имеют детей.
```

### Пример 1. Удаляем `cart` из дерева `car, cart, cat`

До:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
|
t*
```

Удаляем `cart`.

Шаги:

```text
1. Находим путь c-a-r-t.
2. Последний t terminal → снимаем terminal.
3. Этот t теперь не terminal и детей нет → удаляем его.
4. Возвращаемся к r.
5. r terminal? да, потому что car остаётся.
6. Значит r не удаляем.
```

После:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
```

Остались слова:

```text
car, cat
```

### Пример 2. Удаляем `car` из дерева `car, cart, cat`

До:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
|
t*
```

Удаляем `car`.

```text
1. Находим узел r.
2. Снимаем terminal с r.
3. Можно ли удалить r? Нет, у него есть ребёнок t.
```

После:

```text
(root)
  |
  c
  |
  a
 / \
r   t*
|
t*
```

Теперь `car` нет, но `cart` остался.

### Пример 3. Удаляем `cat`

До:

```text
(root)
  |
  c
  |
  a
 / \
r*  t*
```

Удаляем `cat`:

```text
1. Находим c-a-t.
2. Снимаем terminal с t.
3. t не terminal и детей нет → удаляем t.
4. a ещё имеет ребёнка r → a не удаляем.
5. c ещё имеет ребёнка a → c не удаляем.
```

После:

```text
(root)
  |
  c
  |
  a
  |
  r*
```

## 7. Код удаления

```cpp
bool erase(Node* v, const string& s, int pos) {
    if (pos == s.size()) {
        if (!v->terminal) return false; // слова не было
        v->terminal = false;
        return v->next.empty();         // можно ли удалить этот узел
    }

    char c = s[pos];
    if (!v->next.count(c)) return false;

    Node* child = v->next[c];
    bool needDeleteChild = erase(child, s, pos + 1);

    if (needDeleteChild) {
        delete child;
        v->next.erase(c);
    }

    return !v->terminal && v->next.empty();
}
```

### Как читать `return !v->terminal && v->next.empty()`

Это вопрос:

```text
Можно ли удалить текущий узел?
```

Ответ “да”, только если:

```text
тут не заканчивается слово
и
из узла больше никуда не идут рёбра
```

## 8. Типичная структура узла

### Вариант 1. Через массив

Если алфавит маленький, например `a..z`:

```cpp
struct Node {
    Node* next[26];
    bool terminal;
};
```

Плюсы:

```text
быстрый переход по символу: O(1)
```

Минусы:

```text
много памяти: у каждого узла 26 указателей, даже если реально нужен 1
```

### Вариант 2. Через map/unordered_map

```cpp
struct Node {
    unordered_map<char, Node*> next;
    bool terminal = false;
};
```

Плюсы:

```text
памяти меньше, храним только существующие переходы
```

Минусы:

```text
переход по символу чуть дороже
```

## 9. Сложность Trie

Пусть:

```text
m = длина слова
Σ = размер алфавита
```

| Операция | Сложность по времени | Почему |
|---|---:|---|
| Поиск | O(m) | читаем m символов |
| Вставка | O(m) | читаем m символов, иногда создаём узлы |
| Удаление | O(m) | идём вниз и возвращаемся вверх |
| Поиск всех слов с префиксом p | O(|p| + answer) | сначала доходим до p, потом обходим поддерево |

Главное отличие от BST:

```text
BST зависит от числа слов n: O(log n) сравнений строк.
Trie зависит от длины слова m: O(m).
```

Но сравнение строк в BST тоже не бесплатное: одно сравнение может стоить O(m). Поэтому для строк trie часто очень удобен.

## 10. Поиск всех слов с префиксом

Задача:

```text
Даны слова: to, tea, ten, in, inn.
Найти все слова с префиксом te.
```

Trie:

```text
(root)
 /        \
t          i
/\          \
o* e         n*
  /\          \
 a* n*         n*
```

Шаги:

```text
1. Идём по префиксу te:
   root → t → e

2. Дальше запускаем DFS из узла e.

3. Из e есть дети a и n.

4. Путь e-a даёт слово tea.

5. Путь e-n даёт слово ten.
```

Ответ:

```text
tea, ten
```

## 11. Compact Trie

Обычный trie может иметь длинные цепочки узлов с одним ребёнком.

Например, храним одно слово:

```text
algorithm
```

Обычный trie:

```text
root -a- l -g- o -r- i -t- h -m*
```

Это много узлов, хотя выбора нигде нет.

**Compact trie** сжимает цепочки без ветвлений в одно ребро со строковой меткой.

```text
root --"algorithm"--> *
```

Главная мысль:

```text
Обычный trie хранит по одному символу на ребре.
Compact trie хранит строки на рёбрах.
```

---

## 12. Compact Trie на примере

Слова:

```text
bear, bell, bid, bull, buy, sell, stock, stop
```

Обычный trie имел бы много односимвольных узлов.

Compact trie можно представить так:

```text
(root)
├── "b"
│   ├── "e"
│   │   ├── "ar"*
│   │   └── "ll"*
│   ├── "id"*
│   └── "u"
│       ├── "ll"*
│       └── "y"*
└── "s"
    ├── "ell"*
    └── "to"
        ├── "ck"*
        └── "p"*
```

Что тут важно:

```text
Ребро "ar" означает сразу два символа: a потом r.
```

## 13. Поиск в Compact Trie по шагам

Ищем `stock`.

Дерево:

```text
(root)
└── "s"
    ├── "ell"*
    └── "to"
        ├── "ck"*
        └── "p"*
```

Шаги:

```text
1. Слово начинается с s.
   У root есть ребро "s" → совпало.
   Остаток строки: "tock".

2. Из узла после s есть рёбра "ell" и "to".
   Остаток "tock" начинается с "to" → идём по "to".
   Остаток: "ck".

3. Из узла после "sto" есть рёбра "ck" и "p".
   Остаток "ck" совпадает с ребром "ck".
   Остаток пуст.

4. Пришли в terminal-узел.
   Ответ: stock есть.
```

Ищем `stork`.

```text
1. root → "s" совпало, остаток "tork".
2. "to" совпало, остаток "rk".
3. Дальше есть рёбра "ck" и "p".
4. Остаток "rk" не начинается ни с "ck", ни с "p".
Ответ: stork нет.
```

## 14. Вставка в Compact Trie: главный случай — надо разрезать ребро

Самое важное отличие от обычного trie:

```text
При вставке может понадобиться split ребра.
```

### Пример. Было слово `bear`, вставляем `bell`

До:

```text
(root)
└── "bear"*
```

Вставляем `bell`.

Сравниваем ребро `bear` и слово `bell`:

```text
bear
bell
be    ← общий префикс
```

Общий префикс = `be`.

Ребро `bear` надо разрезать:

```text
(root)
└── "be"
    ├── "ar"*   ← остаток старого слова bear
    └── "ll"*   ← остаток нового слова bell
```

### Пример. Было `bear`, `bell`, вставляем `be`

До:

```text
(root)
└── "be"
    ├── "ar"*
    └── "ll"*
```

Вставляем `be`.

```text
1. Ребро "be" полностью совпало.
2. Слово закончилось прямо в этом узле.
3. Просто ставим terminal=true на узле после "be".
```

После:

```text
(root)
└── "be"*
    ├── "ar"*
    └── "ll"*
```

Теперь есть три слова:

```text
be, bear, bell
```

## 15. Ещё один split ребра: вставляем `bid`

Было:

```text
(root)
└── "be"
    ├── "ar"*
    └── "ll"*
```

Вставляем `bid`.

Сравниваем у корня ребро `be` и слово `bid`:

```text
be
bid
b   ← общий префикс
```

Нужно разрезать ребро `be` на:

```text
b + e
```

После вставки:

```text
(root)
└── "b"
    ├── "e"
    │   ├── "ar"*
    │   └── "ll"*
    └── "id"*
```

Смысл:

```text
После первой буквы b есть развилка:
e... для bear/bell
id для bid
```

## 16. Удаление в Compact Trie

Удаление похоже на обычный trie, но после удаления надо **склеивать** узлы, если появилась цепочка без ветвления.

Правило:

```text
После удаления, если узел:
1) не terminal;
2) имеет ровно одного ребёнка;
то его можно склеить с ребёнком.
```

### Пример. Есть `be, bear, bell`, удаляем `bear`

До:

```text
(root)
└── "be"*
    ├── "ar"*
    └── "ll"*
```

Удаляем `bear`:

```text
1. Идём по "be".
2. Остаток "ar".
3. Идём по "ar".
4. Снимаем terminal с узла ar.
5. Узел ar не terminal и детей нет → удаляем ребро "ar".
```

После:

```text
(root)
└── "be"*
    └── "ll"*
```

Склеивать `be` и `ll` нельзя, потому что узел `be` terminal: слово `be` должно остаться.

### Пример. Есть `bear, bell`, удаляем `bear`

До:

```text
(root)
└── "be"
    ├── "ar"*
    └── "ll"*
```

После удаления `bear`:

```text
(root)
└── "be"
    └── "ll"*
```

Узел после `be`:

```text
не terminal
имеет одного ребёнка
```

Можно склеить:

```text
(root)
└── "bell"*
```

## 17. Compact Trie vs Trie

| Вопрос | Trie | Compact Trie |
|---|---|---|
| Что на ребре? | Один символ | Строка |
| Много ли узлов? | Может быть много | Обычно меньше |
| Поиск | По символам | По кускам строк |
| Вставка | Просто создаём узлы | Иногда режем ребро |
| Удаление | Удаляем пустые листья | Ещё и склеиваем рёбра |

## 18. Частые ошибки

### Ошибка 1. Думать, что путь означает слово

Неверно:

```text
если путь существует, слово есть
```

Правильно:

```text
если путь существует И последний узел terminal, слово есть
```

Пример:

```text
есть tea и ten
путь te существует
но слова te может не быть
```

### Ошибка 2. При удалении стереть общий префикс

Если удаляем `car`, нельзя удалить `c-a-r`, если есть `cart`.

### Ошибка 3. В Compact Trie забыть split ребра

Если было:

```text
root --"bear"-->*
```

и вставляем `bell`, нельзя просто добавить второе ребро `bell`, потому что оба начинаются с `be`. Нужно:

```text
root --"be"--> node
node --"ar"-->*
node --"ll"-->*
```

## 19. Шпаргалка к экзамену

### Trie

```text
Trie хранит множество строк как дерево префиксов.
Один уровень = один символ.
Одинаковые префиксы не дублируются.
```

Операции:

```text
search(s): идём по символам, в конце проверяем terminal.
insert(s): идём по символам, создаём недостающие узлы, в конце terminal=true.
erase(s): снимаем terminal, удаляем снизу вверх бесполезные узлы.
```

Сложность:

```text
O(|s|) для поиска/вставки/удаления
```

### Compact Trie

```text
Compact trie = trie, где цепочки без ветвления сжаты в одно ребро.
Ребро хранит строку, а не один символ.
```

Операции:

```text
search: сравниваем строку с метками рёбер.
insert: если частичное совпадение — split ребра.
erase: удаляем слово, потом склеиваем узлы без terminal и с одним ребёнком.
```

Сложность:

```text
O(|s|) по числу просмотренных символов.
Узлов обычно меньше, чем в обычном trie.
```
