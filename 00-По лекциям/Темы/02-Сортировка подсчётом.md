# Сортировка подсчётом

Источники: [Видео 1](https://www.youtube.com/watch?v=8D7AzV0Al8M). Ссылки на конкретные моменты сохранены в разделах.

В текстовых схемах: `✓` — совпадение или подтверждённый результат, `×` — несовпадение, `↑` — рассматриваемое место. Причина каждой отметки объясняется перед схемой.

Перед этой темой: [[00-По лекциям/Темы/01-Асимптотика и нижняя оценка сортировок|Асимптотика и нижняя оценка сортировок]].

## Подсчёт: сначала сортируем просто числа

[Лекция 2, 5:50](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=350s)

Пусть даны $n$ целых неотрицательных чисел, каждое не превосходит $k$. В первом примере лектор ограничивает числа значениями от $0$ до $9$.

Создадим массив `count` из $k+1$ нулей. Индекс ячейки — возможное значение числа, содержимое — сколько раз оно встретилось. Один раз идём по исходному массиву: встретили двойку — увеличили `count[2]`, встретили пятёрку — увеличили `count[5]` и так далее.

### Четыре числа вместо длинного массива

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Возьмём `[2,1,2,0]`. Сумма частот `1+1+2=4` проверяет, что учли все четыре элемента.

**Шаг 1. Нули в счётчиках.**

Мы не ищем место каждого числа в отсортированной последовательности. Вместо этого заведём три ячейки: для ключей 0, 1 и 2. В ячейке с индексом x будем хранить, сколько раз уже встретилось число x.

```text
Вход      2  1  2  0
Ключ x    0  1  2
count     0  0  0
```

**Шаг 2. Читаем 2, затем 1.**

Первое число — 2: увеличиваем count[2] с 0 до 1. Следующее — 1: увеличиваем count[1]. Это два разных счётчика, поэтому после двух прочитанных чисел таблица равна [0,1,1].

```text
После 2    0  0  1
                 ↑
После 1    0  1  1
              ↑
```

**Шаг 3. Читаем вторую 2, затем 0.**

Вторая 2 увеличивает уже ненулевой count[2]: было 1, стало 2. Последний 0 увеличивает count[0]. Получили [1,1,2]; сумма счётчиков равна 4, то есть ни одно входное число не потерялось.

```text
После 2    0  1  2
                 ↑
После 0    1  1  2
           ↑
```

**Шаг 4. Выписываем ключи по возрастанию.**

Теперь идём по индексам счётчиков в порядке 0,1,2. Выписываем 0 один раз, 1 один раз и 2 два раза. Порядок получается из порядка индексов, поэтому сравнивать исходные числа друг с другом не понадобилось.

```text
Ответ    0  1  2  2
         ✓  ✓  ✓  ✓
```

### Почему сложность $O(n+k)$, хотя есть вложенный цикл

[Лекция 2, 10:49](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=649s)

Подсчёт частот требует одного прохода по $n$ элементам. Для выписывания ответа просматриваем $k+1$ счётчиков и внутри каждого повторяем вывод нужное количество раз.

Однако число повторов внутреннего цикла суммарно равно $n$:

$$
\sum_{x=0}^{k}\operatorname{count}[x]=n.
$$

Следовательно, этап восстановления занимает $O(k+n)$, а весь алгоритм —

$$
O(n+k).
$$

Инициализация массива счётчиков также входит в $O(k)$.

Линейным **по числу входных элементов** этот алгоритм становится, когда $k=O(n)$. Большой диапазон при маленьком массиве не подходит: для сотни чисел с огромными возможными значениями нельзя разумно выделить по счётчику на каждое значение.

Здесь $k$ — максимальный ключ; поэтому ячеек $k+1$. Позже, при обсуждении разрядов, лектор использует $k$ как число возможных значений разряда. Разница в обозначениях не должна превращаться в ошибку размера массива.

## Отрицательные числа и узкий диапазон далеко от нуля

[Лекция 2, 14:37](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=877s); [уточнение, 23:07](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1387s)

Отрицательный ключ напрямую не годится в индекс обычного массива. Лектор предлагает сдвиг.

### Сдвиг по шагам

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Учебный вход `[1,-2,0]`; сдвигаем все ключи на одну и ту же величину, затем возвращаем её обратно.

**Шаг 1. Исходные значения.**

Индекс массива не может быть −2. Найдём минимум входа: min=−2. Для каждого числа будем использовать ключ x−min=x+2. Одинаковое прибавление сохраняет порядок: если x<y, то и x+2<y+2.

```text
Вход         1   -2  0
Прибавить    2   2   2
```

**Шаг 2. Сдвинутые ключи.**

Число 1 превратилось в 3, −2 в 0, а 0 в 2. Теперь все ключи неотрицательны и подходят для таблицы частот. После обычной сортировки подсчётом получаем ключи [0,2,3].

```text
До       3  0  2
После    0  2  3
         ✓  ✓  ✓
```

**Шаг 3. Возвращаем исходную шкалу.**

Отсортированы пока сдвинутые значения. Возвращаем прежнюю шкалу: к каждому прибавляем min, то есть вычитаем 2. Получаются −2,0,1 — именно исходные числа, расположенные по возрастанию.

```text
Ответ    -2  0   1
         ✓   ✓   ✓
```

Следующий вопрос студентов расширяет эту идею: что делать с числами $999,1000,1001$? Они положительные, но выделять тысячу счётчиков ради диапазона ширины три бессмысленно.

Общее преобразование одно и то же. Пусть $c$ — минимум, $d$ — максимум. Вместо ключа $x$ используем $x-c$. Тогда диапазон $[c,d]$ переходит в $[0,d-c]$, а размер массива счётчиков равен $d-c+1$.

Порядок сохраняется: вычитание одной и той же константы из всех чисел не меняет отношения между ними. После сортировки прибавляем $c$ обратно. При реализации не обязательно физически переписывать исходный массив: можно вычислять индекс $x-c$ во время подсчёта, а при восстановлении выводить индекс плюс $c$.

Дополнительные проходы не делают алгоритм квадратичным: $2n$, $3n$ и другое фиксированное число проходов дают тот же порядок $O(n)$. Константа поглощается множителем $c$ в определении большого $O$.

### А если числа дробные?

[Лекция 2, 18:42](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1122s); [обсуждение, 26:32](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1592s)

Для произвольных дробных чисел прямое обращение по ключу как по индексу не работает. Если заранее известно, что значения лежат на определённой сетке, можно перевести их в целые ключи: например, половинки умножить на два. Но диапазон новых ключей тоже должен оставаться подходящим.

Лектор предлагает разделять задачи: отдельно подготовить целочисленный ключ, отдельно отсортировать по нему. Не стоит превращать сортировку подсчётом в универсальную функцию, которая сама ищет неизвестные закономерности в произвольных данных.

## Почему для объектов простого выписывания ключей недостаточно

[Лекция 2, 19:19](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1159s); [возврат к алгоритму, 30:17](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1817s)

Реальные элементы часто содержат больше одного числа. В лекции это объект с несколькими полями: строкой, вещественными значениями и целочисленным ключом; в качестве понятного случая обсуждается запись о студенте с именем, фамилией и идентификатором.

Если посчитать только идентификаторы и заново выписать их, остальные поля не появятся в результате. Нам нужно перенести **исходные объекты целиком**, сохранив связь данных с ключом.

Можно было бы после выписывания очередного ключа искать соответствующий объект в исходном массиве. Но тогда для $n$ ключей пришлось бы до $n$ раз проходить массив длины $n$: линейная сортировка превратится в квадратичную. Вместо поиска объектов нужно сразу вычислить их позиции в ответе.

## Полная сортировка подсчётом: частоты → границы → позиции

[Лекция 2, 30:39](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1839s)

### Полный пример с видимым порядком равных ключей

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Берём `[2A,1,2B,0]`. Буквы обозначают разные объекты: `2A` стоял раньше `2B`, значит и в результате должен стоять раньше.

1. Считаем частоты ключей `0,1,2`: `[1,1,2]`.
2. Накопленные суммы равны `[1,2,4]`: столько элементов имеет ключ не больше соответственно `0,1,2`.
3. При индексации с нуля последняя свободная позиция блока ключа $x$ — `count[x]-1`.
4. Читаем вход **справа налево**. Переносим объект целиком и уменьшаем только его счётчик.

Например, после размещения `2B` уменьшается `count[2]`. Границы блоков других ключей не меняются: их места уже выделены. В конце `count[x]` содержит число элементов строго меньше $x$.

**Результат:** `[0,1,2A,2B]`. Порядок `A` перед `B` сохранён.

**Шаг 1. Частоты и правые границы.**

Вход содержит два разных объекта с одним ключом 2. Обозначим их 2A и 2B: буквы не участвуют в сортировке, но позволяют проверить устойчивость. Накопленные суммы [1,2,4] задают правые границы блоков: для 0 выделен индекс 0, для 1 — индекс 1, для двоек — индексы 2 и 3.

```text
Вход       2A  1   2B  0
Ключ       0   1   2
Частоты    1   1   2
Суммы      1   2   4
```

**Шаг 2. Берём 0 справа налево.**

Идём с правого конца входа, поэтому первым берём 0. Его накопленный счётчик равен 1, а индексация результата начинается с нуля: место равно 1−1=0. После записи уменьшаем только count[0]; блок нулей теперь полностью заполнен.

```text
Индекс       0  1  2  3
Результат    0  ·  ·  ·
             ✓
count        0  2  4
             ↑
```

**Шаг 3. Берём 2B справа налево.**

Следующий справа объект — 2B. Последнее свободное место блока двоек равно count[2]−1=4−1=3. Ставим туда весь объект 2B и уменьшаем count[2] до 3. Следующая двойка попадёт на позицию левее.

```text
Индекс       0   1   2   3
Результат    0   ·   ·   2B
                         ✓
count        0   2   3
                     ↑
```

**Шаг 4. Берём 1 справа налево.**

Для ключа 1 граница по-прежнему равна 2: размещение двойки не меняло его счётчик. Поэтому индекс равен 2−1=1. Записываем 1 и уменьшаем count[1]; свободной осталась только позиция 2.

```text
Индекс       0   1   2   3
Результат    0   1   ·   2B
                 ✓
count        0   1   3
                 ↑
```

**Шаг 5. Берём 2A справа налево.**

Остался 2A, который во входе стоял раньше 2B. Теперь count[2]=3, поэтому ставим его по индексу 2. Объекты с равными ключами сохранили порядок A перед B именно благодаря обходу входа справа налево.

```text
Индекс       0   1   2   3
Результат    0   1   2A  2B
                     ✓
count        0   1   2
                     ↑
```

Лекционное объяснение алгоритма: [Лекция 2, 32:06](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=1926s), [Лекция 2, 34:07](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=2047s), [Лекция 2, 41:05](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=2465s).

## Устойчивость и причина обратного прохода

[Лекция 2, 48:20](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=2900s)

**Устойчивая, или стабильная, сортировка сохраняет взаимный порядок объектов с одинаковыми ключами.** Не их абсолютные позиции, а порядок друг относительно друга.

На схеме `2B` обрабатываем раньше и ставим по индексу `3`; `2A` обрабатываем позже и ставим по индексу `2`. В результате `2A` по-прежнему левее `2B`.

Это верно для любого числа равных ключей: их блок заполняется справа налево в том же порядке, в каком справа налево просматривается вход. Поэтому взаимный порядок сохраняется.

Если оставить те же накопленные суммы и уменьшение счётчиков, но идти по исходному массиву слева направо, порядок равных ключей развернётся. Числа всё ещё будут отсортированы, но устойчивость пропадёт.

Студент предлагает альтернативу: изначально хранить число ключей **строго меньше** текущего, идти слева направо и увеличивать указатель. Лектор соглашается, что такой вариант возможен. Обратный проход обязателен именно для разобранной комбинации «правая граница блока + уменьшение счётчика».

### Время и память полной версии

[Лекция 2, 53:06](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=3186s); [память, 1:34:17](https://www.youtube.com/watch?v=8D7AzV0Al8M&t=5657s)

Есть фиксированное число проходов по входу и по массиву счётчиков: найти границы при необходимости, посчитать частоты, накопить суммы, перенести объекты в результат. Поэтому время остаётся $O(n+k)$.

Помимо входного массива нужны `count` из $k+1$ ячеек и `result` из $n$ элементов. Дополнительная память — $O(n+k)$. При оценке в байтах нужно учитывать размер объектов и счётчиков; оценка в элементах не означает, что все объекты занимают один байт.
