## Суффиксный массив без суффиксного дерева

Источник: [лекция 21, 02:16–13:22](https://www.youtube.com/watch?v=SM5QxyPms7g&t=136s).

Пока построение массива зависит от умения строить суффиксное дерево. Теперь лектор убирает эту зависимость: массив можно построить за $O(n\log n)$ с помощью **цифровой сортировки циклических строк**.

### Подготовка: дополнение до степени двойки

К исходной строке приписываем хотя бы один `$`. Затем, если полученная длина не является степенью двойки, дописываем ещё `$` до ближайшей степени двойки. Все эти служебные символы меньше любого исходного символа.

Пусть исходная длина равна $n$, а новая — $N$:

$$
N=2^{\lceil\log_2(n+1)\rceil}.
$$

В коротком учебном примере `aba` превращается в `aba$`, длина равна 4. В общем случае долларов может быть **несколько**. Это именно вариант лекции; не заменяем его алгоритмом, который всегда добавляет только один знак.

Работаем с дополненной строкой циклически: за позицией $N$ идёт позиция 1. Последовательно сортируем циклические фрагменты длины

$$
1,2,4,8,\ldots,N.
$$

На каждом этапе хранится $N$ начал фрагментов. Длина фрагментов удваивается, число их начал остаётся прежним.

### Два массива и их смысл

Обозначим через $p$ массив начал фрагментов в текущем отсортированном порядке, через $c[i]$ — класс эквивалентности фрагмента, начинающегося в позиции $i$.

Классы нумеруем с 1, как в лекционном примере:

- одинаковые фрагменты имеют одинаковый класс;
- меньший фрагмент имеет меньший класс;
- при переходе к следующему отличающемуся фрагменту увеличиваем номер класса на 1.

Класс заменяет длинный фрагмент одним целым числом для последующих сравнений. Не путаем $c[i]$ с порядковым номером самого фрагмента в $p$: одинаковые фрагменты занимают разные места в $p$, но имеют один класс.

## Первый этап: отдельные символы

Источник: [лекция 21, 05:04–10:27](https://www.youtube.com/watch?v=SM5QxyPms7g&t=304s).

### Короткий пример: `aba$`

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Стабильная сортировка отдельных букв даёт **$p=[4,1,3,2]$**. Классов три: `$` — 1, `a` — 2, `b` — 3. По исходным позициям записываем **$c=[2,3,2,1]$**.

**Шаг 1. Добавили $ к aba.**

Исходная строка aba имеет длину 3. Дописываем минимальный служебный символ $, получая длину 4 — степень двойки. Теперь рассматриваем циклические фрагменты с четырёх возможных начал. На первом этапе длина фрагмента равна одной букве.

```text
Позиция    1  2  3  4
Строка     a  b  a  $
```

**Шаг 2. Стабильно отсортировали символы.**

Буква $ из позиции 4 меньше всех остальных. Затем идут две a из позиций 1 и 3, их исходный порядок сохраняет стабильная сортировка. Последней идёт b из позиции 2. Поэтому массив начал p=[4,1,3,2]; числа в нём — индексы исходной строки, а не коды букв.

```text
p          4  1  3  2
Символы    $  a  a  b
```

**Шаг 3. Назначили классы: $ → 1, a → 2, b → 3.**

Присваиваем одинаковым буквам одинаковые классы: $→1, a→2, b→3. Массив c записываем по исходным позициям: для позиции 1 класс 2, для позиции 2 класс 3, для позиции 3 класс 2, для позиции 4 класс 1. Получаем c=[2,3,2,1]. Не переставляем его вслед за p.

```text
Позиция    1  2  3  4
Строка     a  b  a  $
c          2  3  2  1
```

## Удвоение: почему достаточно одной сортировки подсчётом

Источник: [лекция 21, 10:31–23:25](https://www.youtube.com/watch?v=SM5QxyPms7g&t=631s).

Предположим, фрагменты длины $k$ уже отсортированы. Любой фрагмент длины $2k$ — две половины длины $k$. Поэтому вместо посимвольного сравнения достаточно сравнивать пару

$$
\bigl(c[i],\ c[i\oplus k]\bigr),
$$

где $i\oplus k$ — циклический сдвиг индекса вперёд на $k$. Для индексации с единицы удобно явно определить

$$
i\oplus d=1+((i-1+d)\bmod N).
$$

Сначала сравнивается класс первой половины, при равенстве — класс второй. Это и есть два разряда для цифровой сортировки.

Кажется, нужны две сортировки: по второй половине, затем стабильно по первой. Но вторая половина **уже отсортирована** на предыдущем этапе. Используем это.

### Сдвигаем начала назад

Для каждого элемента старого массива $p$ строим

$$
p'[j]=p[j]\oplus(-k).
$$

Почему это даёт нужный порядок? У фрагмента длины $2k$, начинающегося в $p[j]\oplus(-k)$, вторая половина начинается ровно в $p[j]$. А эти половины уже идут по возрастанию в старом $p$.

Значит, $p'$ отсортирован по **второй половине**. Остаётся выполнить стабильную сортировку подсчётом по классу первой половины $c[p'[j]]$. Стабильность сохраняет прежний порядок вторых половин среди одинаковых первых.

### Переход от длины 1 к длине 2

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Исходно $p=[4,1,3,2]$, $c=[2,3,2,1]$.

1. Циклически вычитаем 1: $p'=[3,4,2,1]$.
2. Это начала фрагментов `a$`, `$a`, `ba`, `ab`. Их **вторые буквы** уже идут по порядку: `$`, `a`, `a`, `b`.
3. Стабильно сортируем по классу первой буквы: `$a`, `a$`, `ab`, `ba`.
4. Получаем **$p=[4,3,1,2]$**.
5. Пары старых классов различны: $(1,2),(2,1),(2,3),(3,2)$. Новые классы по исходным позициям: **$c=[3,4,2,1]$**.

`a$` и `ab` начинаются одинаково, но получают разные классы из-за второй половины. При пересчёте все пары берём из **старого** массива $c$; заменяем его новым лишь после завершения этапа.

**Шаг 1. Вычитаем 1 из каждого начала циклически.**

Чтобы получить порядок по вторым половинам будущих пар, сдвигаем каждое старое начало на одну позицию назад. Из [4,1,3,2] получаем [3,4,2,1]: ноль при вычитании из 1 заменяется на 4. Начинающиеся здесь пары — a$, $a, ba, ab. Их вторые буквы $,a,a,b уже отсортированы, потому что они начинаются ровно в старых индексах p.

```text
Старое p     4   1   3   2
p′           3   4   2   1
Фрагменты    a$  $a  ba  ab
2-я буква    $   a   a   b
```

**Шаг 2. Стабильно сортируем по первой букве.**

Осталось устойчиво отсортировать по первым буквам, то есть по их старым классам. Сначала идёт $a, затем две пары на a в уже готовом порядке a$,ab, затем ba. Получаем начала [4,3,1,2]. Устойчивость важна именно для двух одинаковых первых букв: она сохраняет правильный порядок вторых.

```text
Новое p       4    3    1    2
Фрагменты     $a   a$   ab   ba
Пары c       1:2  2:1  2:3  3:2
```

**Шаг 3. Разные пары получают разные классы.**

Сравниваем пары старых классов: (1,2), (2,1), (2,3), (3,2). Все различаются, значит в порядке p им выдаются новые классы 1,2,3,4. Возвращаем эти классы на исходные позиции: c[4]=1, c[3]=2, c[1]=3, c[2]=4. Новый массив c=[3,4,2,1]; старые классы меняем только после полного пересчёта.

```text
Позиция    1  2  3  4
Новое c    3  4  2  1
```

## Длина 4, остановка и готовый ответ

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

После длины 2 все четыре класса уже различны. Можно остановиться: дальнейшие буквы не изменят порядок.

Для закрепления выполним ещё один этап. Из $p=[4,3,1,2]$ вычитаем **2** циклически: $[2,1,3,4]$. Стабильная сортировка по классам первых половин возвращает $[4,3,1,2]$. Соответствующие полные циклические строки: `$aba`, `a$ab`, `aba$`, `ba$a`.

**Шаг 1. Вычитаем уже 2, а не 1.**

Для удвоения 2→4 вторая половина имеет длину 2, поэтому вычитаем из старых начал уже 2. Из p=[4,3,1,2] получаем [2,1,3,4] с циклическим переходом через начало. Этим индексам соответствуют полные циклические строки ba$a, aba$, a$ab, $aba.

```text
p′            2     1     3     4
Фрагменты    ba$a  aba$  a$ab  $aba
```

**Шаг 2. Сортируем по классам первых половин.**

Устойчиво сортируем по классам первых половин длины 2. Их классы уже все различны, поэтому получаем прежний порядок [4,3,1,2]. Дополнительные символы не смогли его изменить: любые два фрагмента различались ещё на предыдущем этапе. Поэтому в реализации здесь можно было закончить раньше.

```text
p                4     3     1     2
Цикл. строки    $aba  a$ab  aba$  ba$a
```

**Шаг 3. Отбрасываем служебное начало 4.**

Начало 4 соответствует служебному доллару, а исходный текст имеет только позиции 1..3. Убираем 4 и оставляем [3,1,2]. Теперь читаем эти индексы как начала обычных суффиксов исходной aba: a, aba, ba. Циклические строки были лишь средством определения этого порядка.

```text
SA           3    1    2
Суффиксы     a   aba   ba
```

Лекционное объяснение алгоритма: [лекция 21, 23:37–40:37](https://www.youtube.com/watch?v=SM5QxyPms7g&t=1417s), [около 30:55–31:20](https://www.youtube.com/watch?v=SM5QxyPms7g&t=1855s).

### Почему порядок циклических строк даёт порядок суффиксов

Рассмотрим два начала в исходной части текста. Если соответствующие суффиксы различаются до конца более короткого, их циклические продолжения различаются там же.

Если более короткий суффикс является префиксом длинного, следующий символ его циклического продолжения — `$`, а у длинного суффикса ещё стоит обычная буква. Минимальность `$` ставит короткий суффикс раньше, как и требуется при обычной сортировке строк. Возврат к началу дополненной строки случится уже после различия и не изменит результат сравнения.

Все циклические строки, начинающиеся с добавленных долларов, идут перед строками, начинающимися с исходных символов. Поэтому после завершения алгоритма оставляем **последние $n$ элементов**, где $n$ — исходная длина. Отбрасываем все добавленные начала, а не всегда ровно одно.

Для `aba$` удаляем начало 4. Ответ: **$SA=[3,1,2]$**. Он задаёт порядок обычных суффиксов исходного `aba`: `a`, `aba`, `ba`.

Во время промежуточных этапов фрагменты с `$` не выкидываем: они нужны для циклических сдвигов и классов. Фильтрация выполняется в конце.

## Закрепление: что делать с несколькими `$`

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Возьмём ещё более короткое `ab`. После обязательного разделителя длина 3; дополняем до 4 и получаем `ab$$`.

1. По буквам: $p=[3,4,1,2]$, классы по исходным позициям $c=[2,3,1,1]$.
2. Сдвиг на $-1$: $p'=[2,3,4,1]$ — фрагменты `b$`, `$$`, `$a`, `ab`.
3. Стабильная сортировка: `$$`, `$a`, `ab`, `b$`, то есть $p=[3,4,1,2]$.
4. Пары различны, можно закончить. Отбрасываем **оба** служебных начала 3 и 4.
5. Получаем **$SA=[1,2]$** — суффиксы `ab`, `b`.

Промежуточные `$$`, `$a`, `ab`, `b$` — циклические фрагменты длины 2, а не список настоящих суффиксов. Результат алгоритма — их **индексы**, которые после удаления служебных начал задают нужный порядок исходных суффиксов.

**Шаг 1. Длина исходного текста 2.**

У ab длина 2. После обязательного доллара длина стала бы 3, но лекционный вариант требует степень двойки, поэтому дописываем ещё один: ab$$, N=4. Оба доллара служебные и оба меньше букв. В конце нужно будет убрать два соответствующих начала, а не одно.

```text
Позиция    1  2  3  4
Строка     a  b  $  $
                 ↑  ↑
```

**Шаг 2. Сортируем буквы, затем пары.**

По одиночным буквам получаем p=[3,4,1,2]: сначала два доллара, затем a и b. Старые классы по позициям — [2,3,1,1]. Вычитаем 1 циклически: [2,3,4,1]. Пары b$, $$, $a, ab уже расположены по вторым буквам $, $, a, b.

```text
p′      2   3   4   1
Пары    b$  $$  $a  ab
```

**Шаг 3. Пары уже определяют полный порядок.**

Стабильная сортировка по первой букве даёт $$, $a, ab, b$, то есть p=[3,4,1,2]. Все пары различны, значит порядок уже окончательный. Удаляем оба начала в добавленной части — 3 и 4. Остались [1,2], которые обозначают настоящие суффиксы ab и b.

```text
p₂           3   4   1   2
             ↑   ↑
Фрагменты    $$  $a  ab  b$
SA           1   2
Суффиксы     ab  b
```

Лекционное объяснение алгоритма: [лекция 21, 42:08–51:28](https://www.youtube.com/watch?v=SM5QxyPms7g&t=2528s).

## Оценка цифровой сортировки

Источник: [лекция 21, 51:41–52:56](https://www.youtube.com/watch?v=SM5QxyPms7g&t=3101s).

На каждом этапе:

1. Сдвигаем $N$ индексов за $O(N)$.
2. Стабильно сортируем по классам подсчётом за $O(N)$: классов не больше $N$.
3. Проходим отсортированный массив и пересчитываем классы за $O(N)$.

Этапов $O(\log N)$, потому что длина сравниваемого фрагмента каждый раз удваивается. Дополнение до ближайшей степени двойки сохраняет $N=O(n)$, поэтому

$$
\boxed{O(n\log n)\text{ времени},\qquad O(n)\text{ памяти}.}
$$

Начальная сортировка символов подсчётом предполагает доступные целочисленные коды подходящего диапазона; для произвольного большого алфавита отдельно учитывается работа с его кодами. На последующих этапах диапазон классов уже гарантированно линейный.

Этот алгоритм строит сам суффиксный массив. Ранее разобранная подготовка соседних LCP использовала суффиксное дерево; отдельный алгоритм получения LCP непосредственно из массива в этих лекциях не выводится. Поэтому нельзя автоматически считать, что последняя цифровая сортировка сама подготовила и все данные для ускоренного поиска.
