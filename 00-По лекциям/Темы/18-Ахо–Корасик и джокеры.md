# Ахо–Корасик и джокеры

Источники: [Видео 1](https://www.youtube.com/watch?v=E559ePuUCRw). Ссылки на конкретные моменты сохранены в разделах.

В текстовых схемах: `✓` — совпадение или подтверждённый результат, `×` — несовпадение, `↑` — рассматриваемое место. Причина каждой отметки объясняется перед схемой.

Обозначения: $T$ — текст длины $n$, $P$ — образец длины $m$; индексация с единицы. Дополнительные обозначения вводятся в соответствующих разделах.

Перед этой темой: [[00-По лекциям/Темы/10-Trie|Trie]], [[00-По лекциям/Темы/15-КМП и префикс-функция|КМП и префикс-функция]].

## Ахо–Корасик: несколько паттернов за один проход

[Лекция 16, 00:35–07:18](https://www.youtube.com/watch?v=E559ePuUCRw&t=35s).

Теперь даны $h$ паттернов $P_1,\ldots,P_h$, их длины $m_1,\ldots,m_h$. Обозначим суммарную длину

$$M=\sum_{r=1}^{h}m_r.$$

Здесь $M$ — новое обозначение суммы длин; это уже **не массив** предыдущего алгоритма.

Если независимо запускать линейный поиск для каждого паттерна, получим

$$O((n+m_1)+\cdots+(n+m_h))=O(nh+M).$$

Проблема — $h$ проходов по одному и тому же тексту. Хотим обработать все паттерны вместе и один раз прочитать текст. Ахо–Корасик дает

$$O(n+M+k),$$

где $k$ — суммарное число найденных вхождений. Добавка $k$ необходима, если все вхождения надо перечислить.

### Начинаем с обычного несжатого trie

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Возьмём четыре коротких образца: **`a`, `ba`, `aba`, `abab`**. В концах храним номера образцов. Паттерн может заканчиваться во внутренней вершине.

Если для каждой позиции текста начинать поиск из корня заново, в худшем случае получим $O(nm_{max})$. Связи неудачи позволяют сохранить уже прочитанный подходящий суффикс.

**Шаг 1. Вставляем a и ba.**

Создаём обычный несжатый бор: для образца a нужен один переход, для ba — переходы b и a. Конечные вершины помечаем галочкой. Вершина b пока нетерминальная, потому что отдельного образца b в наборе нет.

```text
ε
├── a → a ✓
└── b → b
    └── a → ba ✓
```

**Шаг 2. Добавляем aba и abab.**

Добавляем aba: начальная a уже есть, от неё достраиваем b→a. Затем добавляем abab, дописав ещё одно b. Галочка в a не исчезает, когда у вершины появляются дети: короткий образец может быть префиксом более длинного.

```text
ε
├── a → a ✓
│   └── b → ab
│       └── a → aba ✓
│           └── b → abab ✓
└── b → b
    └── a → ba ✓
```

**Шаг 3. Строим связи неудачи по уровням.**

Строим ссылки по глубине. У детей корня a и b цель — корень. Для ab максимальный представленный собственный суффикс — b, для ba — a, для aba — ba, для abab — ab. Последний пример показывает, что цель не обязана быть терминальной: ссылка сохраняет подходящий префикс для продолжения поиска.

```text
Вершина     a     b     ab    ba   aba   abab
Неудача     ε     ε     b     a     ba    ab
```

Лекционное объяснение алгоритма: [Лекция 16, 07:24–14:49](https://www.youtube.com/watch?v=E559ePuUCRw&t=444s).

## Связь неудачи — префикс-функция сразу для всех паттернов

[Лекция 16, 14:53–23:42](https://www.youtube.com/watch?v=E559ePuUCRw&t=893s).

Представим, что прочитали `abab`, а следующая буква — `a`. Из вершины `abab` нет ребра `a`, но суффикс `ab` уже совпал и является префиксом `aba`. Перейдём в `ab`, затем по новой букве в `aba`.

В КМП мы искали собственный суффикс совпавшего фрагмента, являющийся префиксом **того же** паттерна. Теперь разрешаем префикс **любого** паттерна.

Пусть $S(v)$ — строка на пути от корня до вершины $v$. Связь неудачи $f(v)$ ведет в вершину, строка которой является наибольшим собственным суффиксом $S(v)$ среди строк, представленных в trie. При отсутствии непустого подходящего суффикса ведет в корень.

```text
abab ── связь неудачи ──▶ ab
```

Связь одна. Если бы нашлись две цели разной глубины, выбираем более глубокую. Если глубина одна и строка одна, в корректном trie это одна вершина, а не две.

### Строим по длине префикса

[Лекция 16, 23:49–42:47](https://www.youtube.com/watch?v=E559ePuUCRw&t=1429s).

Для всех детей корня связь неудачи ведет в корень: у строки длины $1$ единственный собственный суффикс — пустой.

Далее обрабатываем вершины по уровням. Пусть $v$ получена из родителя $u$ по букве $a$.

1. Мысленно удаляем последнюю букву: возвращаемся из $v$ к $u$.
2. Переходим по уже построенной связи $f(u)$.
3. Ищем из полученной вершины ребро по $a$.
4. Если оно есть, его конец — $f(v)$.
5. Если нет, снова идем по связи неудачи и ищем то же ребро.
6. Если дошли до корня и ребра нет, $f(v)$ — корень.

Почему все необходимое уже построено? Каждая связь неудачи ведет к более короткой строке. Мы идем по возрастанию глубины, поэтому ссылки для более коротких префиксов уже известны.

### Строим связи для короткого примера

1. `a` и `b` — дети корня, их ссылки ведут в корень.
2. Для `ab`: из родителя `a` по неудаче идём в корень; оттуда есть ребро `b`. Значит, $f(ab)=b$.
3. Для `ba`: из `b` по неудаче в корень, затем по `a`. Получаем $f(ba)=a$.
4. Для `aba`: из родителя `ab` по неудаче в `b`, затем по `a` в `ba`. Получаем $f(aba)=ba$.
5. Для `abab`: из `aba` по неудаче в `ba`; ребра `b` там нет. Ещё одна ссылка ведёт в `a`, где ребро `b` есть. Значит, $f(abab)=ab$.

На схеме выше дана вся таблица. Ссылка в корень существует, даже если её стрелку не рисуют.

## Как теперь читать текст

[Лекция 16, 43:15–46:30](https://www.youtube.com/watch?v=E559ePuUCRw&t=2595s).

Храним текущую вершину trie. Для очередной буквы текста:

- если нужное ребро есть, переходим по нему и считаем букву прочитанной;
- если ребра нет, идем по связи неудачи и снова ищем ребро по **этой же** букве;
- если в корне ребра тоже нет, пропускаем букву текста и остаемся в корне.

Текст назад не перематываем.

### Проход по `ababa`

**Учебный пример:** числа или строки упрощены; вариант алгоритма сохранён.

Последовательность состояний после прочтения букв: **`a → ab → aba → abab → aba`**. Последний переход использует связь неудачи, сохраняя уже совпавшее `ab`. Таблицу найденных образцов дополним связями выхода ниже.

**Шаг 1. Читаем первые a и b.**

После первой a текущая вершина терминальная, поэтому выдаём образец a с началом 1. Затем читаем b и переходим в ab. В этой вершине образец не заканчивается, и терминального суффикса у неё нет, поэтому на позиции 2 ничего не выдаём.

```text
Текст        a   b   a   b   a
             ✓   ✓
Позиция      1   2
Состояние    a   ab
```

**Шаг 2. Третья буква a: состояние aba.**

Третья буква a приводит в aba. Сначала выдаём сам образец aba: начало 3−3+1=1. По выходу идём в ba и выдаём начало 3−2+1=2, затем в a — начало 3. Цепочку выходов просматривает отдельный указатель; основное состояние остаётся aba.

```text
Текст      a    b    a    b    a
           ✓    ✓    ✓
Выдаём    aba   →    ba   →    a
Начала     1         2         3
```

**Шаг 3. Четвёртая буква b: остаёмся на длинном пути.**

Четвёртая буква b читается именно из aba, поэтому получаем abab и выдаём вхождение с начала 4−4+1=1. Если бы после перечисления предыдущих выходов оставили основное состояние в a, получили бы лишь ab и потеряли длинный ответ. Это причина разделять движение по тексту и выдачу результатов.

```text
Текст       a     b     a     b     a
            ✓     ✓     ✓     ✓
Переход    aba    →    abab
```

**Шаг 4. Пятая буква a: используем неудачу.**

Пятая буква — a, а из abab такого ребра нет. По неудаче переходим в ab, не потребляя новую букву. Оттуда ребро a есть: идём в aba и только теперь считаем T₅ прочитанной. Выдаём aba, ba, a с началами 3,4,5 соответственно; текст назад не просматривали.

```text
Переход    abab   →     ab    →    aba
Текст       a     b     a     b     a
                        ✓     ✓     ✓
Начала      3     4     5
```

Для оценки числа переходов при поиске можно следить за глубиной текущей вершины. Обычный переход увеличивает глубину на единицу и потребляет одну букву текста; таких увеличений не больше $n$. Каждая неудача строго уменьшает глубину, поэтому суммарно уменьшений тоже $O(n)$. В корне неподходящие буквы просто потребляются.

Построение trie и связей лектор оценивает как $O(M)$, поиск — $O(n)$. Эти оценки предполагают постоянную стоимость доступа к переходу по букве; при другой структуре хранения переходов надо учитывать ее стоимость. Ниже появится еще стоимость выдачи ответов.

## Почему одних связей неудачи недостаточно

[Лекция 16, 46:40–55:47](https://www.youtube.com/watch?v=E559ePuUCRw&t=2800s).

В начале построения лектор временно исключил случай, когда паттерн является префиксом другого. Теперь уточняет: для разобранного упрощенного поиска требуется более сильное ограничение — никакой паттерн не должен быть **подстрокой** другого.

Иначе можно успешно идти по длинному паттерну и не посещать вершину короткого паттерна, который в этот момент уже встретился в тексте. Даже последующий переход по связям неудачи не гарантирует, что мы вовремя сообщим все такие вхождения.

Пример: прочитано `aba`. В текущей позиции закончились сразу `aba`, `ba` и `a`. Основное состояние находится в вершине `aba`; остальные ответы надо перечислить отдельно.

Нужно отдельно перечислить все терминальные суффиксы текущего состояния.

### Вводим связь выхода

Связь выхода $out(v)$ ведет в ближайшую по цепочке неудач вершину, которая является концом какого-либо паттерна. Если такой вершины нет, связь отсутствует.

При чтении очередной буквы:

1. Если текущая вершина сама терминальная, сообщаем ее паттерн.
2. Проходим по цепочке связей выхода, сообщая остальные паттерны.
3. Следующую букву текста обрабатываем из **прежней поисковой вершины**.

Каждая найденная строка заканчивается в текущей позиции текста $j$. Если ее длина $\ell$, начало вхождения равно $j-\ell+1$.

### Строим выходы вместе с неудачами

[Лекция 16, 58:28–1:02:47](https://www.youtube.com/watch?v=E559ePuUCRw&t=3508s).

Сразу после построения $f(v)=u$:

- если $u$ — конец паттерна, ставим $out(v)=u$;
- иначе берем уже построенную $out(u)$;
- если ее нет, выхода из $v$ тоже нет.

Готовность $out(u)$ обеспечена тем же порядком по уровням: $u$ соответствует более короткому префиксу. Не надо заново искать каждый паттерн внутри каждого другого паттерна и не надо хранить отдельную стрелку ко всем терминальным суффиксам: одной ссылки на ближайший достаточно, остальные находятся по цепочке.

## Подробный пример выходов и добавка $k$

В нашем боре $out(aba)=ba$, а $out(ba)=a$. Вершина `a` не имеет выхода. Для `abab` цепочка неудач начинается с нетерминальной `ab`, затем идёт нетерминальная `b` и корень, поэтому выхода нет.

| Позиция в `ababa` | Состояние | Что выдаём — образец и начало |
|---:|---|---|
| 1 | `a` | `a`: 1 |
| 2 | `ab` | ничего |
| 3 | `aba` | `aba`: 1; `ba`: 2; `a`: 3 |
| 4 | `abab` | `abab`: 1 |
| 5 | `aba` | `aba`: 3; `ba`: 4; `a`: 5 |

Начало каждого ответа считаем как $j-\ell+1$. Например, в позиции $j=5$ образец `ba` имеет длину 2, поэтому начинается в $5-2+1=4$.

Каждый переход по выходу нужен для выдачи конкретного ответа. Поэтому полная сложность — **$O(M+n+k)$**, где $k$ — число выданных вхождений. В этом примере $k=8$.

Лекционное объяснение алгоритма: [Лекция 16, 1:09:16–1:14:00](https://www.youtube.com/watch?v=E559ePuUCRw&t=4156s), [Объяснение оценки, лекция 16, 55:52–58:12](https://www.youtube.com/watch?v=E559ePuUCRw&t=3352s).

### Самая важная оговорка из конца лекции

[Лекция 16, 1:20:09–1:23:16](https://www.youtube.com/watch?v=E559ePuUCRw&t=4809s).

**Связь выхода не меняет поисковое состояние.** Лектор возвращается к этому несколько раз после вопросов.

Когда в состоянии `aba` перечислили `aba → ba → a`, следующую `b` надо читать из `aba`. Тогда найдём `abab`. Если оставить состояние в `a`, перейдём лишь в `ab` и потеряем это вхождение.

Удобно различать два указателя:

- основной остается в вершине, до которой довело чтение текста;
- временный пробегает цепочку выходов для выдачи ответов.

Связи неудачи используются для продолжения поиска при отсутствии ребра. Связи выхода используются для извлечения уже найденных ответов. Это разные роли, даже когда некоторые стрелки имеют одинаковые концы.

## Ахо–Корасик и КМП — одна идея для разного числа строк

[Лекция 16, 1:03:18–1:06:59](https://www.youtube.com/watch?v=E559ePuUCRw&t=3798s).

Если в trie хранится только один паттерн, дерево превращается в один путь. Для каждой его вершины связь неудачи ищет наибольший собственный суффикс уже совпавшего префикса, являющийся префиксом этой единственной строки. Это обычная идея $sp$ и КМП.

Разница Ахо–Корасик — разрешение продолжить поиск в префиксе другого паттерна. Поэтому переход по неудаче `aba → ba` помогает понять алгоритм лучше, чем представление о нескольких независимых запусках КМП: поиск у них общий.

## Приложения: джокер и двумерный поиск

[Лекция 16, 1:18:18–1:20:07](https://www.youtube.com/watch?v=E559ePuUCRw&t=4698s).

В конце лектор называет два приложения и предлагает посмотреть их самостоятельно:

1. Поиск маленькой матрицы-паттерна в большой матрице-тексте.
2. Поиск паттерна с джокером, обозначающим любую **одну** букву.

Для второго приложения на лекции дан паттерн вида `ab?cd` и два вхождения с разными буквами на месте джокера. Наглядная буквенная запись этой постановки (нормализованный пример):

```text
P = ab?cd
T = abacdabdcd
```

Есть вхождения с позиций $1$ и $6$. Джокер заменяет соответственно `a` и `d`; фиксированные буквы `ab` и `cd` должны совпасть на своих местах.

Здесь важно не подменить задачу регулярным выражением с произвольной длиной пропуска: на лекции речь об одной неизвестной букве.

**Алгоритм решения на занятии не выводится.** Следующее — поясняющее дополнение, чтобы связать постановку с уже изученным Ахо–Корасик.

Разбиваем паттерн по джокерам на буквальные фрагменты и запоминаем их позиции в исходном паттерне. В `ab?cd` это `ab` с началом $1$ и `cd` с началом $4$. Ищем оба фрагмента одним автоматом. Если фрагмент с началом $a_r$ и длиной $\ell_r$ закончился в тексте в позиции $j$, он подтверждает возможное начало полного паттерна

$$s=j-(a_r+\ell_r-1)+1.$$

Для `ab`, закончившегося в позиции $2$, это $s=1$. Для `cd`, закончившегося в позиции $5$, тоже $s=1$. Все части согласились с одним началом, весь паттерн помещается в текст — значит, найдено вхождение.

Нужно учитывать каждую позицию фрагмента в паттерне: одинаковые буквальные фрагменты могут повторяться на разных смещениях. Паттерн только из джокеров имеет все начала, при которых целиком помещается в текст. Сложность дополнения зависит от числа найденных вхождений фрагментов, а не только от числа полных ответов. Подробного разбора двумерного случая в этой лекции нет.

### Два вхождения с разными буквами на месте ?

**Учебный пример:** подобран для пошагового разбора; это не копия примера с доски.

Для приведённого выше `ab?cd` сначала выделяем буквальные части, затем проверяем согласованность их смещений. Джокер `?`, отмеченный стрелкой, не сравниваем с конкретной буквой.

**Шаг 1. Разбиваем ab?cd на две части.**

Джокер ? занимает ровно одно место, поэтому фиксированные куски должны сохранить свои смещения. У ab начало 1, у cd начало 4. Найти оба фрагмента где-нибудь в тексте недостаточно: нужно, чтобы они указывали на одно и то же начало всего образца.

```text
Образец     a  b  ?  c  d
                  ↑
Смещения    1  2  3  4  5
```

**Шаг 2. Начало 1: обе части согласились.**

Первое ab занимает T₁..T₂, значит предполагает начало образца 1. Фрагмент cd занимает T₄..T₅; поскольку в образце он начинается с четвёртого места, его начало тоже даёт 4−4+1=1. Между ними ровно одна буква T₃=a, которую принимает джокер. Все условия согласованы.

```text
T    a  b  a  c  d  a  b  d  c  d
     ✓  ✓     ✓  ✓
P    a  b  ?  c  d
     ✓  ✓  ↑  ✓  ✓
```

**Шаг 3. Начало 6: тот же образец, другая буква.**

Следующее ab стоит в позициях 6..7 и предполагает начало 6. Фрагмент cd в позициях 9..10 даёт то же начало: 9−4+1=6. Джокер теперь соответствует T₈=d. Образец тот же, а конкретная буква пропуска изменилась; ответы — 1 и 6.

```text
T    a  b  a  c  d  a  b  d  c  d
                    ✓  ✓     ✓  ✓
P                   a  b  ?  c  d
                    ✓  ✓  ↑  ✓  ✓
```
